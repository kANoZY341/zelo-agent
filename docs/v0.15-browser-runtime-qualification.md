## Reproducible harness

Keep runtime browser/library paths explicit, verify artifact hashes, and fail

worktree as a production installation. Preserve native Chromium sandboxing.
Do not accept page-selected executables, flags, paths, origins or proxies.

## Resource owner

Introduce one explicit owner of browser session, fetch budget and resolver slot.
Admission occurs before process creation, has a fixed trusted ceiling, and does
not reset when a page fails. A pending cleanup retains its capacity lease until
all owned children are reaped. An unproven close blocks further admission rather
than spawning replacements. Cancellation cannot produce successful evidence.

The host has cgroup v2 but no writable cgroup root for the current user. Docker
is available; this is an option to qualify, not an already accepted boundary.
No image has been downloaded or container started. A container proposal must
pin provenance and inspect no-network, memory, pids, CPU and swap enforcement,
read-only mounts, user/permissions, native sandbox compatibility, and cleanup.
Do not substitute privileged containers, host networking, host IPC or disabled
browser sandboxing for missing prerequisites.

## Browser evidence gates

- Prove the native renderer filter and namespace state on the pinned artifact.
- Deliver one broker-approved document through a local pipe with page JavaScript
  and service workers disabled and fixed restrictive CSP. No caller-controlled
  script evaluation, uploads, downloads, clipboard or persistent profiles.
- Deny every subresource by default in the first lane. Show that removing route
  interception still cannot expose the host network or user filesystem.
- Check mismatched/untrusted TLS, redirect and encoding rejection, mixed DNS,
  body/header/resource limits, stalled DNS, renderer crashes and repeated cancel.
- Measure observed memory/process limits and deliberately exceed them in a
  disposable fixture. Confirm the entire owned tree dies and capacity is not
  released early. Do not use production data or public target systems.
- Bound extracted visible text and return data as untrusted evidence, never new
  tool authority. Deterministically bind renderer, controller, broker policy and
  approved origins in the accepted execution identity.

Only after those gates pass should a separate runtime PR add a typed browser
request, WorkerDescriptor, capability/skill and persisted execution snapshot.
It must reuse Core action hashing, retry/claim/Runner revalidation, approvals,
audit, scheduler and budgets, and must not create a default AgentSpec by itself.
Independent Astra Medium review and exact-head CI apply to each coherent slice.

Sources and caveats remain in the qualification design and evidence report.
This note is a local handoff, not a new active service or a completed milestone.

## Implemented qualification slice — 2 October 2026

The uncommitted resource-owner slice adds standalone `qualification/admission.py`,
`qualification/resource_owner.py` and `qualification/runtime_contracts.py`.
Admission has a fixed host ceiling of one when all trusted callers use the same
operator-provisioned private persistent directory. Linux nonblocking flock rejects
busy calls without a waiting queue. A bounded, fsynced active marker binds an
unpredictable lease identity to the execution-policy digest before factory entry.
Lock and marker files remain in place; proven cleanup empties the marker. Owner
death leaves a persistent fence even after the kernel releases the lock. There is
no automatic stale-PID/TTL recovery or operator reconciliation API in this slice.

A one-shot asynchronous fixture owner retains creation, work and cleanup ownership
through cancellation. Work results are tentative until the backend explicitly
confirms complete cleanup. Concurrent close shares the one retained lifecycle task;
grace expiry leaves capacity occupied. Ambiguous creation or cleanup failure leaves
the persistent marker fenced. These guarantees rely on a trusted backend and a live
owning event loop; they do not prove child termination or bound uninterruptible OS work.

Frozen validated contracts bind aggregate memory, PID/task count, CPU quota/period,
zero swap, tmpfs and deadline, pinned image/browser/controller/broker/renderer-policy
identities and approved-origin identity. Network denial, read-only operation,
no-new-privileges and native-sandbox-required are fixed semantic requirements.
Contracts do not enforce cgroups or sandboxing. No container, renderer, Docker socket,
broker transport, worker registration or production configuration is added.

Focused owner/contract tests: **43 passed**, with three existing collection warnings.
Ruff lint and format checks pass; see
[owner report](reviews/browser-runtime-owner-report.md) for commands and limitations.
Full pytest, independent review, parent-owned host/container diagnostics and exact-head
CI remain required gates. Native renderer/resource enforcement, broker integration and
adversarial browser evidence remain unqualified. UI stays parked; canonical v0.16,
v0.17 and v0.18 ordering and the published Core v0.14.0 remain unchanged.

## Implemented qualification checkpoint — 2 October 2026

The standalone qualification package now has a shared-directory capacity-one
admission controller, durable crash fence, cancellation-safe resource owner and
immutable execution/resource policy contracts. It still is not imported by Core
startup and grants no Browser task, worker, capability or default AgentSpec.

Admission precedes asynchronous creation. A killed owner leaves a persistent
marker, so an OS lock being released does not let a replacement overlap unknown
orphan resources. No TTL or automatic stale-PID clearing is used. Cleanup retains
capacity until a trusted backend confirms stop/reap; uncertain cleanup fences
future admission. All production callers must eventually share one trusted local
runtime directory. Same-UID operators/filesystem ancestors remain trusted.

The optional owned scratch-container harness now demonstrates cgroup v2 memory,
zero swap, PID, CPU and tmpfs limits with an explicitly bounded C fixture. All
six diagnostic containers and their labelled image were cleaned up. It does not
qualify Chromium under Docker or join renderer and broker into production.
See `reviews/browser-resource-host-report.md` for exact observations/provenance.

Serial host gate: 242 passed, three existing warnings, diff and Ruff checks pass.
This includes 43 new owner/contract tests, 28 launch-guard tests and two tests
that cancel a real controlled subprocess during creation/work, retaining the
shared capacity lease until the child is reaped. The existing broker/DNS and
API Worker suites remain green. No new Python dependency or system service.
