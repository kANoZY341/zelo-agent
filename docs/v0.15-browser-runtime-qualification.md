# Next Core slice: renderer ownership, admission and resource qualification

Base: verified PR #62 merge `939cbd7dc49f7e5e74a7659d13a0c2e92b7f5aef`. The UI stays parked as PR #61.
This is the remaining Browser Worker qualification, not permission to activate it.

## Reproducible harness

Convert the owned fixed-fixture diagnostics into reviewed optional harness files.
Keep runtime browser/library paths explicit, verify artifact hashes, and fail
closed when prerequisites are unavailable. Tests must not depend on the old UI
worktree as a production installation. Preserve native Chromium sandboxing.
Do not accept page-selected executables, flags, paths, origins or proxies.

## Resource owner

Introduce one explicit owner of browser session, fetch budget and resolver slot.
Admission occurs before process creation, has a fixed trusted ceiling, and does
not reset when a page fails. A pending cleanup retains its capacity lease until
all owned children are reaped. An unproven close blocks further admission rather
than spawning replacements. Cancellation cannot produce successful evidence.

The host has cgroup v2 but no writable cgroup root for the current user. Docker
is available; this is an option to qualify, not an already accepted boundary.
No image has been downloaded or container started. A container proposal must
pin provenance and inspect no-network, memory, pids, CPU and swap enforcement,
read-only mounts, user/permissions, native sandbox compatibility, and cleanup.
Do not substitute privileged containers, host networking, host IPC or disabled
browser sandboxing for missing prerequisites.

## Browser evidence gates

- Prove the native renderer filter and namespace state on the pinned artifact.
- Deliver one broker-approved document through a local pipe with page JavaScript
  and service workers disabled and fixed restrictive CSP. No caller-controlled
  script evaluation, uploads, downloads, clipboard or persistent profiles.
- Deny every subresource by default in the first lane. Show that removing route
  interception still cannot expose the host network or user filesystem.
- Check mismatched/untrusted TLS, redirect and encoding rejection, mixed DNS,
  body/header/resource limits, stalled DNS, renderer crashes and repeated cancel.
- Measure observed memory/process limits and deliberately exceed them in a
  disposable fixture. Confirm the entire owned tree dies and capacity is not
  released early. Do not use production data or public target systems.
- Bound extracted visible text and return data as untrusted evidence, never new
  tool authority. Deterministically bind renderer, controller, broker policy and
  approved origins in the accepted execution identity.

Only after those gates pass should a separate runtime PR add a typed browser
request, WorkerDescriptor, capability/skill and persisted execution snapshot.
It must reuse Core action hashing, retry/claim/Runner revalidation, approvals,
audit, scheduler and budgets, and must not create a default AgentSpec by itself.
Independent Astra Medium review and exact-head CI apply to each coherent slice.

Sources and caveats remain in the qualification design and evidence report.
This note is a local handoff, not a new active service or a completed milestone.
