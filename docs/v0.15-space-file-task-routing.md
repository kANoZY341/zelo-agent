# v0.15 — Explicit Space file Task routing

**Status:** stacked change after the attested Space registry PR #145 and internal
file-use gateway PR #146. This is the first narrow Core Computer Task route,
not a general OpenDots permission engine.

## Exact owner approval → Task → safe file-read path

An operator first activates a current AgentInstance Space intent against a
pre-provisioned, attested Core-owned `files` resource (PR #145). The Agent's
trusted current AgentSpec must explicitly declare this Space and
`computer.files`, its computer permission record must have owner-enabled
file access, and the existing Computer Worker must be available.

An explicit Agent Computer task may then request:

```json
{
  "kind": "computer_run",
  "payload": {
    "action": "files_read",
    "path": "notes.txt",
    "space_activation_id": "<UUID of current operator confirmation>"
  },
  "timeout_seconds": 30
}
```

`space_activation_id` is permitted only for the bounded read-only
`files_read` or `files_list` actions. The exact allowed operation must
exist in **both** the recorded intent and registered resource. It is part of
the saved Task payload/action hash and immutable ComputerExecutionSpec, and
must match at dispatch, claim and use. A list grant is not a read grant,
nor can either confirmation be swapped into another Task retroactively.

Core verifies current activation and a canonical relative path at submission,
again at retry and Task claim, and at actual file use after the Computer
backend human-control check. A revoked, expired or spec-stale confirmation
fails closed. The gateway binds exact running Task/Attempt and current
AgentInstance/spec/registry/project identity and checks the permission
record again during the transaction-scoped file operation.

On success the normal `ComputerRunResult(files_read)` records a bounded text
result (at most 64,000 displayed characters, truncated with an explicit flag).
The read itself remains bounded to 65,536 bytes; the stored content digest
proves full source identity. Raw content is **not** automatically admitted
into Zelo Mind's model context or memory. Task projections show only
non-content metadata. No document text appears in audit records.

## Bounded directory listing — operative R1 implementation

A separate `list` intent/activation can now authorize a `files_list`
Computer Task. The `path` is the empty string for the registered Space
resource root or a canonical, shallow, relative directory path. A claimed,
nondelegated Core Task runs via the same mediated gateway and owner-control
barrier as `files_read`, not by opening the host filesystem in the generic
OpenBot backend.

The gateway opens and re-attests directory FDs using `O_NOFOLLOW`, pins the
registered root's device and inode, and returns only safe, sorted file/folder
metadata. The entire directory must contain at most 128 raw entries; more
entries **fail closed without a partial listing**. Symlinks, unsafe modes,
hardlinks, unsupported file types and noncanonical names are omitted. No
file contents, credentials, model-context admission or filesystem writes
occur, and the audit event contains only source IDs, a path **digest** and
entry count. Revocation, expiration, Computer human takeover, Task
cancellation and stale authority are checked before the final use-point.

The feature does not make Space grants universal, allow Browser/Terminal/
Memory access, or permit delegated reads/writes. Those operations require
their own qualified Core routes and approvals before v0.15 release.

## Safety invariants

- The **unmediated OpenBot Computer backend explicitly refuses** any
  `ComputerExecutionSpec` carrying a Space activation ID.
- The Core Runner must use its configured `SpaceFileReadGateway` for such
  actions. If missing, it fails the task with
  `computer_space_gateway_unavailable`, **never falling back** to the
  generic OpenBot `files_read` or `files_list` route.
- The gateway checks human takeover, pending control transitions and
  post-await revocation. Its remote control lookup has the exact bounded
  Computer Task deadline; timeout fails closed without reading files.
  It then serializes its Core authority checks and
  bounded read against owner revocations/task cancellation with a SQLite
  write transaction. It verifies descriptor-relative filesystem containment,
  read-only file type/ownership/size, symlinks, hardlinks and root swaps.
- The first route disallows delegated Space execution. Delegation, task
  hierarchies, repeatable retries after approval changes, filesystem writes,
  Browser/Shell/Memory/Tool grants remain **separately gated**.
- No new unrestricted host-file tool, unauthenticated route, third-party
  runtime, REA or Media permission is introduced. UI PR #61 remains parked.
- Default AgentSpecs still lack allowed Spaces: no usable Space permission
  exists until a specifically registered AgentSpec and an authenticated owner
  confirmation satisfy the prerequisite checks.
