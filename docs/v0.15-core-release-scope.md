# v0.15.0 Core release scope — owner decision, 4 November 2026

The Managing Director chose a smaller Core release scope on 4 November 2026.
This decision supersedes the earlier requirement to qualify every optional
Computer, Skill-publication, Worker and curated-integration lane before a
v0.15.0 release. The 2 November Media deferral remains in force. It does not
turn an unqualified path into a passing one or authorize its activation.

## Supported release profile

The v0.15.0 release target is the local Core service on `127.0.0.1` using its
default authority profile. It includes the existing Coding and Research Agent
templates, durable Core Task and approval boundaries, and registered Research
and isolated Python Workers. The API Worker has no approved endpoint by
default. Normal owner-authenticated management interfaces remain bounded by
their existing Core checks; the release grants no Agent a Space or Computer.

The following remain outside the supported v0.15.0 runtime profile:

| Lane | Release state |
| --- | --- |
| External learned-Skill publication and activation | Disabled; no live Skill publication is claimed. |
| Computer backend, navigation and broad Space delegation | No backend or default grants; the bounded two-Computer pilot is evidence for its exact case only. |
| Browser and Shell Workers | Disabled by default; opt-in qualification receipts are not general release support. |
| API Worker network access | No approved endpoints by default. |
| OCR Reviewer, ECC/Harness Skills and REA Core tools | Inert or unactivated; the failed real-diff OCR evaluation is retained. |
| Media Reader, provenance, decoder and Core Media Worker | Deferred and unavailable; all spent attempts and source decisions remain terminal. |
| Later v0.16/v0.17 channels and company overlays | No new channel or company authority through this release. |

Optional source and operator routes remain in the repository for later work.
Their presence, local tests or explicit configuration do not make them part of
the supported v0.15.0 release. Production configuration for this release must
keep the corresponding opt-ins unset or false. A future activation needs its
own review, proof and operator decision.

## Release gates still required

1. Pin the final `main` SHA and verify the default Agent, Skill, Space, API and
   Worker inventory against this profile. Inspect the release host's effective
   `Settings` after environment and `.env` loading, plus actual conditional
   Worker and authority registration. Refuse release if any excluded lane has
   an effective opt-in or registered authority. Record only redacted booleans,
   counts and pin presence; do not publish secrets or endpoint values. No
   default authority expansion.
2. Pass exact-head and separate `main` CI, negative capability tests, an
   isolated local Core smoke, and v0.14-to-current database upgrade, backup
   restore and reupgrade with preserved Task/audit state.
3. Complete an independent full-repository final-candidate audit. Fix any
   release-blocking finding, then repeat affected checks **and the independent
   full-repository audit** at the new exact SHA before the operator decision.
4. Record the Managing Director's release decision for the audited exact
   `main` SHA. Only then configure the host-only v0.15 release pin, approve the
   separate Release Task and create/verify the annotated `v0.15.0` tag and
   GitHub release. Tagging and publication are separate from CI success.

The currently published release remains `v0.14.0` until those gates pass.
Issue #166 is the release evidence ledger. Issues #131 and #132 remain open
for the deferred authority and curated-integration work; their unresolved
work is not represented as v0.15.0 runtime support.
