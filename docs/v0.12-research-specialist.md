# v0.12 — Fixed Research specialist

## Goal

Add Zelo's first specialist agent without introducing the v0.14 Agent Factory or
the v0.15 broad capability/worker ecosystem.

The specialist is intentionally fixed:

```text
Zelo Mind / Core task
  -> research_run
  -> fixed ResearchRuntime
  -> local_general model
  -> narrow read-only ToolGateway view
  -> evidence-grounded answer
```

## Why this shape

The canonical roadmap puts one fixed Research specialist in v0.12, while Browser
Worker, API Worker, Research Worker, MCP/plugin adapters and the general
Capability Registry remain v0.15.

Open-source research-agent implementations were reviewed for patterns before
this slice. Common useful ideas are separate specialist roles, bounded retrieval
loops, explicit source grounding and source-aware synthesis. No third-party
research framework or code is copied here because their browser/search,
multi-agent, memory and orchestration stacks would pull later roadmap layers
forward.

This slice reuses Zelo's existing ModelGateway, ToolGateway, task lifecycle,
Campaign ownership, audit and bounded Agent Runtime settings.

## Contract

New Core task kind:

```json
{
  "kind": "research_run",
  "payload": {
    "query": "Inspect the project workspace and summarize the evidence."
  },
  "timeout_seconds": 120
}
```

`research_run` is not approval-gated because it can use only the fixed safe-read
retrieval allowlist. It may still be Campaign-owned and dependency-gated like any
other Core task.

Mind can route a user request to `research_run`. Scheduled Mind wakes keep the
same Campaign binding because the existing Mind Campaign-binding rule applies to
the new typed task.

## Retrieval authority

The fixed Research specialist can use only:

- `repo_status`
- `list_workspace_files`
- `read_workspace_file`

It cannot use `system_info`, even though that tool is safe-read for the generic
ToolGateway. This proves the specialist has its own narrower capability surface.

It also cannot use:

- public-web or browser retrieval;
- arbitrary URLs or APIs;
- arbitrary shell, Python or subprocess execution;
- write/edit/delete tools;
- package installation;
- secrets/runtime/database reads;
- task creation or approval authority.

ToolRegistry and ToolPolicy still validate every execution. Adding a new safe-read
tool to the global registry does not automatically grant it to Research.

## Evidence model

Every successful Research tool call gets a Core-generated source ID:

```text
S1, S2, ...
```

The tool result is sent to the model in a generated untrusted-data envelope with
that source ID. The model cannot choose the ID.

A final Research answer must:

1. have retrieved at least one real source;
2. declare only source IDs observed in the current run;
3. declare each source at most once;
4. include each declared ID in the answer using the exact `[S#]` form.

Invalid or invented citations consume the existing bounded parse-retry budget and
then fail closed.

The persisted result contains:

- bounded final answer;
- cited source IDs;
- tool name;
- safe locator such as `workspace:path/to/file` or `repository`;
- SHA-256 digest of the canonical full typed tool result;
- whether the model-facing tool result was truncated;
- model/tool step counts and token usage.

Raw retrieved file contents and the specialist's internal model/tool transcript
are not copied into audit history or a new memory store.

## Bounds and failure behavior

Research reuses the current bounded Agent settings:

- maximum model steps;
- maximum tool calls;
- model timeout;
- overall agent timeout;
- parse-retry budget;
- model-facing tool-result character budget.

The selected model is bound at task submission through the existing ModelGateway
selection snapshot. The runtime accepts only `local_general`.

Expected failures are redacted into stable error codes such as:

- `research_tool_not_allowed`
- `research_tool_unavailable`
- `research_citation_invalid`
- `research_parse_retries_exhausted`
- `research_tool_call_limit`
- `research_step_limit`
- `research_timeout`

## Non-goals

This slice does not add:

- live web search;
- browser automation;
- a general Research Worker;
- AgentSpec or DepartmentSpec records;
- persistent specialist memory;
- recursive subagents;
- autonomous schedule creation;
- write authority;
- external channels;
- new merge/release authority.

Those remain in their canonical later milestones.
