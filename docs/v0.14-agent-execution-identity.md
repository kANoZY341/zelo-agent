# Zelo Core v0.14 — Generic agent execution identity

## Status

Fourth bounded implementation slice of v0.14 Agent Factory.

Merged prerequisites:

- registry foundation: PR #47;
- project-bound lifecycle: PR #48;
- bounded delegation contracts: PR #49.

## Goal

Route the already-existing Coding and Research specialist work through persisted
Agent Factory identity without creating a second task or execution system.

The invariant is:

> Agent identity narrows a normal Core task. It never replaces Core task authority.

## Trusted submission boundary

Operators submit specialist work through:

`POST /agents/{instance_id}/tasks`

The request contains only:

- a normal `research_run` or `developer_run` request;
- optionally, the ID of an already-existing delegation contract;
- the normal idempotency header.

The caller cannot supply:

- AgentSpec or registry snapshots;
- worker IDs or model IDs;
- worker authority profiles;
- capabilities or permissions;
- delegation snapshots;
- budget proof;
- approval state.

`AgentExecutionService` resolves those values from current trusted Core state
and calls the existing `TaskService`.

## Immutable execution binding

A bound task stores `agent_execution_spec` containing:

- agent instance ID;
- owning Project ID;
- exact registry fingerprint;
- exact AgentSpec snapshot;
- task kind;
- when delegated, the exact immutable delegation contract snapshot.

The binding is included in both the request fingerprint and task action hash.
Changing the agent/delegation identity therefore changes task identity rather
than silently reusing an old approval or idempotency record.

Migration `0022_agent_execution_identity` keeps the field nullable so all
existing Core tasks remain backward compatible. SQLite triggers reject invalid
bound task kinds, mismatched persisted agent/delegation identity and later
binding mutation.

## Revalidation

Core revalidates bound execution at:

- initial task submission;
- Coding approval;
- task retry;
- final claim immediately before execution.

Revalidation requires:

- active agent instance;
- active owning Project;
- exact persisted AgentSpec and registry fingerprint;
- current active registry match;
- authorized task kind;
- when a Campaign is supplied, Campaign ownership by the bound Project;
- for delegated work, exact still-active delegation;
- active/current delegating parent;
- same delegation Campaign;
- still-reserved, unexpired, exact parent-owned delegation budget proof.

If any requirement has drifted, Core fails closed.

## Coding and Research

Coding remains a normal `developer_run`.

Its trusted AgentSpec worker requirement is translated into Supervisor capability
selection. The spec's independent-review requirement is also enforced: if no
eligible independent reviewer is available, the Coding Agent cannot submit the
task.

Research remains the existing fixed `research_run` runtime with its bounded
read-only retrieval tools. Agent identity does not widen its tool policy.

## Non-goals

This slice does not:

- add a new Core task kind;
- automatically create child agents;
- create AgentSpecs from model output;
- recursively spawn subagents;
- add agent-to-agent messaging;
- widen tools or workers;
- add automatic memory writes;
- alter scheduler authority;
- bypass approvals, budgets, promotion, merge or release controls.
