# Bounded USTAR inventory adapter: offline implementation design

## Evidence and choice
Observed root-owned Python tarfile source is 113907 bytes, SHA256 664f862558196d80a46663a81bc16cd51061ccec6c1fdda5950a106e97e12512. The original mode0644-only attempt remains refused; metadata diagnostic established mode0755. R2 explicitly scoped one inert read of that observed identity, with total content-attempt ceiling2/2 now consumed. No installed source was modified or executed by observation. The source includes its own permissive notice, retained in full with the file; existing Python copyright is already retained. No third-party source is copied into implementation.

Review basis: tarfile imports/constants/helpers lines1-270, TarInfo initialization, header decoding and automatic processing paths around1253-1629. TarInfo.frombuf decodes exactly512 bytes and checks checksum; TarFile/fromtarfile recursively process extensions and may allocate extension-declared data before caller checks. Use only the mature fixed-header decoder. Do not call TarFile/open/fromtarfile/extract/extractall, optional decompressors or CLI. Official Python3.12 API reference (one documentation view) confirms the supported fixed-header API, but is not installed-version authentication.

## Contract
Input is an already uncompressed trusted-owner byte stream. The first policy deliberately accepts POSIX USTAR magic/version only, regular type0, explicit directory5, symlink2 and hardlink1. All PAX/GNU/legacy/sparse/device/FIFO/unknown records are rejected before decoder dispatch or payload reads; no fallback. This is a restricted adapter, not general tar support, and it may refuse actual packages until independently reviewed extension support is added.

Preflight512-byte records before calling TarInfo.frombuf: exact bytes/width/type/magic, zero reserved tail, bounded octal field lexemes, no data after string NUL terminators, no legacy regular-as-directory rewriting. Decoder parses numeric/string/checksum semantics; the adapter retains exact USTAR name using the inspected string helper and refuses normalization disagreement. Existing media_member_contract validation supplies name/type/mode/owner/digest semantics and canonical collision rules. Links remain inert, never resolved. Validate names and non-directory ancestors in either order before file payload reads.

A read-only stream wrapper requests <=64KiB, handles short reads, bounds calls and total bytes before requesting, incrementally hashes the entire tar, checks deadline/cancel before and after each operation. Total expanded cap64MiB; <=8192 records; per-member payload remaining bound before reading. Header+payload padding exact; require two zero terminator blocks, only zero aligned trailing padding and observed EOF. Missing/truncated/extra data fails. Fixed header512B and chunks<=64KiB bound immediate allocations; retained metadata/JSON have explicit <=4MiB budget. No unbounded communicate/getmembers/readall/list or arbitrary-seek method.

Return immutable bounded manifest bytes, actual observed expanded size and full tar hash only. This is parser output, NOT OwnerOutcome, cleanup receipt, archive provenance or runtime authority. Never manufacture cleanup/exit/process observations to validate it. Caller-owned binding is validated before reading. No result on cancellation, timeout, stream/decoder/padding/extent/name/output failure. Ordinary errors have fixed diagnostics; interrupts abort. The60s in-process deadline is cooperative and does not make a blocked stream read preemptible; actual untrusted work still needs separately qualified external process ownership/resource enforcement.
