# v0.15 — Learned-skill generic publication refusal

## Why this is a separate gate

A successful generic GitHub merge is an external side effect. The later
`SkillLearningProposalStore.record_promotion_link` step cannot undo an
already-merged pull request, even when it correctly refuses a competing
learned-skill head. The generic `MergeRequest` currently binds CI, PR,
repository and exact commit identity, but **does not** bind an Ahmad-approved
learned-skill proposal, exact predecessor, or exclusive publication reservation.

Until that authority exists, the generic `PromotionMergeRuntime` refuses new
merges when its reviewed candidate manifest targets the reserved
`skills/procedures` repository root, a descendant, or the ancestor
`skills` entry whose file/symlink replacement could shadow the subtree.
Slash, backslash and normalizable dot path variants are checked. Unrelated
sibling files such as `skills/registry.py` remain eligible. This applies
even if generic CI is
green; it occurs before the GitHub merge PUT and permits no exception from
a user-supplied request field.

This is intentionally **fail closed**: learned procedure artifacts cannot be
published through the current generic Zelo merge executor. Normal code PR
merges outside the protected subtree continue working.

Exact, already-merged PR recovery is retained as historical read-only
verification. It never sends another merge request and does not grant
runtime loading, skill execution, or approval authority.

## Boundaries and future work

- This blocks a category of **new generic Zelo-initiated merges**; it is not
  a global GitHub branch protection rule. Direct merges outside Zelo are
  not intercepted by this Python service.
- A future, separately reviewed learned-skill publication path must bind
  the immutable proposal/review, AgentInstance and source Skill identities,
  target version, exact prior promoted revision, repository, artifact digest,
  PR head, approved merge action and a durable exclusive publication claim.
  It must verify the binding immediately before the external merge and
  handle uncertain remote results/retries without double promotion.
- Do not add an untrusted caller switch, bypass header, or permissive
  default to re-enable generic promotion of reserved learned files.
- No schema migration, new provider, Worker/Tool authority, agent mutation
  or learned-skill runtime activation is part of this gate.

## Qualification

- Path variants rooted at the protected learned-procedure subtree must
  refuse before any merge PUT.
- Ordinary generic merge and exact-head CI checks remain unchanged.
- Historical already-merged retry performs GET only and remains valid.
- Ruff, formatting and exact-head CI are required before merge.
