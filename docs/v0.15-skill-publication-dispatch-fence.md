# v0.15 — One-time operator-only no-send Skill publication fence

- **Stage:** isolated Core implementation, deliberately NON-PUBLISHING.
- **Release state:** v0.15 HOLD until issue #166 is independently closed.

This is a durable prerequisite to a future separately authorized learned-Skill
publisher. It is **not** a GitHub merge executor, Skill loader or a grant of
new Agent/Worker/Tool/Space permissions.

## One fenced action and exact source identity

The authenticated Managing Director must first have an accepted reviewed
proposal, an immutable exclusive `SkillPublicationClaim`, and one existing
immutable `SkillPublicationOperatorDecision` selecting an exact approved
GitHub PR/head/base/required-CI/merge request for later review.

`SkillPublicationDispatchFenceService.reserve` requires the confirmation
string `APPROVE_EXACT_SKILL_PUBLICATION_FENCE_NO_SEND`, plus the exact
frozen `MergeRequest`. It:

1. Refuses unauthenticated principal, wrong confirmation or malformed nested
   merge evidence *before network access*.
2. Retrieves the immutable operator decision and checks that the decision
   belongs to this claim. Absence refuses without accessing GitHub.
3. Uses the reviewed **GET-only** `SkillPublicationBlobEvidenceService` to
   recheck real PR, exact base/head/merge base, app-signed required CI and
   immutable Git commit/tree membership; byte-bounded SHA-256 verifies that
   the approved regular `100644` Skill artifact truly belongs to the head.
4. Compares the live provider proof to the original exact operator decision,
   including claim/repository/PR/head/base and complete merge request digest.
5. Obtains one SQLite `BEGIN IMMEDIATE` writer lock and revalidates live
   AgentSpec, registry, current accepted review, promoted predecessor, and
   unchanged immutable operator decision. It then writes **one** immutable
   action fence for that exact proposal/PR.
6. An exact repeat returns the same receipt with no second reservation.
   A changed request, competing decision for the PR, stale Agent/revoked
   spec or changed GitHub head fails closed.

## Permanent no-send invariant

The stored row and strict Pydantic response both require:

- `phase="reserved_no_send"`
- `network_dispatch_authorized=false`
- `network_dispatch_started=false`
- `runtime_authority=false`

Database constraints and append-only triggers prevent replacement, UPDATE,
DELETE and `INSERT OR REPLACE` of even the same claim. A procedure's
reservation is not released by reboot, retry or a caller-supplied expiration.
The historical record is deliberately inert.

The operator-only `dispatch-fence` API route exposes this no-send reservation.
It does not invoke `PromotionMergeRuntime`, GitHub PR merge, a new Task, local
registry writes or Skill activation. A separate default-disabled `merge-once`
route invokes the one-attempt sender only after explicit confirmation and its
current policy/source checks. The generic protected learned-procedure merge
refusal remains active.

## Remaining publication/release gates

The one-attempt sender now commits a separate append-only send-attempt record
*before* any external GitHub side effect, with exact Task/Actor and operator
approval binding. It makes at most one exact-head conditional merge attempt;
any timeout, lost response or inconsistent provider state remains fenced with
no blind retry and requires distinct read-only reconciliation. The protected
generic merger never accepts this fence as bypass authority. A positive
merge receipt does not automatically update the active Skill Registry.
Live provider qualification and independent exact-head review remain open.

v0.15 still needs Space/Worker qualification, source/licensing, exact-head
CI/review, post-merge regression checks, release audit and an explicit
Managing Director release decision. Media was deferred from v0.15 and remains
unavailable; prior Stage S/H/S2 and native Reader decisions are spent. Parked
UI PR #61 is unchanged.
