## Decision

The original `media_reader_sixth_ledger` remains a stable audit of the five
refusals and fifth fence reconciliation. A small post-cleanup wrapper takes the
same admission lock, verifies that historical audit and the complete one-use
residual cleanup receipt chain, checks the exact completion digest, then
rechecks the historical audit. This preserves the meaning of earlier ledger
results while making the later cleanup mandatory for a proposed sixth-decision
snapshot.
The internal held form is available only to a future caller already owning
the shared lock; the public fixed-root form obtains that lock itself.

The v4 approval parser now requires the residual completion digest in the
Managing Director's *new* comment and returned evidence. It re-audits both
chains around the authenticated GitHub reads supplied by a future caller.
A fifth-run comment or a sixth comment missing the new digest fails closed.

Alternatives considered: extending the historic ledger in place would change
its earlier audit contract; trusting a caller-supplied digest would not prove
the on-disk chain. The wrapper adds a repeated file audit, which is acceptable
for this rare operator path. No Docker query occurs in this evidence parser.

## Remaining execution boundary

A future one-process run path must attest its exact source head and tree,
authenticate GitHub, hold the admission lock across the decision and
allocation, check the live Docker namespace immediately before allocation,
and durably consume only one newly authorized attempt. It needs independent
review and an explicit *sixth* budget decision. This document, parser and
cleanup receipt do not perform those actions. R4 and v0.15 remain HOLD.

## Sixth admission preparation (candidate)

The held v4 fetch and recheck reuse the exact comment parser while a future
caller already owns the shared admission lock **before** writing a lease
marker. They audit the five refusals and residual cleanup around authenticated
GitHub reads without reacquiring that lock. The historical audit requires an
empty marker, so these functions cannot serve as the final post-lease recheck.

A separate read-only live preflight checks the complete labelled Docker
namespace and the eight pinned image IDs with `image ls --all --no-trunc`
before and after Docker readiness. It must be called under the admission lock
before a grant and again immediately before allocation. This candidate has no
operator CLI or automatic caller, does not write a receipt or grant, and does
not allocate or run a sixth proof. The marker-aware final decision recheck,
one-use admission, allocation and real native matrix remain open.

The next read-only candidate accepts only a live `Lease` held by the calling
thread under its lifecycle guard. It rechecks the canonical retained root and
verifies that the lease's open directory, lock and marker descriptors still
name the retained admission path, then derives the exact marker bytes from
the lease identity and policy digest, then rechecks all five pinned refusals
and the residual cleanup receipt chain. The resulting evidence must equal the
pre-marker snapshot except for the marker's occupied state. A changed marker,
receipt or historic proof refuses without clearing the marker. This remains a
file-only check; it does not create a grant or allocate a sixth attempt.

A separate proposed post-lease decision recheck now takes the still-retained
lease and pre-marker snapshot. It verifies the exact live marker/receipt chain
before and after the three fixed GitHub resource reads, validates the same
fresh sixth comment, and refuses body or metadata drift from the earlier
snapshot. The future operator must supply the authenticated GitHub transport,
hold the lease throughout this call, persist its recheck evidence durably and
bind the one-use grant and allocation to that exact invocation. This parser
alone performs none of those writes or runtime actions.

## One-process sixth decision capture (candidate)

A further isolated candidate holds the same admission lock from the empty
marker through challenge generation, authenticated decision reads supplied by
its caller, live Docker namespace preflights before the decision and after
each GitHub read sequence, durable receipt and
recheck writes, an exclusive v4 grant/seal, and the admission marker write.
The grant binds the five-refusal history, all cleanup digests, exact source
head/tree, comment ID/body/challenge hashes and a limit of six. Every entry is
exclusive and synced; a changed comment or uncertain write leaves any existing
receipt/grant path fenced and refuses before a marker or proof. The challenge
is generated in the invocation and cannot be supplied by a later process.
After the durable marker is written, source and expiry are sampled again;
an expired or changed result returns no lease and leaves the marker fenced
for explicit reconciliation. It is never reset into a new proof budget.

This capture has no operator CLI, post-lease persisted decision recheck,
allocation gate or native Reader execution. A readable grant or seal never
permits a sixth attempt by itself. The complete one-process run path still
requires adversarial qualification, independent review, current-head CI and
a **new explicit sixth** Managing Director budget decision before use.
