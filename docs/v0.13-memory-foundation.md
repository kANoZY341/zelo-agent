# v0.13 — Memory foundation

## Purpose

This slice creates the first durable Zelo-owned memory records without yet
making Mind read or write them automatically.

The foundation is intentionally append-only. A correction or supersession is a
new record linked to the record it replaces. Historical records remain
addressable for provenance, debugging and later evaluation.

## Scope model

Every record has exactly one explicit scope:

- `personal`: operator-level context; no scope ID;
- `project`: bound to an existing Core Project ID;
- `agent`: bound to a typed namespace key. This does not create an AgentSpec or
  Agent Factory before v0.14.

Memory kinds are `fact`, `preference`, `decision` and `experience`.
Operational Task/Campaign state remains in its existing canonical tables rather
than being copied into memory.

## Provenance and lifecycle

Each record stores a provenance kind, optional source reference and bounded note.
The first supported provenance kinds are operator, conversation turn, task,
project, agent and import. A provenance reference is evidence metadata; it does
not grant execution authority.

Records may have an optional expiry timestamp. Default list reads exclude expired
records and records that have been corrected or superseded. Historical reads
remain available with `include_inactive=true`.

Replacement chains are linear: one record can be replaced at most once. A
replacement must remain in the exact same memory scope.

## API

```text
POST /memories
GET  /memories?scope_kind=<personal|project|agent>&scope_id=<optional>
GET  /memories/{memory_id}
```

All routes require the existing operator authentication.

## Explicitly not in this slice

- no automatic extraction from conversations;
- no memory-to-Mind prompt injection;
- no semantic/vector retrieval or embeddings;
- no model-decided retention policy;
- no deletion/rewrite of history;
- no Agent Factory;
- no new approvals, scheduling, merge or release authority.

The next memory slice can build bounded scope-aware retrieval and context
assembly on top of these immutable records.
