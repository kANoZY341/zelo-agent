## Standalone source-build qualification

Performed on the authorized Zelo Ubuntu host using an ignored, isolated
qualification copy, not via the Core/Mind/Agent worker system:

1. npm ci --ignore-scripts --no-audit --no-fund installed 374 packages
   from the committed npm lockfile. All npm install lifecycle scripts were
   disabled, and no global REA installation or MCP client registration ran.
2. npm run build:unlocked succeeded using Node v22.23.2, compiling 1,223
   TypeScript files into 945 generated JavaScript files.
3. The compiled source's own CLI ran in a disposable, unprivileged, offline
   Docker container with no network, read-only root and target mounts,
   dropped capabilities, no-new-privileges, 384 MiB/no swap, one CPU and
   a 64-process limit. It analyzed a harmless two-file JavaScript fixture.
4. The result reported REA provider rea-javascript-application version 1,
   exactly one parsed JS file, one static finding, operation
   analyze_javascript_application and Evidence ID
   ev_0f2c503826e337eeac41e4791b41654cdcf3dffc4991b48bc2629b192e4fa617.
   The target JavaScript was not executed.

This demonstrates a local build and one static Linux analysis. It is not
a qualification of every REA tool, arbitrary hostile inputs, a persistent
computer, native engines, runtime capture, or all transitive dependencies.

## Verifiable local source integrity

The standalone no-network verifier is:

    .venv/bin/python -m scripts.verify_rea_source_vendor

It validates the fixed manifest SHA-256, upstream tag/commit/root tree,
the exact 2,082 file inventory, Git blob hashes and executable modes,
license notices, no extra files/symlink escape and the five optional engine
gitlink identities. The fast Python regression tests run in normal Core CI.

Intentional modifications to vendored source require a versioned feature
branch, reviewed new manifest/pinning and independent qualification. Never
silently alter upstream copyright, run setup scripts during Core startup or
assume that a source file gives itself Core authorization.

Zelo-owned adapters continue to follow standard Ruff validation; the
pinned upstream source tree is excluded from automatic Ruff reformatting.
Git whitespace checks exempt this upstream tree to preserve its original
bytes rather than masking errors in Zelo-owned code.
