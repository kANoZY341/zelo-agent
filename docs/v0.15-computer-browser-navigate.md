# v0.15 — Named-endpoint Agent computer navigation

## Goal

Add the first Agent-executable browser mutation action without granting arbitrary
browser control.

This slice is stacked after:

- persistent Agent computer foundation;
- Core computer ownership/control;
- read-only Computer Worker;
- Core-owned browser egress policy; and
- internal-only Agent computer network topology.

The only new mutation is:

```text
browser_navigate
```

## Task input

The Agent/model never supplies a URL.

The task provides only:

```json
{
  "action": "browser_navigate",
  "endpoint_id": "trusted_name",
  "path": "/bounded/path"
}
```

`endpoint_id` must exist in trusted Core configuration and in the owning
AgentSpec's explicit `computer.browser_endpoint_ids` grant. The path is
canonical, absolute-within-origin, bounded, and rejects query strings, fragments,
backslashes, NUL/CR/LF, `.`, `..` and authority-form `//...`.

Core constructs the target from:

```text
trusted HTTPS origin + bounded path
```

No task field can replace the scheme, host or port.

## Separate Worker authority

Read-only observation stays on:

```text
worker: computer_core
capability: computer_read
authority: agent-computer-read-v1
```

Navigation uses a different Worker selection:

```text
worker: computer_navigate_core
capability: computer_navigate
authority: agent-computer-navigate-v1
skill: computer_navigation
```

The mutation Worker is registered only when all prerequisites exist:

- persistent computer backend configured;
- exact internal-only computer CIDR configured;
- Core egress proxy host configured; and
- at least one trusted browser endpoint configured.

Adding navigation therefore does not widen `computer_core`.

## Frozen execution identity

Every navigation `ComputerExecutionSpec` binds:

- AgentInstance UUID;
- exact Agent registry snapshot through Agent execution identity;
- exact `computer_navigate_core` Supervisor selection;
- worker-authority policy fingerprint;
- action = `browser_navigate`;
- bounded path;
- trusted endpoint binding including endpoint registry version;
- Core egress-policy version;
- persisted computer permission fingerprint;
- OpenBot backend/topology identity; and
- timeout.

Any drift invalidates queued work before a running attempt is created.

Retry creates a new action version and rebinds the current trusted identities.

## Runtime checks

Immediately before execution, Core revalidates:

- Agent execution identity/current registry membership;
- navigation Worker selection;
- browser permission;
- permission fingerprint;
- endpoint registry binding;
- egress-policy fingerprint;
- internal-topology/backend identity;
- action, endpoint ID, path and timeout.

The Computer Runtime also rechecks permission/backend/endpoint/egress identity
before calling OpenBot and after the navigation response returns.

## Human takeover

Navigation is refused while:

- a human holds the computer;
- a handoff request is pending; or
- control is transitioning.

The navigation Worker never takes or releases control itself.

OpenBot's handback rule remains intact: after human control is returned, its
fresh-snapshot requirement still governs later element actions.

## Egress

The Agent computer has no direct public egress in the qualified topology.

Chromium leaves through the per-Agent authenticated Core CONNECT proxy. The
proxy independently revalidates:

- current active Agent;
- exact trusted Agent registry snapshot;
- persisted browser permission;
- Agent `computer_navigate` capability;
- Agent endpoint grant;
- exact trusted endpoint host/port;
- endpoint registry version; and
- public-address DNS resolution.

Authority is rechecked on connection establishment, after DNS, and before tunnel
chunks are forwarded. Permission revocation therefore blocks both new and
already-open traffic.

## Final-origin check

OpenBot may follow normal browser redirects. A navigation is not considered a
valid Zelo result merely because OpenBot reports success.

The returned final page must still be:

- HTTPS;
- on the exact frozen endpoint host;
- on the exact frozen endpoint port; and
- free of URL credentials.

A cross-origin final page fails with
`computer_navigation_final_origin_denied`.

## Result handling

The bounded result may include:

- trusted endpoint ID;
- final URL;
- bounded title;
- bounded readable page text;
- truncation flag;
- elapsed milliseconds; and
- challenge-present metadata.

Full navigation text may exist in the task result for the owning Agent's work,
but normal task/conversation projection strips the page text and exposes only
bounded metadata such as endpoint, URL/title preview, character count and
truncation state.

## Activation policy

Agent activation policy v4 adds two navigation-specific checks:

- explicit browser profile + endpoint grants; and
- an enabled `computer_navigate` Worker.

A deployment that has only the read-only Computer Worker cannot activate an
Agent declaring navigation authority.

## Explicit non-goals

This slice does **not** grant:

- arbitrary URL navigation;
- query-string task input;
- click;
- type/fill;
- key presses;
- scroll;
- form submission;
- credential/secret injection;
- file writes;
- downloads as an authority surface;
- shell/exec;
- screenshots in Agent/model context;
- host filesystem/browser/shell access;
- direct public egress; or
- UI changes.

Those require later explicit authority decisions and independent qualification.

## Next gate

After this slice is reviewed, green in full CI and independently qualified on the
real pinned OpenBot topology, the next browser mutation should be evaluated
separately.

Click/type/key/scroll must not inherit authority merely because navigation
passed. They require snapshot/ref freshness, risk/action policy, takeover
interaction, cancellation and side-effect review before becoming executable.
