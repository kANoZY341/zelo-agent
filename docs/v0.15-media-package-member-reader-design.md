# Media package-member reader: candidate design, not execution clearance

This follows the exact-version dpkg source research. It deliberately separates
byte streaming, tar-member interpretation and later materialization. None is
implemented or qualified by this document. No archive is parsed from this plan.

## Proposed boundary

Core-owned admission -> authenticated fixed archive FD -> immutable native reader
sandbox -> bounded tar stream -> separately qualified tar inventory reader ->
validated manifest -> complete owned cleanup -> proof-bound receipt.

A package archive hash proves the selected archive bytes, not that a native
reader is safe or that its output is a complete member/provenance map. A manifest
also does not establish loader/ABI/import closure or authorize image decoding.

The only candidate native command is a fixed literal path to an approved copied
`dpkg-deb`, with `--threads-max=1 --fsys-tarfile -`. A control-tar action would be
a separate fixed action and budget, not a caller-provided option. Prefer inherited
stdin from a verified immutable archive copy over reopening a caller pathname.
No command string, shell, argument interpolation, archive-supplied executable,
`--info`, `--field`, `--contents`, extraction, package install or maintainer script.
Verify DPKG_TAR_PASSTHROUGH in its exact source header before finalizing this path.

## Required closure before a native launcher is allowed

1. Exact runtime manifest: executable, loader, linked native libraries, required
   locale/config data and notices with literal paths, sizes and hashes. Clarify
   the trust assumption for each installed bootstrap artifact; do not silently
   relabel source-host observations as independently authenticated binary origin.
   No ambient PATH/library search, unqualified compressor helper or writable
   runtime file may enter the sandbox. No apt/dpkg installation or host changes.
2. Close the named source gaps for initialization/options, command dispatch,
   passthrough enum and memory/thread queries. A separate finite literal manifest
   is required; the completed 16-request corpus is exhausted. No recursive search.
3. Choose and inspect a mature secondary tar reader before implementing one.
   Prefer a stream/file-object API with no extract/extractall path. Neither human
   `tar -tv` parsing nor a new general ar/tar/xz/zstd implementation is acceptable.
   Bind its exact source/runtime and license; unsupported metadata fails closed.
4. Identify existing Zelo admission, process-tree ownership and namespace/resource
   helpers to reuse unchanged. They must actually enforce the native reader's
   process/thread/resource model; prior ELF or Browser evidence is not automatic
   qualification of this new runtime, command or decoder.

## Proposed resource and result contract

The following are conservative design ceilings to validate, not observed capability:
- one package at a time; eight fixed input archives already accepted in PR86;
- aggregate native-process memory <=512MiB, no swap, <=8 tasks/threads, <=0.5 CPU;
- per-process address space <=512MiB, CPU time <=30s, descriptors <=32, no core dump;
- parent-enforced wall-clock stop at60s per archive, with an explicit bounded owned
  kill/reap phase; cancellation immediately invalidates any prospective result;
- tar stdout <=64MiB per archive, <=128MiB across the fixed batch; stderr <=64KiB
  per archive and never promoted to executable instructions or trusted metadata;
- no unbounded communicate(), full stderr traceback or in-memory joined tar stream;
- candidate member inventory <=8192 entries/archive, <=16384 across the batch,
  name/link text <=1024bytes/entry and serialized evidence <=4MiB/archive.

Reserve fixed byte/file/process budgets before allocations. Bound decompression
output independently of metadata count. Saturation is permanent refusal even if
the upstream tool later reports exit0; dpkg can normalize decompressor SIGPIPE.
The external owner must stop and settle every owned process, not only dpkg-deb's
parent PID. A cleanup ambiguity preserves the admission fence and no success
receipt. Never broad-kill processes, infer ownership from names or retry raw FDs.

No cgroup/namespace probe or allocation is cleared here. These candidate limits
must be mapped to supported existing mechanisms and tested against fake then
controlled native fixtures before any real archive-member qualification.

## Tar semantics to settle before implementation

Inputs must be fixed authenticated modern package bytes. --deb-format=2.0 does
not restrict parsed inputs; design a narrow reviewed precondition rather than
assuming legacy shell paths cannot be reached. Do not use this as a reason to
write a second general archive parser.

The secondary reader must retain exact ordinal/name/type/mode/size/digest data
and reject duplicate normalized names, traversal, absolute paths, NUL/control
characters and ambiguous normalization. Define the one permitted './' convention
explicitly. Links must be represented as inert metadata, never followed or created;
selecting a linked runtime file requires a later separately validated resolution.
Devices, FIFOs, sockets, sparse files and unsupported extensions fail closed.
Directory and file metadata must not select host output destinations.

Specify exact acceptance of POSIX/PAX/GNU forms before using the parser, including
how extension payload sizes are bounded before allocation and how duplicate keys,
GNU longnames, trailing records, tar termination/padding and truncated streams are
handled. A native reader exit0 or pipe EOF alone cannot prove these properties.
No external tool output alone upgrades all-compressed-bytes-consumed or checksum
validity; claim only the framing/completeness actually proved by the chosen path.

A first inventory stage retains no extracted package files. Hash payloads while
streaming and retain only bounded names, metadata, hashes and authorized notices.
Any later file selection/copy requires separate trusted destinations and license/
source/runtime/ABI/import closure review. No writes to the host installation.

## Required offline controls before a native attempt

Define fake-only tests for immutable source/input mismatch before launch; invalid
identity/action/argv; aggregate input/output/member budgets before materialization;
partial writes; duplicate names and links; timeout/cancellation; descendant escape
attempt; blocked stderr/stdout; close/reap failure; empty/short/extra/truncated
streams; SIGPIPE followed by exit0; stale/replayed/tampered manifest; and receipt
refusal after failed cleanup. Control inputs must demonstrate the intended failure,
not merely any exception. Real native fixtures require source/launcher clearance.

A unique finite member-reader qualification scope must be approved before first
use, with failure retention and no retry/reset inherited from source research.
It cannot reuse or reset origin, index, ELF, loader, acquisition or local-identity
attempts. Exact-source review, actual evidence, matching full CI and exact-tree
merge remain gates. No runtime enabled flag, Core binding, UI change or later
milestone completion follows from this candidate design.

## Direct design disposition

Useful direction; NOT CLEARED for implementation of the native launcher, tar
parser or materializer, and NOT CLEARED for execution. The next actionable item
is a bounded closure proposal for the named helpers and secondary-reader choice.
Pure documentation and existing fake regression checks may proceed. The known
source gaps must be resolved rather than hidden by a successful package download.
