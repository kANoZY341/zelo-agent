## Staged input decision, not yet cleared

### 30 October source-index reconciliation (read-only research)

After the ninth **synthetic** native Reader matrix passed, the retained
15-file source corpus and separate eight-file helper corpus were re-read on
the Zelo host. All 23 files (1,146,370 bytes) matched the sizes and SHA-256
pins in the two reviewed gate manifests. This is source-byte continuity, not
distribution source authentication or package execution authority.

The host's current `noble-updates` InRelease (SHA-256
`96c33b3572665457051772ca8456301bbf4f1c19d877231d8c86f259c584de44`)
verified with the already pinned `gpgv` binary and Ubuntu Archive keyring;
the signing fingerprint was
`F6ECB3762474EDA9D21B7022871920D1991BC93C`. Its signed SHA256 section
names `main/source/Sources.xz` as 581,352 bytes, SHA-256
`45897fa0cc9cafc430c90c1b779a504dd6fe0716aa0741378a531317bbaf9384`.
One bounded GET against the live archive refused on size before accepting an
index or extracting a dpkg stanza. No retry, source-index proof, descriptor
request, tarball request, package execution or runtime grant followed.

The live archive and an earlier cached InRelease are a moving pair. Ubuntu's
documented provenance chain is signed InRelease → hash-bound Sources → hash-bound
source descriptor and tarball. The descriptor's *uploader* signature is a
distinct identity claim, not the Ubuntu Archive signing key. A candidate
snapshot design must first bind the same timestamped archive state for every
member of that chain. See Ubuntu's [archive verification](https://documentation.ubuntu.com/security/software-integrity/archive-verification/)
and [snapshot service](https://snapshot.ubuntu.com/) documentation; their
examples are design references, not Zelo input grants.

### Stage S: immutable archive snapshot, proposed before Stage D

Freeze one exact Ubuntu snapshot ID and the `noble-updates/main` paths before
any input request. Use that same snapshot ID for the release metadata, Sources
index, descriptor and source tarball URLs; reject a live-archive fallback.
A reviewed, bounded one-use acquisition must retain the
snapshot InRelease and its exact `Sources.xz` with partial-failure accounting,
no redirect/proxy/fallback/retry, separate byte and time ceilings, and no
system APT configuration change. Verify the InRelease with a reviewed explicit
Ubuntu Archive keyring and isolated `gpgv`; require the expected signing
fingerprint and strict status. The accepted receipt must pin the raw InRelease
SHA-256 and validate its signed Suite/Codename, main component, and
Date/Valid-Until fields under an explicit historical-snapshot time policy.
The snapshot ID is a service locator, not a signed claim of publication time;
changed or ambiguous release metadata refuses. Parse only the authenticated SHA256 entry for
`main/source/Sources.xz`, then require exact compressed byte size/hash before
bounded decompression and unique `dpkg` version `1.22.6ubuntu6.6` selection.
Pin the descriptor and tarball filename/size/SHA and the literal pool
`Directory` from that stanza. Any changed
signed value, missing version, duplicate field or unqualified snapshot refuses
the phase. The candidate timestamp and request limits still need exact review;
the 30 October observation is **not** this acceptance receipt.

Stage S provides archive membership/integrity, not the human uploader's
identity or a source-to-binary build correspondence. This Stage D design
additionally requires independently pinned uploader identity and signature
verification after the archive chain; a keyserver result is not an automatic
trust anchor. Stage D below remains blocked until this new source-index design has
been implemented, reviewed and qualified.

### Stage D: descriptor only

A separate reviewed research allowance would make **one** GET to the exact
snapshot-qualified `.dsc` URL derived from the accepted Sources `Directory`
and filename, no redirects, proxy, alternate mirror, conditional retry or
ambient credentials. Reserve at most **65,536 response bytes**, one private
exclusive regular evidence file and a bounded journal before the request. A
non-200 response, short/oversized body, TLS uncertainty, close uncertainty,
write/fsync failure or timeout consumes the allowance and retains partial
failure evidence. No automatic second GET is permitted.

Before parsing or trusting the descriptor, require its exact response length
and SHA-256 to equal the accepted Sources stanza's `.dsc` entry. Its
authenticated source/version, source tarball filename, size and SHA-256 must
then agree with the same accepted stanza; mismatches permanently refuse.
The historical live-archive URL above is a research locator, not an authorized
Stage D input.

Before Stage D can run, an independent reviewer must pin the exact trusted
OpenPGP key identity/fingerprint, permitted source-signing purpose, key material
hash, validity/revocation policy and isolated verification tool/runtime identity.
The verifier must consume the exact retained `.dsc` bytes and an explicit
read-only keyring; no keyserver, user trustdb/cache, default key search,
attacker-supplied key or network during verification. A parsable descriptor
or a generic "good signature" message is insufficient. The authenticated
version/source name, native format, exactly one tarball filename/size/SHA and
all unexpected fields must be reviewed before a tarball input is selected.
The key and signature policy are **not yet pinned**, so Stage D remains
blocked and this document performs zero GETs.

Derive one literal snapshot-qualified HTTPS tarball URL from the accepted

candidate caps; metadata/journals need a separate explicit bounded allowance.
The tarball URL remains **unresolved** until Stage D has passed. Stage T is
not authorized by Stage D or by this proposal.
Require the received archive's exact size and SHA-256 to match both the
accepted Sources stanza and the verified descriptor before archive parsing.

## Isolated static inspection and acceptance

Treat the tarball and `.dsc` as data. Inspect with a separately reviewed,
bounded mature archive reader in a no-network, no-write sandbox; no package
scripts, build, extraction to host paths, executable import, `dpkg-deb`, shell
pipeline or acquired `.deb` read. Pin parser/tool source and license, maximum
entry count, per-member/aggregate expanded bytes, path/link/type rules,
streaming limits, wall-clock/resource ceilings and owned cleanup before use.
Unsupported extensions, links, traversal, duplicate names, checksum mismatch
or resource/cleanup uncertainty refuse the phase. Retain an immutable
inventory and compare source archive members to the exact reported Git tree
with an independently reviewed membership method. Do not equate equal version
strings or cgit blob observations with this equivalence.

Compare the authenticated archive against the **23 already retained source
files** and their exact pinned hashes, including the eight helpers. Reconcile
the known passthrough/options/program/command/meminfo behavior with source
archive membership. Then name only unresolved locale/debug/error descendants,
actual build configuration and library provenance in a separately reviewed
finite manifest. Unknown edges stop the gate; no recursive fetch or duplicate
request for a known helper.

Installed `dpkg-deb` binary/package membership, actual loaded libraries, ABI,
real archive-format compatibility and Core Media authority remain separate
proofs even if this static source phase passes.

The earliest reviewable next decision is therefore **Stage S** with one pinned
snapshot and explicit archive-key/verifier policy, followed by a separate
Stage D descriptor decision bound to its accepted Sources record. The literal
archive URL, source/archive-to-Git relationship, installed build/binary
correspondence and locale/debug/error/runtime closure are explicit blockers.
Both spent source corpora and all eight native Reader refusals remain terminal;
the ninth synthetic pass is separate and grants no actual package authority.
See `docs/reviews/media-package-reader-source-review.md`,
`docs/reviews/media-reader-helper-review.md` and
`docs/reviews/media-reader-helper-gates.json` for the separate historical
