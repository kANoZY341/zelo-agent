# Public research with reviewed project memory

## Purpose

The first public research workflow connects Zelo's existing Browser Worker,
Mind, Research Worker, and project memory into one bounded operator task. Its
initial question is practical: which access and diagnostic patterns in three
Agent-Reach channel files fit Zelo's current public-retrieval boundaries?

Previously, Browser could retrieve from explicitly configured HTTPS origins,
while Research could inspect only local workspace evidence. The new workflow
stages verified Browser results as readable evidence, then lets a real Mind
turn request the existing `research_run` task. Research keeps its workspace
read tools; the operator workflow owns source selection and evidence staging.

This is an opt-in development workflow. It does not change production chat
routing, default Browser settings, the published release, or runtime Agent and
Skill authority. Current engineering remains within v0.15.

## One complete task

1. Create a fresh private run directory, isolated Core database, and separate
   model-readable workspace. Check that the selected local model is installed.
2. Prepare the existing qualified Browser source bundle with current code and
   the explicit public origin `https://raw.githubusercontent.com`.
3. Submit and execute one normal Core Browser task for each pinned source.
   Require a successful persisted task, its exact request and binding, complete
   text, and the independently expected fetched-body hash.
4. Stage each verified source in the owned workspace, with provenance and the
   retained MIT notice. Preflight the actual typed file-read result against the
   Research tool-output budget before inference.
5. Send the goal and exact evidence filenames to a real local-model Mind turn.
   Dispatch only the resulting expected Research task through Core's normal
   claim and Runner path.
6. Verify every cited Research source against its staged file and typed tool
   result. Retain a report for semantic review, with the actual answer, source
   mapping, task identities, model usage, and cleanup outcome.
7. Separately record an operator-reviewed concise summary through Core's
   append-only MemoryService. Verify retrieval in the report's project and
   exclusion from another project.

An unexpected Mind task, incomplete source, invalid citation, or unsuccessful
cleanup is recorded as a failed stage. A successful process exit alone does not
establish that the complete workflow passed.

## Evidence and review contracts

Three different hashes retain different meanings:

| Identity | What it binds |
|---|---|
| Browser source digest | Exact fetched response body |
| Staged artifact digest | Evidence-file bytes, including their provenance header |
| Research source digest | Canonical JSON of the typed `read_workspace_file` result, including path, text and truncation status |

The mapper requires complete `read_workspace_file` sources, exact expected
locators, and exact typed-result hashes. Research's ordinary source-ID validator
is useful but cannot establish these stronger workflow-specific conditions by
itself. Its source IDs become public citations through the retained mapping to
the Browser task, origin, path, upstream commit, and source hash.

The reviewed-memory command receives the expected digest of the exact report
bytes and a separately reviewed summary. It verifies the report against its own
successful Research task, project, and database before writing. It serializes
admission and handles an exact replay without creating another memory record.
The exact shared budget mapping is checked before acquiring the admission lock
or opening the database, alongside the model settings and report eligibility.
Canonical comparison rejects changed types as well as changed or missing limits.
The memory provenance refers to the Research task and report digest. A separate
memory receipt avoids making the report's digest depend on the memory that
cites it.

Memory retrieval always requests the explicit project scope. The workflow does
not put source text into personal memory or change normal Mind context admission.

## Runtime scope and retained evidence

All Core state, Browser preparation, model-readable files, and reports belong
to the isolated run. The model-readable workspace is under the current
checkout's `workspaces/` directory; runtime databases and admission records are
kept outside that read surface. Init-only settings and a reviewed minimal
process environment prevent live `.env` or proxy configuration from selecting
another database, provider, or Browser receipt.

The current candidate uses the already installed `qwen3.5:4b` through
Zelo's Model Gateway, pinned to digest
`2a654d98e6fba55d452b7043684e9b57a947e393bbffa62485a7aac05ee4eefd`.
The workflow explicitly requests a 16,384-token context and each exact Core
output schema, with thinking disabled. A copied, opt-in provider sampling
mapping requests temperature 0.7, top-p 0.8, top-k 20, min-p 0, presence penalty
1.5, repeat penalty 1.0, seed 10102026, and at most 1,024 generated tokens.
The nonthinking sampling choices follow the
[official model card](https://huggingface.co/Qwen/Qwen3.5-4B/blob/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a/README.md);
the seed, context and output cap are separately chosen workflow bounds.

The shared provider preserves its existing defaults when these options are
omitted, and sampling overrides apply only to structured actions. The real
qualifier and its HTTP fixture use the same `workflow_provider()` factory.
Requested settings, model identity, usage and elapsed times are retained in the
report; the separate memory gate requires the exact same requested settings.
This changes neither installed model tags nor normal production routing, and
does not implicitly download a model. A fixed seed is recorded without claiming
cross-platform or cross-version deterministic output.

Browser cleanup follows the current qualified ownership and admission helpers.
An unresolved cleanup state retains its fence and evidence. The retained Media
native-reader runtime and its four exhausted attempts are outside this work.

## Run the fixed workflow

From the implementation checkout, use its trusted Python environment and the
previously qualified Browser source bundle:

```bash
env -i PATH=/usr/bin:/bin HOME="$HOME" LANG=C.UTF-8 \
  /path/to/trusted-venv/bin/python -B -m scripts.qualify_public_research \
  --source /path/to/qualified/browser/source/bundle \
  --source-manifest-digest 5cd2da1e5d84d268dbe7c46e6a95f82d640babed410ffd1f31c681de37f424ca \
  --acknowledge-live-public-research
```

The clean environment preserves the existing home directory and supplies only
reviewed process variables; a normal shell environment is refused before setup.
Replace the Python path with the trusted environment already installed for Core;
an isolated worktree does not need a new dependency installation.

The acknowledgement opts into this command's public HTTPS reads, owned Docker
resources, and local model calls. The source digest is the independently
retained source-bundle manifest identity, not a prepared-renderer digest.
The command records its new run directory and preserves failure evidence.

| Budget | Current fixed value |
|---|---:|
| Each Browser task | 30 seconds |
| Each Mind model call | 240 seconds |
| Each Research model call | 480 seconds |
| Whole Mind turn | 966 seconds, computed by current Core settings |
| Research task | 600 seconds |
| Dispatch cleanup grace | 15 seconds |
| Research model steps | 6 |
| Research tool calls | 4 |
| Research parse retries | 1 |
| Serialized tool result | 16,384 characters |

Inspect the generated report and its digest before the separate reviewed-memory
command. Record a concise summary of supported conclusions; do not automatically
store the model's full answer. The memory receipt records which report and
summary were admitted and the scoped retrieval checks. An operator may perform
this review through an authorized assistant; the provenance does not claim a
personal human review of the generated answer.

The separate command accepts the report path, the SHA-256 of the exact reviewed
report bytes, the reviewed summary, and a recall query:

```bash
/path/to/trusted-venv/bin/python -B -m scripts.record_public_research_memory \
  --report /absolute/path/to/proof-RUN_ID/report.json \
  --expected-report-sha256 REVIEWED_REPORT_SHA256 \
  --reviewed-summary "Supported conclusions reviewed against the three sources." \
  --recall-query "Agent-Reach public retrieval"
```

These values are placeholders. The report must be in the command's own fixed run
directory; arbitrary report/database paths and changed report bytes are refused.
An exact replay verifies the same memory and receipt. A changed summary for an
already admitted report requires a separate explicit correction workflow.
