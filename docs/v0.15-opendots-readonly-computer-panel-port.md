# OpenDots Computer Panel — isolated read-only React adaptation

This independently reviewed Core-backed adapter continues the curated source
work of PR #130. The exact MIT upstream `CopilotKit/OpenDots` reference is
pinned in `integrations/community/sources/opendots/src/client/ComputerPanel.tsx`.
It is **reference data**: the Zelo-owned component is not upstream Dot runtime,
not an imported Space permission store, and never executes upstream JSX.

## Delivered (read-only and detached)

- `workspace/lib/computer-panel.ts`: strict Zelo Core-v1 panel projection
  validation, exact `AgentInstance` identity, tab metadata and refusal of any
  response claiming new navigation, shell, file or takeover authority.
- `workspace/app/api/agents/[id]/computer/panel/route.ts`: workspace-scoped,
  operator-token-backed server-only proxy for existing authenticated Core
  `GET /agents/{instance_id}/computer/panel`. Rejects malformed IDs before
  dispatch, uses the existing restricted loopback `proxyCore`, rejects requests
  missing `X-Zelo-Workspace: 1`, and never passes caller credentials upstream.
- `workspace/components/AgentComputerPanel.tsx`: React panel with Browser, Files,
  Terminal and Activity tab projections, only for computer capabilities in the
  *trusted* existing Zelo AgentComputerSpec. Readiness respects current Core
  computer state/permissions. Shows recent ten event **names** from Core with
  no event details, credentials, source text, screenshots or commands. A single
  10-second poll with abort/unmount handling avoids overlapping work and wipes
  stale authority display on errors. Tab switching is local-only.
- Workspace TypeScript and happy-dom tests verify the exact API authority
  boundary, no foreign credential forwarding, invalid target refusal,
  no tab-driven mutation, strict schema, and safe DOM presentation.

**Deliberately not mounted in production `workspace/app/page.tsx`.** UI PR #61
remains parked, and no new UI route or active agent capability was enabled.
The component can later be mounted into the reworked Control Desk once Zelo
Core and the UX are qualified. This source import does **not** implement live
browser screenshot/file reading or interactive Terminal; the browser/files
status text explicitly says interactive operations require separate controls.

## Remaining OpenDots completion gates

1. Bring the actual Computer Panel into the chosen Zelo workspace route,
   preserving user-selected tabs and error boundaries during reconnect.
2. Add independently authorized browser snapshots/read, file browsing and
   terminal output projections; never present speculative state as a screenshot
   or reuse OpenDots' Dot IDs/credentials.
3. Separately qualify existing operator Take Control / Return Control
   interactions, race cancellation, stale-backend refusal and audit receipts.
4. Enforce Space/project/document grants through Zelo-owned AgentInstance
   authority and revocation, not copied OpenDots `dot_spaces` storage.
5. Complete evidence-driven learning → evaluated draft Skill → trusted review
   → versioned publication → measured use, without self-granting Tool authority.

No Agent Factory, active Worker Registry, Task/approval schema, Space grant,
Docker runtime, external connector or UI PR #61 file is changed by this slice.

## Initial verification

The exact isolated workspace slice passed TypeScript `tsc --noEmit`,
`next typegen`, all 18 Next/React workspace tests and a complete optimized
Next.js 16.3.6 production build, including the new server-only dynamic
`/api/agents/[id]/computer/panel` proxy route. Independent GPT-6 Astra Medium
read-only code review found no actionable defects. These checks establish
compile/contract compatibility; they do **not** qualify interactive computer
actions or claim the parked UI has been redesigned.
