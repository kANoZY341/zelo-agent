# Specialist Dot — governed learning history (read-only candidate)

The OpenDots Specialist profile now offers a separate operator-only view of existing
Zelo governed Skill Learning proposal metadata at:

    GET /agents/{instance_id}/specialist-profile/learning

This uses the exact existing Core SkillLearningProposalStore.list_for_agent()
and its persisted immutable proposal, event and review verification, not a global
newest-100 sweep or imported OpenDots learner. Results are scoped to the requested
AgentInstance and bounded to the latest 32 proposal metadata entries. The total
count and more_available marker disclose truncation explicitly.

Entries show source Skill ID/version, proposed procedure ID/version, immutable
revision digest, proposed/accepted/rejected decision, whether a human review
exists, and whether a promotion evidence link exists. A link is not activation,
and an accepted proposal is not an executable or published Skill. No
instructions, evidence payloads, prompts or procedure source code are returned.

The operator must authenticate through existing Core bearer authentication;
missing AgentInstances return 404 and invalid persisted proposal/history records
refuse generically with 503. The Agent profile inspection state is included
so stale, retired or paused agent bindings are not portrayed as permissions.

Every entry and the response retain explicit execution_enabled=false,
automatically_learned_or_activated=false, permission_widening=false, and
model_context_admission=false. No new Worker, Task, Space, Tool, computer or
published Skill Registry authority is created. No automatic feedback loop,
model learning, skill publication or governance bypass is enabled.

This remains a development candidate stacked on the inert Space-intent
foundation and the Context/Archify import chain. The full per-AgentInstance
outcome evaluation, proposal, review, promotion and runtime-evidence lifecycle
requires separate qualification (issue #131). UI PR #61 stays parked.
