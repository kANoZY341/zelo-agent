# Zelo Core v0.15 — API Worker

## Status

Sixth bounded implementation slice of the v0.15 Capability and skills ecosystem.

Merged prerequisites are Capability Registry PR #55, Skill Registry PR #56,
Generic Worker Registry PR #57, Research Worker PR #58, and Python Worker PR #59.

## Goal

Add useful read-only HTTPS API access without creating an arbitrary network or
credential escape hatch. Core owns endpoint configuration, routing, DNS validation,
connection identity, response bounds, and audit.

## Trusted contract

The built-in worker is `api_core`, role `api`, capability `api_read`, with
`public-api-read-no-credentials-v1` authority. No default AgentSpec or department is
added. Agent-bound `api_run` is refused at submission because the persisted Agent
task-kind constraint does not admit it. A future trusted AgentSpec can require
`api_run` only after that contract and its lifecycle checks are implemented.

Operators configure at most 32 named canonical HTTPS origins. A task may select only
one configured endpoint ID, a relative path, bounded query keys/values, and timeout.
The task cannot supply a URL, method, credential, authorization header, proxy, TLS
setting, executable, or network policy.

There is no host-secret lookup or credential-injection mechanism. Bounded query
strings are still caller-provided text and can contain tokens or private data; do
not submit credentials through them. They are sent to the configured origin and
stored as task input. The absence of auth headers is not a content-level secret filter.

## Network boundary

Only GET is supported. This is a transport-authority restriction, not a guarantee
that every approved remote GET endpoint is semantically side-effect-free; operator
approval must account for the remote API contract. Redirects and environment proxies
are disabled. Immediately before each request, Core resolves the trusted hostname, rejects the request unless
every returned address is globally routable, then connects to one validated IP while
preserving the trusted hostname for TLS SNI and the Host header. This prevents a task
from redirecting the connection toward loopback, link-local, private, metadata, or
other non-public addresses.

Paths are ASCII URI path characters only, without percent escapes, dot segments,
backslashes or repeated slashes, bounded to 2048 bytes. Queries have at most 32
string pairs (keys 1–128 characters, values at most 2048), an 8192-byte encoded
limit, and no CR/LF/NUL.

Responses must have JSON content types. Wire and decoded bodies each have a
262144-byte cap. Only identity, single gzip or zlib-wrapped deflate encodings are
accepted; inflation is bounded during decompression, and truncated or trailing
compressed data fails. Empty JSON, duplicate keys, non-finite numbers, invalid
UTF-8/surrogates, nesting beyond 64, redirects and oversized bodies fail closed.
The combined DNS/request timeout is 0.1–30 seconds. DNS resolution uses the
system resolver through a worker thread. Timing out cancels Zelo's wait, but Python
cannot forcibly terminate a getaddrinfo() call already blocked inside the operating
system; operators should treat a persistently unhealthy resolver as a host-level
availability problem. A non-2xx JSON response is a failed task with a bounded result.

Use `ZELO_API_WORKER_ENDPOINTS` as a JSON array of `name=https://canonical.origin`
entries; it defaults to empty. See the README and `.env.example` for configuration.

## Persisted identity

Migration `0028_api_worker_selection` adds `tasks.api_spec` and `api_run`.
The persisted ApiExecutionSpec binds the endpoint-registry version, exact endpoint
definition, API policy version, and exact WorkerSelectionSnapshot. Action hashing
binds the whole specification. Retry performs fresh trusted selection and endpoint
binding; claim and Runner revalidate everything before execution.

Adding this network surface advances WorkerAuthority policy identity to v4. Existing
pending snapshots created under older authority semantics therefore fail closed and
must use normal retry/reselection.

## Non-goals

This slice does not add arbitrary URLs, credentials, authenticated APIs, request
bodies, POST/PUT/PATCH/DELETE, custom headers, file downloads, workspace access,
Browser/Computer control, Shell Worker authority, or package installation. Mind does
not route `api_run` in this slice because configured endpoint names are not exposed
as a trusted Mind routing surface.

## Verification

Required gates include endpoint canonicalization, public-address enforcement,
connection pinning, redirect/proxy/credential denial, bounded JSON parsing, exact
selection and endpoint identity, retry/revalidation, action-hash tamper rejection,
migration/trigger preservation, diff/Ruff checks, full pytest, adversarial review and
exact-head GitHub CI.

## Local verification (2 October 2026)

Implementation commit `7a5884a1d2e6115d8192bca8883a20d3d9add800` was verified on
the Zelo host, outside the Codex sandbox: 195 focused API/worker-registry/
capability/skill/database tests passed with 3 warnings. That includes all 100
API-specific cases. Diff, Ruff lint and Ruff format checks passed.

The separate Astra Medium read-only review found no demonstrated authority bypass.
It documented the resolver-thread availability limitation and clarified that GET-only
and absence of credential injection are transport restrictions, not guarantees
about remote side effects or arbitrary query contents. Network tests use controlled
transports. The HTTPX/httpcore test verifies TCP pinning, TLS hostname/verification
settings and Host headers; it is not a live certificate-handshake test.

The fresh real-clone full run on `7a5884a` completed with 1049 passed, 1 failed,
and 12 warnings. The sole failure was
`test_later_runnable_work_can_overtake_deferred_developer_task`: a wall-clock race
around a 250-millisecond backoff. The follow-up regression fix uses a controlled
clock and checks eligibility immediately before and exactly at the stored deadline,
without changing production scheduling. Its targeted test passes.

Earlier sandbox runs stalled on denied asyncio wakeup-socket sends and rejected
linked worktree metadata. Timer-assisted results are diagnostic only, not release
evidence. The final exact-head full suite and GitHub CI remain required before merge.
