# v0.13 — Worker/model performance and cost evidence

## Purpose

This fourth v0.13 slice makes already-persisted execution evidence queryable
without turning metrics into routing authority.

The design is deliberately read-only:

```text
ConversationTurn / TaskAttempt / developer result
  -> bounded evidence extraction
  -> safe usage/timing fields only
  -> per-model / per-worker summaries
  -> authenticated evidence API
```

No prompt, reply, diff, worker summary or hidden reasoning is copied into the
evidence response.

## Sources

The evidence service reads existing Core records only.

Model evidence can come from:

- Zelo Mind `ConversationTurn` records;
- `ai_prompt` task attempts;
- `agent_run` task attempts;
- `research_run` task attempts;
- `self_improvement_run` planner attempts.

Worker evidence can come from:

- `developer_run` task-attempt results;
- persisted independent-review results nested in a developer attempt.

Every evidence row carries the exact persisted source ID. Task-attempt rows also
carry attempt number and task kind/ID where appropriate.

## Usage and timing

Only counters already reported and persisted by Core are surfaced.

Model evidence preserves:

- prompt tokens;
- completion tokens;
- total tokens;
- reported/partial/unreported usage status;
- observed attempt duration when Core has start/end timestamps.

Developer/reviewer evidence preserves the safe counter vocabulary already
accepted from worker adapters, including Codex-style cached input counters and
Claude-style cache creation/read counters.

Per-model and per-worker summaries are computed only over the bounded rows
returned in that response. The response declares:

```text
summary_scope = "returned_evidence_only"
```

so a bounded window cannot be mistaken for all-time history.

## Monetary cost

Current persisted model and coding-worker sources do not provide trusted
monetary billing records.

Therefore the evidence API explicitly returns:

```json
{
  "status": "not_reported_by_current_sources",
  "currency": null,
  "amount_micros": null
}
```

Zelo does not apply guessed token prices, scrape a vendor price table, or convert
usage counters into currency. Token usage is resource evidence, not monetary
cost evidence.

A later provider/worker integration may expose a trusted reported charge, but it
must be added as an explicit source contract rather than inferred here.

## API

Authenticated operator route:

```text
GET /performance/evidence?limit=200
```

The limit is bounded to 1–500. Model and worker rows are ordered by observed
time and the summaries describe only the returned evidence window.

## Outcome semantics

Summaries keep these categories separate:

- `succeeded`;
- `failed`;
- other outcomes such as cancellation/interruption.

Cancellation is not silently counted as failure.

Developer evidence also carries validation pass/fail when the persisted result
reported it.

## Authority boundary

This slice is evidence only.

It does not:

- automatically select a model or worker;
- change Supervisor policy;
- alter approvals or budgets;
- create pricing estimates;
- persist prompts/replies into a new analytics store;
- add automatic memory writes;
- add Agent Factory;
- change merge/release authority.

Evidence-based model/worker routing remains a later milestone (v0.18).

abstraction for future Postgres/Supabase/vector backends.
