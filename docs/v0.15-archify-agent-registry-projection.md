# Archify — actual Agent Factory registry templates, not running Agents

The imported Archify architecture schema is exact-source pinned and verified,
but its renderer remains inert. This candidate adapts existing Zelo Core's
trusted immutable AgentRegistry into a deterministic, bounded architecture
diagram that can be inspected with no HTML/JS execution.

## View

GET /integration-candidates/community/architecture/agent-registry

Existing operator authentication is required. The response exposes:
- the trusted Core AgentRegistry fingerprint;
- exact counts for its registered AgentSpec and DepartmentSpec templates;
- Archify-compatible JSON plus a static Mermaid text projection;
- a SHA256 checksum binding the view metadata and exact diagram bytes.

Only agent IDs, organizational level and lifecycle of *templates* are shown.
It does not read AgentInstance data or inspect devices, browser sessions, memory,
instructions, private credentials or runtime Task statuses. A registered
"active" AgentSpec is a *configuration*, not proof of a running agent.
Department edges reflect only current trusted registry membership. Unassigned
registered agents attach directly to the Agent Factory node.

The output is limited to 22 agent and 8 department definitions plus one Factory
node. Oversized or untrusted input is refused rather than truncated. An invalid
or missing pinned Archify source or registry produces a generic operator-only
503 without exposing source validation details. The full
imported Archify renderer is **not** run. This view carries no permission to
activate an agent or modify any organizational relationship.
