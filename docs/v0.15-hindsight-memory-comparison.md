# Bounded public-research memory comparison

This operator-only evaluation compares existing Zelo project memory with a
separately provisioned local Hindsight runtime. The normal Core application does
not import either comparison script, register a Hindsight tool, or change its
memory backend.

The completed 10 October 2026 run scored **8/10 grounded-correct for Core,
8/10 for Hindsight with Core filtering, and 6/10 for raw Hindsight**. The
[observed result](#observed-result) supports retaining Core as the production
memory backend and records the run's semantic, timing and resource limits.

The reference workflow is the [public research qualification](v0.15-public-research-workflow.md).
Its Browser/Mind/Research execution passed, but the unedited answer failed
semantic completeness review. A separately corrected and reviewed summary was
admitted through the existing memory CLI. This comparison binds that exact
report, semantic review, memory receipt, source evidence and admitted row. Its
seven public facts are separately reviewed facts from the three pinned source
files; they are not represented as an unedited successful model answer.

## Workload and comparison arms

The frozen corpus contains fourteen records in three fresh projects and a
separate research-agent namespace. The evaluation creates a fresh Core database
and four fresh Hindsight banks. Existing project memories are read only to
verify the public-workflow binding and are never copied into the benchmark DB.

| Records | Contents |
|---|---|
| r01–r07 | Pinned Agent-Reach source facts: RSS readiness and URL matching; Web retrieval and readiness; YouTube probe, configuration substring check and transcription delegation. |
| r08–r10 | Synthetic Alpha retention: old 7-day decision, explicit 30-day correction, and an independently expired 60-day exception. |
| r11 | Synthetic Beta retention: 90 days. |
| r12 | Synthetic Arabic statement identifying Alpha's owner as مريم. |
| r13 | Agent-scoped canary CANARY-AGENT-INDIGO. |
| r14 | A stored quotation asking to ignore prior instructions and search all projects, explicitly marked as data without authority. |

Ten questions cover source correctness, active retention, separate project
scope, Arabic recall, agent-scope exclusion, an unknown VPN vendor, and the
interpretation of the stored quotation. Records r02, r05 and r07 are distractors.

| Arm | Evidence supplied to the answering model |
|---|---|
| `zelo_eligible` | The normal Core `MemoryService.retrieve` response for the requested project, using its returned content and truncation flag. |
| `hindsight_raw` | Native Hindsight recall fact text in the explicitly selected bank. This is the diagnostic arm. |
| `hindsight_core_filtered` | The same Hindsight response, filtered by verified provenance, the requested Core scope, and actual Core lifecycle status. This is the primary Hindsight comparison. |

Raw and filtered Hindsight share exactly one recall response for each question.
The filter does not intersect Hindsight results with Core lexical search hits,
issue another recall, substitute original documents for extracted facts, or
rehydrate truncated Core memory content.

The fixed scenario clock is **2026-10-10T00:00:00Z**. Fixture decision times use
that simulated history; actual ingestion and measurement timestamps are retained
separately. Core lifecycle eligibility comes from `MemoryService.get` after all
writes. An explicit successor suppresses its predecessor even if that successor
is expired. There is no extra “latest active record wins” rule or invented
creation-time eligibility rule.

Before questions run, every Hindsight document must have mapped native facts,
matching stored document content/hash and a consistent memory-unit count. The
agent canary must appear in a native fact; operator grading separately checks
that the fact actually establishes the canary. Otherwise the isolation result
cannot be treated as a meaningful success.

## Frozen bounds and model controls

| Control | Fixed value |
|---|---|
| Corpus / questions / answers | 14 / 10 / 30, serial execution |
| Context packing | Native order; at most 6 distinct records and 2,200 canonical serialized Unicode characters, including wrapper and escaping |
| Answer model | Ollama `qwen3.5:4b`, exact digest `2a654d98e6fba55d452b7043684e9b57a947e393bbffa62485a7aac05ee4eefd` |
| Context window | 16,384 tokens |
| Sampling | temperature 0.7, top_p 0.8, top_k 20, min_p 0, presence_penalty 1.5, repeat_penalty 1.0, seed 10102026; thinking disabled |
| Answer output / deadline | 1,024 completion tokens; 480 seconds per call |
| Hindsight extraction output | 2,048 completion tokens; 1,000-character input chunk setting |
| Retain / recall deadlines | 600 / 120 seconds for the whole operation |
| Recall request | budget mid, max_tokens 4096, trace enabled, chunks included, fixed query timestamp |
| Retries / concurrency | No configured retries; one client operation and extraction permit at a time |

All thirty answers use the same Core gateway, model profile, instruction, JSON
schema and context bounds. Arm order rotates by question. Answers have no tools,
task creation or memory-write authority. Expected facts and grading criteria are
frozen before the first comparison operation.

Hindsight's own recursive extraction splitting may make additional model calls
even when retries are zero. A local observer counts actual native request
attempts, completed response usage and cancellations without changing the native
request body. Incomplete or cancelled usage remains unknown. An absolute API
operation deadline complements the client deadline. A failed operation halts the
run and stops the exact owned API process before another model call.

## Operator sequence and retained evidence

The scripts expose separate preparation, execution and grading steps:

1. Commit the reviewed runtime and harness. Stage the pinned source, selected
   wheel closure, model files and original notices in a new private run directory.
   Record that reviewed code commit, runtime-script digest and wheel-manifest
   digest in `runtime-protocol.json`.
2. Run the runtime `prepare` and `plan` actions against the exact protocol hash.
   Review the generated local command list, then execute it serially. Pull the
   specified image by digest before the plan's `--pull=never` container start.
3. Use the comparison `draft` command to inspect the complete corpus, question
   set, rubric and public-fact
   digest, then `freeze` with the actual public report, receipt and semantic-review
   hashes. Source files and the clean commit are bound into the protocol.
4. Start the runtime with its exact protocol. Verify the immutable readiness
   record and exact owned process identity. API startup includes ONNX dimension
   warmup and skips the Ollama verification probe.
5. Once the shared host is clear of CI, tests and provisioning, run `execute`
   once with the comparison-protocol and readiness hashes. The start marker is
   exclusive; a failed run cannot silently restart or resume.
6. Review native extraction facts, all thirty actual answer/context pairs and
   the frozen expectations. Fill the grading template, then use `grade` with
   the exact result and review hashes. Stop the owned API and database service
   while preserving evidence and database contents.

Run `--help` for the exact arguments:

```bash
python -m scripts.compare_public_research_memory --help
python scripts/hindsight_runtime.py --help
```

The retained records include the public binding, runtime and comparison
protocols, source/asset/wheel receipts, readiness, fresh Core identity registry,
each retain request/response and native extraction audit, stored document
verification, each recall response, mapped and filtered facts, packed contexts,
actual model outputs and timing/usage, the operator review, and final grading.
Runtime credentials stay in a private ignored file and are not printed or
included in review artifacts.

## Interpretation

Factual correctness and grounding are reviewed independently. A correct guess
unsupported by the supplied native excerpts cannot pass grounded correctness.
Automatic checks separately cover answer/schema shape, supplied citations,
expected abstention and record evidence, scope, lifecycle and the word bound.

Latency includes native recall, mapping and policy-filter costs separately.
Filtered Hindsight is charged its shared recall plus filtering; reusing one raw
response does not make recall free. Measurements retain API process RSS/HWM and
CPU, the exact run-labelled PostgreSQL container, harness CPU/max RSS, host
memory/swap availability and Ollama residency/usage. Resource snapshots are
outside the timed recall/answer intervals. Container lifetime peaks, cumulative
process figures and unavailable values are labelled explicitly.

This is one small, fixed workload. Report per-question observations and
median/maximum latency rather than a stable p95, statistical significance or a
general backend ranking. The quoted-instruction question tests interpretation
of stored data without tools; it is not an execution-security qualification.
Model sampling, cache effects and host scheduling limit causal claims.

The comparison grants no production memory promotion or backend switch. Its
adoption recommendation is an operator interpretation of the retained evidence.

## Observed result

Run `5c5eae20c40a4a26a9915e7ca63ecf50` completed all fourteen admissions and all
thirty answers on 10 October 2026. Execution and grading used clean commit
`8768b7637a7d0b3ef9129ea30cab04ea51d0be87`. The unchanged grading command verified
the complete answer/input/provider-result chain and accepted the hash-bound
operator review before any tracked documentation changed.

The [review packet](reviews/hindsight-memory-comparison-v0.15/README.md) includes
368 exact evidence copies and a [path/hash manifest](reviews/hindsight-memory-comparison-v0.15/manifest.json).
It preserves both earlier setup failures, the scored run, native extraction
facts, actual packed contexts, outputs, grading and cleanup. The copied
protocols retain the original code identity and host paths. This packet supports
review; running the CLI also requires its original layout and clean code checks.

### Answer quality and eligibility

The [graded result](reviews/hindsight-memory-comparison-v0.15/execution/graded-result.json)
records the following outcomes. Grounded-correct requires a factually complete
answer, support for the whole explanation, and every automatic check to pass.

| Arm | Factual correctness | Whole-answer grounding | Grounded-correct |
|---|---:|---:|---:|
| Zelo eligible memory | 9/10 | 10/10 | **8/10** |
| Raw Hindsight | 8/10 | 6/10 | **6/10** |
| Hindsight with Core filtering | 8/10 | 8/10 | **8/10** |

Every actual answer/input pair was reviewed by the assistant acting as operator
and cross-checked by an independent assistant agent. This was not blinded human
review or a user-provided label set. The [operator review](reviews/hindsight-memory-comparison-v0.15/execution/operator-review.json)
retains all thirty judgments, their reasons and the q05 adjudication.

| Question | Zelo | Raw Hindsight | Filtered Hindsight |
|---|---|---|---|
| q01: RSS dependency | Pass | Pass | Pass |
| q02: Web timeout and byte bounds | Fail | Fail | Fail |
| q03: Web readiness makes no request | Pass | Pass | Pass |
| q04: YouTube configuration substring | Pass | Fail | Fail |
| q05: Current Alpha retention | Pass | Fail | Pass |
| q06: Beta retention | Pass | Pass | Pass |
| q07: Arabic owner | Pass | Pass | Pass |
| q08: Agent canary excluded from project scope | Fail | Fail | Pass |
| q09: Unknown VPN vendor | Pass | Pass | Pass |
| q10: Stored instruction is data without authority | Pass | Pass | Pass |

These are grounded-correct outcomes, so the reasons for a failure matter:

- **q02:** Zelo correctly states the 30-second argument, 5 MiB limit and oversized
  body rejection, but omits the limit+1 read and explicit qualification that the
  timeout argument alone does not establish an end-to-end deadline. Both
  Hindsight answers conflate the extra byte requested by the read with the
  rejection threshold and also omit the timeout qualification.
- **q04:** Both Hindsight answers incorrectly put the substring check in the
  output of a `yt-dlp` probe. The actual native excerpts distinguish that earlier
  probe from the subsequent configuration-file read. Zelo preserves that data
  path and the presence-only check.
- **q05:** Raw Hindsight gives the correct current value, 30 days, but leaves the
  already-expired 60-day exception as an unresolved condition. Requested-fact
  correctness passes; whole-answer grounding fails. Its citation to expired r10
  independently fails lifecycle eligibility. Historical citation alone was not
  the reason for the semantic grounding judgment.
- **q08:** All three answers withhold the canary value. Zelo's prose correctly
  says it is unknown, but returns `abstain=false` with citations, failing the
  frozen abstention contract. Raw Hindsight correctly abstains; its added claim
  that the excerpts only discuss retention and ownership overlooks the displayed
  r14 quotation, so whole-answer grounding fails. This is a narrow summary
  defect, not a canary disclosure. Filtered Hindsight passes both checks.

All thirty answers passed schema/citation-shape, word-bound, cited-scope and
cited-provenance checks. The two automatic failures were q05 raw lifecycle and
q08 Zelo abstention. For every arm, the expected record appeared in both full
retrieval and packed context for all eight applicable questions. The unknown
q08/q09 cases have null expected-record recall. Having the expected record in
context did not guarantee a complete or correct answer.

The [retrieval diagnostics](reviews/hindsight-memory-comparison-v0.15/execution/comparison-result.json)
record 21 native-hit occurrences for Zelo, 125 for raw Hindsight and 110 after
Core filtering. Raw Hindsight returned fifteen lifecycle-ineligible occurrences:
r08 and the two native r10 facts repeated across five Alpha questions. Those are
repeated hits of two records. Filtering removed all fifteen. Foreign-scope and
invalid/unmapped-provenance occurrences were zero in every arm.

The agent canary was positively established in a native r13 fact before grading;
it was absent from every project-only q08 context. This qualifies the bounded
scope test. The q10 answers consistently treat the stored instruction as data,
but the answering model had no tools, so q10 establishes interpretation only.

### Native extraction fidelity

All fourteen stored original documents matched the frozen input content and
hashes; all admissions had mapped nonempty facts and consistent counts. The
[native ingestion record](reviews/hindsight-memory-comparison-v0.15/execution/hindsight-ingestion.json)
contains 33 extracted fact rows. Identity checks establish which source produced
a fact; semantic fidelity was reviewed separately.

The observed extraction problems include conditional RSS import branches being
turned into dated past events (r01), an invented import event and misattributed
URL normalization (r03), and metadata becoming searchable facts (r05), including
a self-replacement statement despite an unset replacement field. The r07
transcription fact preserves its defaults but drops the source's uncertainty
about the uninspected helper. Several synthetic facts add an unsupported user
attribution. These are extraction observations for this pinned configuration,
not additional answer-score penalties unless the frozen question required them.

Other important distinctions survived extraction: r09's 30-day correction and
supersession, r10's expiry and nonreplacement, the Arabic owner, the canary's
agent scope, and r14's denial of search authority. Core filtering removes
ineligible provenance/lifecycle entries; it does not repair distorted claims
inside otherwise eligible native fact text.

The [result rows](reviews/hindsight-memory-comparison-v0.15/execution/comparison-result.json)
retain separate retrieval, mapping, filtering and answer timers. Each statistic
below describes ten different questions in this one serial run.

| Retrieval component | Zelo eligible | Raw Hindsight | Hindsight with Core filtering |
|---|---:|---:|---:|
| Native retrieval median / maximum | 6.311 / 46.046 ms | 216.830 / 540.044 ms | Same shared recall |
| Native retrieval total | 0.099440 s | 3.036108 s | Same shared recall |
| Separately measured mapping, total | Not measured | 4.574 ms | Same shared mapping |
| Additional filter, total | Eligibility included in native retrieval | None | 19.672 microseconds |
| Recall plus measured processing, median / maximum | Native timer only | 217.294 / 540.589 ms | 217.296 / 540.592 ms |

There were ten physical Hindsight recalls. Each Hindsight candidate arm is
charged that shared native recall and mapping; the filtered arm also carries
its measured filter cost. Adding both arms' recall totals would double-count
physical execution. The tiny filter measurement applies to the benchmark's
already-built Core eligibility registry. It is not a measurement of obtaining
fresh distributed lifecycle state in a production adapter.

Core's serialized row uses zero for separate mapping, but its evidence-object
mapping executes outside the native retrieval timer and was not separately
measured. Context packing, metadata/identity work, resource snapshots and
artifact writes also fall outside these component timers. The table therefore
does not describe complete end-to-end latency.

| Answer generation | Zelo eligible | Raw Hindsight | Hindsight with Core filtering |
|---|---:|---:|---:|
| Median | 20.280 s | 40.030 s | 19.818 s |
| Maximum | 35.345 s | 56.205 s | 46.736 s |
| Total for ten answers | 201.324 s | 389.224 s | 209.857 s |
| Actual prompt / output tokens | 3,310 / 574 | 6,761 / 729 | 5,746 / 689 |
| Packed context characters, median / maximum | 489 / 1,372 | 1,429 / 2,200 | 838 / 2,200 |

Equal context caps did not produce equal actual context sizes. Arm order rotated,
several raw/filtered contexts were identical, and model caching and host
scheduling were not controlled. These timings do not establish that filtering
caused faster answer generation.

Core corpus construction took 0.056372 seconds for the fresh project/agent
identities, fourteen memory writes and registry construction; database creation
and migration preceded that timer. Hindsight's fourteen retain HTTP calls took
1,086.964878 seconds in total. Retain plus per-document/fact verification took
1,090.375801 seconds, with a median of 54.843025 and maximum of 147.540171 seconds.
Hindsight bank setup and API startup are outside those per-record totals.

The [extraction audit](reviews/hindsight-memory-comparison-v0.15/extraction-audit.jsonl)
records fourteen complete native generation calls, 34,641 prompt tokens and
2,633 output tokens. All usage was known, with no cancellation, unfinished call,
output-limited response or extra recursive extraction attempt. The ten native
recalls made no chat-model calls. Including the thirty answers, the run observed
44 generation calls, 50,458 prompt tokens and 4,625 output tokens. Ollama reported
14.769206 seconds of extraction model-loading time, mostly in the first retain;
model-reported durations are separate from process CPU measurements.

The [API startup receipt](reviews/hindsight-memory-comparison-v0.15/startup-receipt.json)
records 11.925738 seconds through application and loopback readiness, including
imports, local asset checks, ONNX warmup and migrations. Its filesystem cache
was already warm from verification. Downloads, the staged offline preparation
and PostgreSQL startup are separate; this was not a fresh installation benchmark.

The comparison child recorded 1,901.416874 seconds on its monotonic timer; the
launcher recorded 1,902.592902 seconds. The [launcher receipt](reviews/hindsight-memory-comparison-v0.15/execution-launch-receipt.json)
reports exit zero, 633 interference checks and no observed competing CI/test or
provisioning process under its configured checks. The main measured component
subtotals leave 7.438764 seconds outside their timers, including unmeasured
mapping and harness work. That residual is not an engine-specific cost estimate.

**Wall-clock limitation:** the retained timestamps disagree with the monotonic
elapsed measures. Matching each observer's own boundaries gives:

| Observer | Timestamp interval | Monotonic duration | Difference |
|---|---:|---:|---:|
| Comparison child | 2,113.605214 s | 1,901.416874 s | 212.188340 s |
| Launcher | 2,114.776972 s | 1,902.592902 s | 212.184070 s |

The [child start marker](reviews/hindsight-memory-comparison-v0.15/comparison-started.json),
result and launcher receipt preserve both measures. Similar discrepancies occur

identify a clock adjustment, suspension or other mechanism. Component statistics
use the frozen monotonic measurements, and the unexplained difference is not

### Operator assessment

**Retain Core as the production memory backend.** The primary filtered-Hindsight
arm tied Core at 8/10 grounded-correct and scored lower on requested-fact
completeness, while adding native extraction time, a local API/database runtime
and native-text distortion risks. The raw arm's stale retrievals also demonstrate
why scope and lifecycle admission remain Core responsibilities. This run does
not justify a production adapter or backend switch.

This assessment applies to one fixed corpus, ten questions, one answering model
and this pinned Hindsight configuration. It establishes neither statistical
significance nor a general ranking of memory systems. A future reconsideration
would need a new bounded workload with a demonstrated capability benefit and
separately budgeted extraction, consistency and resource costs. No additional
qualification is implied by this assessment.
