# Bounded public-research memory comparison

This operator-only evaluation compares existing Zelo project memory with a
separately provisioned local Hindsight runtime. The normal Core application does
not import either comparison script, register a Hindsight tool, or change its
memory backend.

The reference workflow is the [public research qualification](v0.15-public-research-workflow.md).
Its Browser/Mind/Research execution passed, but the unedited answer failed
semantic completeness review. A separately corrected and reviewed summary was
admitted through the existing memory CLI. This comparison binds that exact
report, semantic review, memory receipt, source evidence and admitted row. Its
seven public facts are separately reviewed facts from the three pinned source
files; they are not represented as an unedited successful model answer.

## Workload and comparison arms

The frozen corpus contains fourteen records in three fresh projects and a
separate research-agent namespace. The evaluation creates a fresh Core database
and four fresh Hindsight banks. Existing project memories are read only to
verify the public-workflow binding and are never copied into the benchmark DB.

| Records | Contents |
|---|---|
| r01–r07 | Pinned Agent-Reach source facts: RSS readiness and URL matching; Web retrieval and readiness; YouTube probe, configuration substring check and transcription delegation. |
| r08–r10 | Synthetic Alpha retention: old 7-day decision, explicit 30-day correction, and an independently expired 60-day exception. |
| r11 | Synthetic Beta retention: 90 days. |
| r12 | Synthetic Arabic statement identifying Alpha's owner as مريم. |
| r13 | Agent-scoped canary CANARY-AGENT-INDIGO. |
| r14 | A stored quotation asking to ignore prior instructions and search all projects, explicitly marked as data without authority. |

Ten questions cover source correctness, active retention, separate project
scope, Arabic recall, agent-scope exclusion, an unknown VPN vendor, and the
interpretation of the stored quotation. Records r02, r05 and r07 are distractors.

| Arm | Evidence supplied to the answering model |
|---|---|
| `zelo_eligible` | The normal Core `MemoryService.retrieve` response for the requested project, using its returned content and truncation flag. |
| `hindsight_raw` | Native Hindsight recall fact text in the explicitly selected bank. This is the diagnostic arm. |
| `hindsight_core_filtered` | The same Hindsight response, filtered by verified provenance, the requested Core scope, and actual Core lifecycle status. This is the primary Hindsight comparison. |

Raw and filtered Hindsight share exactly one recall response for each question.
The filter does not intersect Hindsight results with Core lexical search hits,
issue another recall, substitute original documents for extracted facts, or
rehydrate truncated Core memory content.

The fixed scenario clock is **2026-10-10T00:00:00Z**. Fixture decision times use
that simulated history; actual ingestion and measurement timestamps are retained
separately. Core lifecycle eligibility comes from `MemoryService.get` after all
writes. An explicit successor suppresses its predecessor even if that successor
is expired. There is no extra “latest active record wins” rule or invented
creation-time eligibility rule.

Before questions run, every Hindsight document must have mapped native facts,
matching stored document content/hash and a consistent memory-unit count. The
agent canary must appear in a native fact; operator grading separately checks
that the fact actually establishes the canary. Otherwise the isolation result
cannot be treated as a meaningful success.

## Frozen bounds and model controls

| Control | Fixed value |
|---|---|
| Corpus / questions / answers | 14 / 10 / 30, serial execution |
| Context packing | Native order; at most 6 distinct records and 2,200 canonical serialized Unicode characters, including wrapper and escaping |
| Answer model | Ollama `qwen3.5:4b`, exact digest `2a654d98e6fba55d452b7043684e9b57a947e393bbffa62485a7aac05ee4eefd` |
| Context window | 16,384 tokens |
| Sampling | temperature 0.7, top_p 0.8, top_k 20, min_p 0, presence_penalty 1.5, repeat_penalty 1.0, seed 10102026; thinking disabled |
| Answer output / deadline | 1,024 completion tokens; 480 seconds per call |
| Hindsight extraction output | 2,048 completion tokens; 1,000-character input chunk setting |
| Retain / recall deadlines | 600 / 120 seconds for the whole operation |
| Recall request | budget mid, max_tokens 4096, trace enabled, chunks included, fixed query timestamp |
| Retries / concurrency | No configured retries; one client operation and extraction permit at a time |

All thirty answers use the same Core gateway, model profile, instruction, JSON
schema and context bounds. Arm order rotates by question. Answers have no tools,
task creation or memory-write authority. Expected facts and grading criteria are
frozen before the first comparison operation.

Hindsight's own recursive extraction splitting may make additional model calls
even when retries are zero. A local observer counts actual native request
attempts, completed response usage and cancellations without changing the native
request body. Incomplete or cancelled usage remains unknown. An absolute API
operation deadline complements the client deadline. A failed operation halts the
run and stops the exact owned API process before another model call.

there is no network resolver fallback.

The API uses the library factory, explicit configuration and loopback addresses.

model downloads or content export through the configured paths. Built-in local
metrics still initialize and remain available for the comparison. The account home
directory remains unchanged. No upstream MCP, worker, observation,
consolidation, or maintenance service is activated.

## Operator sequence and retained evidence

The scripts expose separate preparation, execution and grading steps:

1. Commit the reviewed runtime and harness. Stage the pinned source, selected
   wheel closure, model files and original notices in a new private run directory.
   Record that reviewed code commit, runtime-script digest and wheel-manifest
   digest in `runtime-protocol.json`.
2. Run the runtime `prepare` and `plan` actions against the exact protocol hash.
   Review the generated local command list, then execute it serially. Pull the
   specified image by digest before the plan's `--pull=never` container start.
3. Use the comparison `draft` command to inspect the complete corpus, question
   set, rubric and public-fact
   digest, then `freeze` with the actual public report, receipt and semantic-review
   hashes. Source files and the clean commit are bound into the protocol.
4. Start the runtime with its exact protocol. Verify the immutable readiness
   record and exact owned process identity. API startup includes ONNX dimension
   warmup and skips the Ollama verification probe.
5. Once the shared host is clear of CI, tests and provisioning, run `execute`
   once with the comparison-protocol and readiness hashes. The start marker is
   exclusive; a failed run cannot silently restart or resume.
6. Review native extraction facts, all thirty actual answer/context pairs and
   the frozen expectations. Fill the grading template, then use `grade` with
   the exact result and review hashes. Stop the owned API and database service
   while preserving evidence and database contents.

Run `--help` for the exact arguments:

```bash
python -m scripts.compare_public_research_memory --help
python scripts/hindsight_runtime.py --help
```

The retained records include the public binding, runtime and comparison
protocols, source/asset/wheel receipts, readiness, fresh Core identity registry,
each retain request/response and native extraction audit, stored document
verification, each recall response, mapped and filtered facts, packed contexts,
actual model outputs and timing/usage, the operator review, and final grading.
Runtime credentials stay in a private ignored file and are not printed or
included in review artifacts.

## Interpretation

Factual correctness and grounding are reviewed independently. A correct guess
unsupported by the supplied native excerpts cannot pass grounded correctness.
Automatic checks separately cover answer/schema shape, supplied citations,
expected abstention and record evidence, scope, lifecycle and the word bound.

Latency includes native recall, mapping and policy-filter costs separately.
Filtered Hindsight is charged its shared recall plus filtering; reusing one raw
response does not make recall free. Measurements retain API process RSS/HWM and
CPU, the exact run-labelled PostgreSQL container, harness CPU/max RSS, host
memory/swap availability and Ollama residency/usage. Resource snapshots are
outside the timed recall/answer intervals. Container lifetime peaks, cumulative
process figures and unavailable values are labelled explicitly.

This is one small, fixed workload. Report per-question observations and
median/maximum latency rather than a stable p95, statistical significance or a
general backend ranking. The quoted-instruction question tests interpretation
of stored data without tools; it is not an execution-security qualification.
Model sampling, cache effects and host scheduling limit causal claims.

The comparison grants no production memory promotion or backend switch. Its
adoption recommendation is an operator interpretation of the retained evidence.
