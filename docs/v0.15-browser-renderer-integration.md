## Integrate the existing prerequisites

- One canonical AdmissionController/ResourceOwner lease must cover the whole job,
  before any DNS/helper/container/transport is spawned. Preserve crash fencing.
- Construct the ownership handle before creating external resources. Label every
  created container with the trusted lease identity; failed client acknowledgements
  cannot make the handle forget an existing resource.
- Use an operator-prepared, verified content-addressed image containing only the
  browser, libraries and fixed pipe/bootstrap executable. Execution must not build,
  pull, select arbitrary images or accept caller flags/env/mounts/profiles.
- Bind image identity, complete artifact roles/content, generated seccomp profile,
  fixed controller protocol, renderer policy and resource policy into one immutable
  execution contract. Scanner equality alone is not immutable attachment proof.
- Revalidate the exact image/profile/configuration immediately before start. Preserve
  nonroot, cap-drop ALL, no-new-privileges, read-only, network-none and cgroup limits.
- Keep the browser's anonymous pipe private to the trusted controller. No debug port,
  browser console access, raw CDP command API, arbitrary evaluation or user session.
- Start in an opaque blank context; disable page scripts before injecting evidence.
  No user-supplied navigation, redirects, headers, cookies, clipboard or downloads.

## Bounded work and truthful cleanup

- Fetch only through the existing approved-origin document broker, under the same
  lease and an absolute deadline. Keep HTML labelled untrusted evidence, never
  commands that can modify policy or instructions to the controller.
- The controller's protocol methods/parameters are fixed trusted code. Bound total
  messages, pending requests, per-message bytes, DOM nodes/depth, output text,
  stderr retention and wall-clock time. Unexpected events/responses fail closed.
- Request only bounded text/evidence first. Screenshots, interactions, authenticated
  sites, general browsing and scripted automation are not this first execution lane.
- Return results only after ResourceOwner confirms DNS, container, pipe, local CLI
  child and reader tasks are stopped/reaped. Keep unknown cleanup fenced; no TTL
  clearing or stale-PID shortcut. Do not remove the approved reusable base image.
- Prove timeout/cancellation during create, attach, fetch, document transfer, output
  read and cleanup. Test lost acknowledgements, child death, concurrent close,
  output/resource floods, orphan fences and a second process denied admission.
- Promote the pipe diagnostic into repeatable controlled integration tests before
  introducing task/worker/capability registration. Keep optional host container
  tests explicitly opt-in; automatic CI remains offline and deterministic.

## Prior proof scope and remaining distinctions

The native C fixture directly observes kernel filter/capability/namespace and
cgroup state, not document completion or renderer root filesystem. DOM completion
was verified separately through fixed-page dump and anonymous-pipe diagnostics.
Native chroot behavior was inferred from pinned browser source and the prior
explicit chroot-denial failure; do not claim direct root attestation.

Eight supplemental offline failure-injection cases exercised native diagnostic
orchestration cleanup, but are not committed CI regressions. Promote applicable
lifecycle failure coverage when implementing the production integration. Scanner
equality before image building is not immutable artifact attachment proof.
