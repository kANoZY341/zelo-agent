## Integrate the existing prerequisites

- One canonical AdmissionController/ResourceOwner lease must cover the whole job,
  before any DNS/helper/container/transport is spawned. Preserve crash fencing.
- Construct the ownership handle before creating external resources. Label every
  created container with the trusted lease identity; failed client acknowledgements
  cannot make the handle forget an existing resource.
- Use an operator-prepared, verified content-addressed image containing only the
  browser, libraries and fixed pipe/bootstrap executable. Execution must not build,
  pull, select arbitrary images or accept caller flags/env/mounts/profiles.
- Bind image identity, complete artifact roles/content, generated seccomp profile,
  fixed controller protocol, renderer policy and resource policy into one immutable
  execution contract. Scanner equality alone is not immutable attachment proof.
- Revalidate the exact image/profile/configuration immediately before start. Preserve
  nonroot, cap-drop ALL, no-new-privileges, read-only, network-none and cgroup limits.
- Keep the browser's anonymous pipe private to the trusted controller. No debug port,
  browser console access, raw CDP command API, arbitrary evaluation or user session.
- Start in an opaque blank context; disable page scripts before injecting evidence.
  No user-supplied navigation, redirects, headers, cookies, clipboard or downloads.

## Bounded work and truthful cleanup

- Fetch only through the existing approved-origin document broker, under the same
  lease and an absolute deadline. Keep HTML labelled untrusted evidence, never
  commands that can modify policy or instructions to the controller.
- The controller's protocol methods/parameters are fixed trusted code. Bound total
  messages, pending requests, per-message bytes, DOM nodes/depth, output text,
  stderr retention and wall-clock time. Unexpected events/responses fail closed.
- Request only bounded text/evidence first. Screenshots, interactions, authenticated
  sites, general browsing and scripted automation are not this first execution lane.
- Return results only after ResourceOwner confirms DNS, container, pipe, local CLI
  child and reader tasks are stopped/reaped. Keep unknown cleanup fenced; no TTL
  clearing or stale-PID shortcut. Do not remove the approved reusable base image.
- Prove timeout/cancellation during create, attach, fetch, document transfer, output
  read and cleanup. Test lost acknowledgements, child death, concurrent close,
  output/resource floods, orphan fences and a second process denied admission.
- Promote the pipe diagnostic into repeatable controlled integration tests before
  introducing task/worker/capability registration. Keep optional host container
  tests explicitly opt-in; automatic CI remains offline and deterministic.

## Implemented integration checkpoint — 3 October 2026

`DocumentRenderer.render(endpoint_id, path)` now combines the existing document
broker, owned DNS, resource owner and cross-process admission with a fixed private
pipe controller and local content-addressed Docker image. Core startup/registries,
existing API Worker, migrations, dependencies and UI remain unchanged.

The complete contract binds browser/bootstrap/loader artifact inventory, image ID,
controller source digest, renderer policy, original broker policy/origin bindings,
resource policy and exact generated seccomp profile. The full contract digest is
persisted in the admission marker before DNS/container work. Every job is one-shot;
results stay tentative until HTTP/DNS, daemon container, local CLI children and
reader tasks have confirmed cleanup. Unknown outcomes stay fenced.

Operator setup is separate from execution. `scripts/qualify_browser_renderer.py`
compiles the fixed bootstrap and builds a network-disabled scratch image only with
explicit opt-in. It exports an UNSTARTED container and verifies all 339 expected
payload files against their actual bytes/modes without extracting a tar. The exact
Docker-generated empty metadata placeholders and `etc/mtab -> /proc/mounts` alias
are recognized explicitly; payload symlinks/devices/unexpected files are denied.
This closes the bundle-scan-before-build gap for the inspected immutable image ID,
not hostile administrator mutation or a signing/provenance claim. Runtime never
builds, pulls, chooses image tags or deletes the reusable prepared image.

The controller accepts only its fixed protocol, creates a fresh about:blank context,
disables scripts, blocks downloads/service-worker/network access, and supplies
untrusted evidence as document data. Events are bounded and identity checked.
Unexpected frames/navigation/resource floods fail closed. Extracted DOM text is
not a claim about CSS visibility. Bounds: 512 KiB per protocol message, 2 MiB total,
24 commands, 32 events, depth 16, 4096 nodes and 64 KiB UTF-8 text.

Actual host testing found two protocol notifications absent from the initial doubles:
requested `Target.attachedToTarget` and `Page.documentOpened`. Both are now bound
to the exact requested context/session/blank frame; they grant no extra navigation.
It also found Chromium's 10,000 UTF-16-unit text preview with an appended ellipsis.
Such previews are now conservatively marked incomplete; a short literal ellipsis
is not. Multiple full text nodes still exercise the separate 64 KiB output bound.
No new evaluation command or unbounded DOM fetch was introduced to bypass the cap.

Chromium primary-source implementation consulted for preview semantics:
https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/core/inspector/inspector_dom_agent.cc
No upstream source was copied into Zelo for this behavior.
