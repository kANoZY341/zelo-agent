# REA: durable operator-asserted target selection and revocation

This Core-only increment follows the separately qualified **offline** target
admission and target preflight. It stores only an operator-selected assertion
of an inert review receipt. It neither verifies submitted filesystem bytes nor
implies that an arbitrary user target is approved for analyzer execution.

## API workflow and trust boundary

1. An operator first creates a private, sealed text-only snapshot with
   `python -m scripts.admit_rea_target --allow-offline-target-admission`.
2. Using the independent local `python -m scripts.preflight_rea_target
   --allow-offline-rea-preflight`, the operator obtains a compact SHA-256-bound
   offline review with **every authority flag false**.
3. The authenticated operator may explicitly record this non-authoritative
   metadata with `POST /integration-candidates/rea/operator-targets`:

```json
{
  "confirm_inert_selection": true,
  "review": {
    "schema_version": "zelo-rea-target-preflight-v1",
    "snapshot_id": "target-<32 lowercase hex>",
    "receipt_sha256": "<64 lowercase hex>",
    "content_sha256": "<64 lowercase hex>",
    "file_count": 2,
    "total_bytes": 42,
    "source_commit": "6fee42689ae6e95a0182e0d4d0f55644e73e72be",
    "source_manifest_sha256": "6f593ce98506d319cce71acbc975b0c150360d371845f1634966c5dc254a19b9",
    "tool_catalog_sha256": "82fb67571758c177d1eecac72efac152772cccc753442a77ef9418edc69be6a0",
    "tool_name": "analyze_javascript_application",
    "tool_qualification": "fixed_fixture_only_not_target_qualified",
    "manual_operator_opt_in": true,
    "review_fingerprint": "<64 lowercase hex produced by the local CLI>",
    "execution_enabled": false,
    "core_approval": false,
    "runtime_qualified": false,
    "worker_registered": false,
    "tool_grants": []
  }
}
```

`GET /integration-candidates/rea/operator-targets/{snapshot_id}` views one
historical selection. `POST .../{snapshot_id}/revoke` appends a terminal
revocation. All routes require Core's existing bearer-authenticated operator
principal. Matching retries are idempotent; conflicting second assertions for
the same snapshot ID are refused. A revoked ID can never be selected again,
including with a different content digest or review fingerprint.

Core validates the exact frozen contract, canonical review fingerprint and
pinned source/tool identities, but **does not trust these fields as proof of
actual target files**. A malicious or mistaken holder of the operator token
could submit a synthetic hash-coherent review. The resulting record is
`origin=operator_asserted_unverified` and `target_verified_by_core=false`.
The operator should verify the real snapshot locally; a future runtime must
validate its contents again under separately approved authority. The review
hash is not a signature, capability token, execution lease or authorization.

## Persistence and revocation guarantees

Migration `0038_rea_target_operator_selection` introduces one append-only
selection table and one append-only revocation table. SQLite constraints pin
structural digest/ID limits and permanently false execution/Worker/approval
flags. `WITHOUT ROWID` and insert/update/delete triggers prevent mutation and
replace/upsert resurrection. Service writes are serialized inside Core's
existing `BEGIN IMMEDIATE` transaction; concurrent identical submissions
return the same record, while conflicting submissions fail closed. Core
revalidates stored record integrity when read.

No target paths, relative filenames, source contents, credentials, Docker
profiles, execution instructions or Tool grants are persisted. An operator
selection is a reversible *intent* until revoked, not an execution approval.
Revocation is permanent for that selected snapshot identity. It neither
launches nor cancels any analyzer because no analyzer consumption path exists.

## Next separate milestones

This increment makes **no** changes to `WorkerAuthority`, Tasks, approval
schemas, runtime claim logic, Active AgentInstance permissions, Mind, network,
MCP or Docker. A separately reviewed operation must establish a trusted
source-built runtime and secure user-target consumer; source and snapshot
identity at claim time; Core-owned approval, revocation checks, an exclusive
bounded lease; no-network, read-only resource limits; bounded untrusted Evidence
and proven teardown. Never turn `currently_selected` into automatic execution
permission. UI PR #61 and four exhausted Media-reader attempts remain untouched.

## Local deployment gate

This increment adds migration 0038 and does **not** auto-migrate an existing
Core database. Before starting the upgraded Core against real retained data,
back up the local SQLite database, stop its owning Core runner, apply the normal
trusted Alembic `upgrade head` process under the configured runtime directory,
then verify `PRAGMA foreign_key_check` and `Database.check_schema()`. A Core
startup that sees a stale schema must refuse; it must not silently create the
selection tables or discard existing account, Agent, Task or conversation data.
Run upgrades only against the intended configured database, not a developer
worktree copy. Tests independently cover upgrade from prior revision 0037 and
retention of the preexisting WhatsApp account-selection record.
