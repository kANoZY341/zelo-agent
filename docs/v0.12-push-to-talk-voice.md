# v0.12 Push-to-Talk Voice

Status: active implementation slice.

## Purpose

Add local push-to-talk speech I/O to the existing Zelo Workspace without creating
another conversation path, agent, authority system, memory system, or execution
boundary.

Canonical flow:

```text
browser microphone
  -> Workspace /api/voice/transcribe
  -> localhost speech adapter
  -> transcript
  -> SAME existing conversation turn endpoint
  -> Zelo Mind / Core contracts remain unchanged
  -> assistant text
  -> Workspace /api/voice/synthesize
  -> localhost speech adapter
  -> browser audio playback
```

Voice is an I/O adapter only.

## Initial replaceable providers

Speech-to-text:

- `faster-whisper==1.2.1`
- default model: multilingual `small`
- default device: CPU
- default compute type: `int8`

Text-to-speech:

- default trial provider: `chatterbox-tts==0.1.7`
- multilingual English/Arabic with optional operator-owned reference clip via
  `ZELO_TTS_REFERENCE_AUDIO`
- CPU-friendly fallback: `sherpa-onnx==1.13.8` using converted Piper/VITS
  bundles selected with `ZELO_TTS_PROVIDER=sherpa_vits`
- the Sherpa fallback selects separate English and Arabic model bundles through
  `ZELO_SHERPA_EN_MODEL_DIR` and `ZELO_SHERPA_AR_MODEL_DIR`

Provider choice is deliberately behind the local speech adapter. Install
`requirements-voice-chatterbox.txt` for Chatterbox or
`requirements-voice-sherpa.txt` for Sherpa/Piper. Both include the common
`requirements-voice.txt` STT layer, but neither TTS provider installs the other.
Changing Zelo's voice or TTS runtime must not require changes to Mind, Core,
conversations, tasks, approvals, or the Workspace conversation contract.

## Security and authority

- speech service binds to `127.0.0.1` only;
- browser never receives `ZELO_VOICE_TOKEN`;
- Workspace server is the only browser-facing speech proxy;
- audio/text conversion cannot create tasks, approvals, schedules, projects,
  campaigns, memory, or tool calls;
- voice-originated text is submitted through the same idempotent turn endpoint
  as typed text;
- recorded audio is processed transiently and is not persisted by this slice.

## Limits

- raw captured audio: 12 MiB maximum per utterance;
- synthesis text: 4,000 characters maximum;
- English and Arabic TTS only in the first provider;
- Chatterbox generation selects one language per synthesis call. Mixed
  Arabic/English code-switching may need segmentation in a later refinement;
- Chatterbox 0.1.7 has a known upstream Arabic tokenizer issue around some
  word-initial hamza/alef forms, so it is a trial voice rather than a permanent
  architectural dependency; Sherpa/Piper is available as a local fallback;
- first model load may be slow because models are lazy-loaded locally;
- TTS runs in one persistent local worker process. The adapter uses a 110-second
  default generation deadline (configurable with `ZELO_TTS_DEADLINE_SECONDS`);
  browser/proxy cancellation or deadline expiry terminates that worker, and the
  next request starts a clean worker rather than leaving a stale model call
  holding CPU or the provider lock.

## Swap rule

The user may change the voice later. Do not couple UI or conversation logic to
Chatterbox-specific controls. Chatterbox and Sherpa/Piper already share the same synthesizer contract.
Future Kokoro or another provider should fit behind the same speech adapter.
