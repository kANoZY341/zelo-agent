# v0.15 Media immutable file-image qualification

After publisher PR#76, implement the smallest immutable-image prerequisite without
installing/importing/loading Pillow or decoding images. The existing strict wheel
inspector, normalization manifest and Linux sealing primitives are the reusable
sources. Astra Medium reviewed this design statically at publisher head edb8489;
no proof of a new image, transfer semantics or ownership is implied yet.

## Bytes and immutable identity

One public managed factory accepts exactly bytes and calls inspect_pillow_wheel
before allocating descriptors. No caller paths/inventories/hash/budget/mount/publisher
receipt selectors. Private fixture seams may use synthetic inspected bytes and
syscall failures. Construct from the same immutable inspected archive bytes, never
from mutable prepared paths. Preserve all files/notices and complete normalization
through media_preparation._expected and unchanged ArtifactFile/ArtifactManifest.

Fixed actual closure:6,940,830 archive bytes,140 files,six normalized directories
including root,19,667,368 expanded bytes. Expected normalized manifest digest:
47adde6932ce7c0c40cf7f781fe142057465771bc2895b00e80f9fdc411a5dc7.
Retain inspector ceilings:8MiB archive,16MiB/file,64MiB expanded,512 entries/depth8.
Public fixed image additionally requires the exact observed closure. Image identity
binds filename/archiveSHA/inventory/wheel-policy/full normalized manifest/new image
policy; descriptor numbers, offsets and inode observations are private live-owner
state. Disable direct successful identity/owner/receipt construction.

## Sealing and lifecycle

Stream each inspected member with chunks<=65,536 and running exact length/hash,
CRC/EOF and aggregate limits. Register every memfd immediately with its owner;
MFD_CLOEXEC|MFD_ALLOW_SEALING. Loop on partialwrites; reject zero/negative/noninteger/
excess counts. Empty data files remain valid in private fixtures and are sealed with
empty SHA/EOF. Data modes0400, fixed26 native files0500, all directories0500.
Require F_SEAL_WRITE|GROW|SHRINK|SEAL; independently re-read/hash exact size, mode,
regular type and all seals before exposing a complete managed image. Seals freeze
content/length, not chmod metadata, shared offsets or execution permission.

One owner transitions constructing -> ready -> consuming -> ready or failed ->
closed. No concurrent consumers, public FD export or reuse after terminal failure.
Reverify/rewind all transfer FDs before each sequential consumption; dup shares
underlying offsets. Hold descriptors through pending process creation, guest work,
I/O/group cleanup and reap. Reuse qualified OwnedProcess/run_process and cleanup
observation; cancellation settles outstanding work before image teardown. Unknown
cleanup prohibits another attempt. Attempt all closes even after a failure; never
blindly retry a Linux close on a possibly reused FD. Close failure prevents receipt.
Stable image identity is distinct from a post-cleanup guest-copy proof receipt.

## Fixed native proof and resources

Use explicit --perms plus --file into one dedicated package namespace, creating
all normalized directories and applying0500, then read-only remount before trusted
scanner startup. No anonymous memfd pathname bind or mutable-path fallback. Preserve
existing Python sandbox policy and production helpers; derive a distinct versioned
image profile. Trusted fixed bootstrap under -I -S -B with only stdlib/trusted scanner
source on sys.path; package root is excluded. Independently enumerate/hash every
file and directory and compare full manifest, not just an echoed expected digest.
Validate the bounded report strictly on the host. Repeat transfers to expose offset
errors. Guest mutation probes cover writes/truncate/chmod/create/delete/rename and
directories with unchanged complete manifests around them. No package imports.

One live image/consumer;256-total-FD supervisor/setup ceiling with explicit existing
FD count and reserved overhead, and64-FD guest scanner ceiling after transfer closes.
Do not raise shared limits. Refuse insufficient RLIMIT_NOFILE or descriptor capacity.
The optional private launcher may lower only its own limits, inherited during
Bubblewrap setup, without changing the shared process/system configuration. Fixed
scanner proposal:CPU10s/AS512MiB/stdout64KiB/stderr16KiB/native deadline30s/no cores or
regular-file writes; setup caps must precede transfers and be separately recorded.
Native geometry and limits remain proof-pending until qualification.

Actual sealed pages plus guest copies hold39,334,736 content bytes before page
rounding and kernel metadata. Generic expanded ceilings permit128MiB for both
copies. Archive/BytesIO copies, decompression buffers/interpreter memory/descriptors/
kernel/tmpfs costs are additional. RLIMIT_AS does not bound total host/tmpfs charges.
Numeric bounds do not guarantee syscall/allocation/swap latency or hard end-to-end
memory/I/O enforcement. Trusted local host/operator assumptions remain explicit.
At most four retained complete proof attempts; no overwrites or evidence deletion.

## Acceptance

Meaningful offline fixtures: pin rejection before allocation; malformed/oversized
streams; empty/partial/zero writes; creation/chmod/seal/read/hash failures; missing
seals; descriptor exhaustion/partial construction/every close position; stale handles,
reuse/concurrency and cancellation ownership. Actual fixed-wheel proof must cover
complete manifest/repeat transfer, seal write/grow/shrink/shared writable mmap
rejection, read-only file/directory mutation, no package import/ambient credentials/
host-data/external network, setup/output/deadline/repeated cancellation and confirmed
all descriptor/process cleanup. Review fixed launcher/profile before native proof,
then exact final static source/evidence review, fullCI and standalone supplements.

Claim only that the closed wheel's complete normalized file image was sealed and
reproduced unchanged in the qualified read-only guest namespace. Publisher attribution
remains separate conditional historical evidence; prepared-tree comparison remains
separate. No decoder correctness, ABI/runtime safety, complete security/license audit,
current trust freshness, Core selection/authority or production activation follows.


## Implemented checkpoint, native proof pending

The managed bytes-only owner uses per-file sealed memfds, complete independent
hash verification and the existing normalized expected manifest. Permission/offset
mutability is explicit. Registration failure retains the unregistered FD for cleanup;
all close positions are tested. Active consumption or unknown native cleanup retains
descriptors and blocks a new owner; a trusted settlement continuation may close a
failed owner but cannot make it reusable. No production helper is modified.

The optional scripts/qualify_media_image.py command accepts only the exact wheel
filename in an owned prior runtime/media-wheel-qualification/wheel-proof-* attempt,
reads bounded pinned bytes, and lowers only its own inherited setup limits to
NOFILE256/CPU30s/AS512MiB/FSIZE16MiB/CORE0 before allocation or Bubblewrap transfer.
The scanner lowers its own limits further. The qualified process helper and
publisher launcher's ownership/readiness primitives are reused unchanged.

Mount only five fixed trusted scanner modules from the frozen qualification source
closure read-only, with source hashes compared before/after each operation under
trusted source ancestors/no concurrent host mutator assumptions. Image root stays
off sys.path; package absence uses top-level find_spec, never an attempted package
import. Directory creation starts0700, file transfers use explicit normalized modes,
then every directory is chmod0500 before the existing read-only remount sequence.
Complete before/after manifests and canonical hashes are validated; boolean/integer
aliases and incomplete probe results cannot pass.

One retained proof attempt runs13 sequential native operations: complete copy twice;
all nine read-only file/directory mutations; network; host sentinel; import absence;
memory; output; CPU; live-ready cancellation; deadline; missing-mount setup refusal;
and repeated live-ready cancellation. Both repeated cancellation requests must be
delivered and operation settlement precedes owner release. Each host seal control
checks all files for write/grow/shrink/shared writable-mmap rejection as applicable.
The full acceptance receipt is written only after image/consumer/channel/source
cleanup. A failure retains its bounded attempt and returns no accepted receipt.
Actual closed-wheel transfer/mutation/resource/ownership execution remains pending
static source/launcher review;113 synthetic image/launcher cases pass.
