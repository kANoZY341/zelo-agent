# v0.15 — Read-only GitHub merge-result reconciliation

**Stage:** isolated local candidate, not a publication executor.
**Release state:** HOLD; governed by issue #166.

The separate claim, immutable operator decision and no-send fence bind one
approved proposal, reviewed PR number/repository/base/head SHA and the exact
required-CI/Skill blob digest. This addition can only **observe** the eventual
status of that historical candidate through GitHub GET. It does not start,
repeat or grant a GitHub write; it does not authorize loading or promoting
a learned skill.

## Outcomes and immutable source of truth

`SkillPublicationReconciliationService.reconcile(claim_id, merge_request,
OperatorPrincipal)` requires a preexisting immutable
`SkillPublicationDispatchFence` with `phase=reserved_no_send`,
`network_dispatch_started=false` and `runtime_authority=false`. It
revalidates the exact retained request digest, claim/PR/head/base identity
and literal squash-only intent. It independently rechecks the root-owned
configured GitHub CLI and credential directory against the frozen publisher.
An unknown claim, changed provider, changed message, source repository or
operator identity refuses **before any network access**.

It then GETs the exact GitHub PR and returns one bounded observed state:

- `open_unmerged`: still open with the exact approved head/base/branch,
  draft=false and merged=false. **Not** a retry or future dispatch ticket.
- `closed_unmerged`: terminal closure without a merge, historical only.
- `merged_single_parent_content_observed`: GitHub reports merged/closed,
  the PR source identity still matches, the immutable commit has exactly
  one parent equal to the reviewed base SHA, and its Git tree contains the
  exact reviewed **regular `100644`** file with the approved Git blob OID.
  **This does not establish squash versus a one-commit rebase.**

An ordinary two-parent Git merge, base advancement, changed PR source,
arbitrary commit, swapped blob or symlink is rejected. A one-commit rebase
or fast-forward can share the same topology as a squash. The evidence
therefore records `remote_merge_method_unproven=true` and never claims
the approved squash method was executed. For an already closed
PR, the mutable `base.sha` field is not sufficient evidence of the original
base: the verified immutable merge commit parent is authoritative.

## Negative authority boundary

Every result has the literal flags:

- `source_fence_was_no_send=true`
- `remote_actor_identity_unproven=true`
- `remote_merge_method_unproven=true`
- `cannot_retry_or_dispatch_github_merge=true`
- `no_skill_promotion_or_runtime_authority=true`

Because this stage **never sent** any GitHub merge request, even a confirmed
exact squash would be a remote action by some other, unproven actor. It may
not be used as automatic operator approval, a promoted-link receipt, a new
Skill Registry version or evidence that Zelo itself initiated the merge.

Read-only reconciliation remains available to the authenticated operator
after the associated Agent is paused or revoked, because historical incident
review must not require live execution privileges.

Scripted-provider regressions cover open/closed/merged states, wrong
one/two-parent commits, exact artifact mode/OID, changed PR identifiers,
forged request, unknown fence, revoked Agent and absence of every external
PUT/POST. No real GitHub merger is invoked and no model Tool is registered.

## Still missing before v0.15 publication can become operational

A **different, separately reviewed** publication-specific runner must bind a
fresh authenticated operator dispatch decision and trustworthy current
Task/Worker identity to a durable **send-started** fence before the first
external merge request. Any timeout, crash, ambiguous response or provider
error must remain terminally blocked pending this read-only reconciliation,
with no blind second send. Only a verified persisted action/merge receipt
and all current Core policy checks may feed governed promotion-link state.
The existing generic protected learned-skill merge denial remains unchanged.

Other release gates—Space, Worker qualification, third-party source/license
disposition, Media native-reader scope, exact-head CI and final independent
release audit—remain open. Four native Media proof attempts were consumed;
no fifth attempt is authorized. UI PR #61 remains parked.
