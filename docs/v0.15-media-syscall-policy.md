# Zelo Core v0.15 — Media syscall candidate policy

Active scope after immutable image PR #77 merged at `3381ada6`: a qualification-only,
immutable candidate policy for trusted standard-library probes. No filter compiler,
ctypes/library load, process probe, Pillow import, native member load, decoder,
installation, cgroup change, runtime receipt or Core binding belongs in this slice.
Policy bytes describe intended restrictions; they do not enforce them.

The Astra Medium design review recommends pure policy first and identifies concrete
installer and aggregate-resource prerequisites. This keeps the original PNG adapter
RLIMIT/cgroup/seccomp gate ahead of decoder execution. A smaller no-Pillow guard
experiment may follow separately; it cannot authorize a decoder by implication.

Reuse the existing unmodified Apache-2.0 Moby vendor profile and LICENSE/NOTICE:

profile SHA256 6416b47770785a41ac59073cdc77d9fe98517df2799dc83ef207e622de3053f6.
Authenticate bounded exact vendor bytes before parsing. Derive eligible syscall
names only from unconditional ALLOW rules without arguments, includes or excludes.
A mature subset establishes provenance, not suitability. Do not call Browser's
profile builder or inherit its appended clone, unshare, chroot rules, capability
conditions, compatibility architectures or broad allowlist. Preserve its implementation.

The Media candidate has a fixed explicit syscall tuple and a rationale for every
name. Names must be eligible under the unchanged authenticated upstream source.
The exact tuple is independently selected for trusted read/hash/report semantics;
it is not inferred from arbitrary workload failures. Permit no caller-selected
syscall, action, ABI, compiler, path, loader, FD, environment or policy override.
A later decoder may require a separately reviewed candidate revision.

## Candidate language and identity

Expose a pure factory, frozen candidate-specific type and exact validator in
qualification/media_syscall_policy.py. Canonical ASCII JSON binds fixed versioned
schema, purpose, bootstrap order, native x86-64 intention, default EPERM intention,
unsupported-ABI kill intention including x32, fixed syscall tuple/rationales and
vendor commit/digest/license. No OCI JSON interpreter or foreign profile acceptance.
No enforcement/runtime-authority/decoder-ready field can be set true by a caller.
Retained policy bytes and their SHA256 are identity only, instruction trust none.

Validation requires strict immutable bytes within a fixed small limit, exact
lowercase SHA256, computed hash equality, and exact bytes from fresh current fixed
policy generation. Rehashing changed, reordered, duplicated, permissive or expanded
JSON cannot approve it. No mutable cache, broad parser/coercion or caller source
path. Authenticate the bounded vendor file on every generation and validation;
source ancestors and local Python process are trusted operator prerequisites.
Candidate construction may validate exact bytes directly; it grants no successful
native enforcement claim. Do not introduce successful result constructors.

Allowlist review must individually decide FD operations, mmap/mprotect executable
memory, ioctl/prctl/prlimit64 and resource-query behavior. The pure candidate represents exact masked-equality restrictions for read-only
openat access/creation flags and no new executable mmap/mprotect mappings. These are
intentions until a later compiler and enforcement are separately qualified. Other
allowed syscall arguments remain unrestricted; the artifact grants no suitability
or argument-safety assurance beyond its declared fixed candidate language.
Do not claim suitability merely because a syscall appears upstream. For the first
stdlib-only candidate, prefer omitting broad ioctl, prctl, seccomp and prlimit64;
possible compatibility failures belong to later bounded installer qualification.
No fork/clone/clone3/vfork, execve/execveat, setsid/setpgid, socket family, namespace,
mount/chroot, ptrace/process_vm, bpf/perf, io_uring, keyring or privilege-change entry.

## Installer contract, not implementation

Before any native installer, close all of these separately reviewed prerequisites:

- Exact libseccomp artifact, provenance, digest, ELF/SONAME, API/symbol requirements,
  dependencies and notices; Python, loader, libc, _ctypes and libffi platform closure.
  Verified bytes must be tied to actual loaded bytes, including symlinks, search,
  dependencies and preloaded libraries. Availability or a version string is insufficient.
- Native library/loader execution before filtering is an explicit trusted bootstrap
  stage. No copied package may enter the import path before filter installation.
- Exact fixed-width ABI signatures, error conventions, context ownership and release;
  prefer fixed-signature APIs. Every syscall name must resolve on the chosen ABI.
- Native x86-64 only, explicit unsupported-ABI whole-process kill and x32 encoding
  treatment. A ordinary architecture check alone does not close x32.
- Explicit single-threaded bootstrap or independently reviewed synchronization;
  verify task closure. Establish limits and descriptor closure before installation.
- Bind candidate bytes, compiler/installer/library identity and compiled filter
  evidence. Actual Seccomp=2/NNP=1/filter-count growth alone does not identify policy.
- Precise controls with valid arguments and safe sensitivity baselines. EPERM alone
  can come from namespaces, capabilities, NPROC or bad arguments. Removed-filter
  controls require independent containment and owned cleanup.
- Reuse OwnedProcess and the image owner unchanged. Hold image/support descriptors
  through pending creation, installation failure, channel draining, repeated cancel
  and settlement. Unknown cleanup fences resources and produces no accepted receipt.
  Work deadline and eventual cleanup settlement are distinct; no hard cleanup promise.

## Aggregate resources before decoder execution

The original PNG adapter gate still requires RLIMIT/cgroup/seccomp qualification.
Resolve aggregate memory/swap, PID/task and CPU limits, admission and placement
before governed allocation, membership/escape constraints, cleanup and empty-state
proof, and retained ownership when uncertain. Include sealed host pages, guest
copies, setup and supervisor costs or explicitly identify which remain outside the
chosen enforcement boundary. A later move does not prove earlier accounting.
CPU quota is not a total-time budget. Existing Browser documentation records no
writable user cgroup root; do not assume delegation or change host/daemon policy.
A dedicated immutable OCI/Python bundle requires its own platform/package identity
and delivery/accounting contract. Browser approval does not transfer to it.

## Offline qualification

Adversarial fixtures must establish strict types, bounded reads and authenticated
source-before-parse, exact canonical identity, immutable fields, stale/forged/changed
policy refusal even with a matching new digest, missing/added/reordered/duplicate
syscalls, changed default/ABI/bootstrap/provenance and forbidden true flags. Test
vendor drift, oversize/missing source, conditional-rule eligibility and absence of
mutable shared state. A fresh interpreter audit should verify no optional imports,
process/network/library/filter/package execution or environment-derived configuration.
These are candidate-policy tests only. Astra Medium source review, focused checks,
matching-head full CI and existing standalone supplements precede merge.
