## Implemented opt-in proof

`scripts.qualify_shell_operator` uses unmodified default application/runtime/owner
assembly with a rejecting counted model provider. Six real cases cover disabled
startup, enabled unknown-fence refusal, auth/native-override rejection with no task,
two exact persisted/audited native results with idempotency/readmission, and full
Runner/runtime shutdown. The Core DB action hash is recomputed from its canonical
selection; audit requires exactly one of every execution event and binds terminal
task/attempt/policy/trust. Source and runtime identity remain fixed Core authority.

The CLI requires explicit native opt-in and assertion-enabled Python. It has no
arbitrary script/file/path/policy input and emits bounded private sanitized JSON.
Reports record exact Git revision/clean state, policy/operator identity, model
request counters and cleanup confirmation. Real acceptance requires clean reviewed
head and passed independent/CI/native gates; an in-progress smoke report is not
production acceptance. Offline tests use guarded fakes only for control coverage,
and cannot launch optional Shell guests.

## Discovered factory import issue

The initial ambient CLI failed before diagnostic settings because importing
`app.main` constructed its module-level default app and parsed ordinary environment/
`.env` settings. The reusable, unchanged factory is moved to `app/application.py`.
The normal `app.main:app` ASGI entry still creates default settings normally, and
`app.main.create_app` remains compatible. The proof imports the side-effect-free
factory, with fresh-process tests that forbid settings source access. This extraction
is explicitly part of the review/compatibility gates; it changes no task/native
lifecycle or authority semantics. Audit validation also binds routing/selection and
revalidated operator/policy identities plus all execution attempt IDs. Shutdown
requires Runner termination and successful fresh private DB ownership acquisition.
