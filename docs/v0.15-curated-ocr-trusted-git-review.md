# Open Code Review: trusted Git evidence scope (follow-up to PR #130)

## Reason for this slice

The existing non-authoritative `bind_ocr_review()` adapter accepts a
`Mapping[str, frozenset[int]]` provided by **trusted Core**, never by a model.
This slice provides a Core-owned implementation of that prerequisite, so reviewer
findings can be strictly anchored to the exact added lines of reviewed Git
commits. No external Open Code Review runtime or SDK runs.

This is a **manual/offline evidence adapter** and does not register a Worker,
select a reviewer, change the independent-review pipeline, post GitHub comments,
promote a Skill, or authorize tasks, approvals, merges or shell access. It is
not a production code-review service.

## Input trust boundary

`verified_git_review_scope(trusted_repo, base_sha, head_sha)` accepts only a
Core-selected local Git root (not an Agent/model-supplied path), exact full
commit SHA identities and a checkout with HEAD equal to `head_sha`.
**Working-tree content is not read or certified**: untracked, staged and
modified files cannot influence the output. In particular, no `git status`
or worktree-to-index diff is allowed because repository-configured clean
filters can execute arbitrary commands. Its subprocesses are argument arrays,
never shells; run a fixed Git binary without network, user/global system config,
textconv, external diffs, or filesystem monitor commands. Git attributes
are read from the verified `head_sha` tree via `GIT_ATTR_SOURCE`; Git
versions older than 2.43 are rejected. Named or forced `diff` attributes are
refused because custom drivers can depend on mutable configuration. Nothing
is read from mutable working-tree `.gitattributes`.
The local `core.attributesFile` is overridden to `/dev/null`,
`GIT_ATTR_NOSYSTEM=1` disables system attributes, global/system Git
configuration and attribute paths are isolated, and a mutable Git
`info/attributes` file causes a **refusal** rather than unreviewed influence.
Mutable `diff.orderFile` is overridden with `-O/dev/null` and fixed
Git configuration; diff algorithm, full index hashes, fixed a/b headers,
relative prefixes, hunk shape and output markers are pinned.
Reading has a time and size budget. The exact HEAD is checked **again** after
all file patches are gathered; any future live worktree review would require
a separate trusted snapshot boundary, not a relaxation of this one.

Git compares those immutable revisions and supplies a NUL-delimited list of
added, modified, type-changed and deleted paths with renames disabled.
Each path must be a simple safe relative path, and existing base/head tree
entries must have regular-file modes (`100644`/`100755`), not symlinks
or gitlinks. Submodule changes are enumerated even when local Git configuration
requests ignoring them. Binary, special, untrusted, oversized and noncanonical
files fail closed. Any deleted file or deletion-only hunk refuses the entire
review scope, even if mixed with additions: its finding cannot be anchored
to a new line.

For each regular path, a **zero-context, zero inter-hunk-context** patch
supplies the evidence lines. Parsing is LF-delimited and checks old/new hunk
counters, counting only actual added/new lines rather than trusting entire
hunk spans as changed. Embedded carriage returns, code resembling patch
headers, and repository-configured inter-hunk context cannot mint line
permissions. The deterministic patch bundle is SHA256-bound and carries
`base_sha`, `head_sha`, approved per-path new-line sets and explicit
no-authority flags.

`bind_ocr_review_from_git(raw_json, trusted_repo, base_sha, head_sha)`
**rederives** the scope from Git internally before applying the existing
bounded Open Code Review schema and `ReviewerReport` adapter. It does not
accept a caller-fabricated changed-line map or pretend a review is approved.

## Representative offline usage

```python
from pathlib import Path
from app.community_review_git_scope import bind_ocr_review_from_git

# trusted_repo, base_sha, head_sha must come from Core's verified review
# context, NOT user/model output. Only committed objects are reviewed.
report, evidence, scope = bind_ocr_review_from_git(
    reviewer_json_bytes,
    Path("/trusted/core-selected/review-snapshot"),
    base_sha=verified_base_sha,
    head_sha=verified_head_sha,
)
# Review this evidence under the EXISTING independent-review/approval process.
# Never treat this function as CI success, approval or permission.
```

## Qualification before activation

1. Exercise adversarial Git fixture tests including CR+hunk injection,
   `diff.interHunkContext`, unexpected binary/symlink and type changes,
   executable repository clean filters, unsafe Git pathspecs, removed lines,
   size limits, uncommitted attribute overrides, mutable `info/attributes`
   refusal, uncommitted diff-order overrides, dirty worktree irrelevance
   and stale HEAD.
2. Independent reviewer inspects exact patch plus repository security boundary.
3. Exact-head Ruff/pytest/full CI green before merge and post-merge main CI.
4. A **separate** promotion decision is needed before wiring an actual Coding
   Specialist/reviewer Worker; retain independent reviewer selection,
   sandbox/identity snapshots, approval and runtime revalidation.
5. UI PR #61, Media four consumed native-reader attempts, and REA offline
   authority restrictions remain unchanged.
