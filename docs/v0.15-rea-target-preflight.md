# REA: offline target preflight (inert)

After target-admission PR #123, this separate manually invoked qualification
boundary checks a sealed text-only target snapshot **again**, binds the
independently retained receipt/content digest to the exact vendored REA 6.0.0
source and the 139-name catalog, and emits a deterministic inert review receipt.
No target analysis or model/Worker execution is authorized.

## Explicit local workflow

First use the already merged [target admission](v0.15-rea-target-admission.md)
CLI to seal a benign text-only target folder under the fixed private inbox.
Retain its `snapshot_id` and `receipt_sha256` separately from the sealed bytes.
Then run, from the trusted Zelo repository root:

```sh
.venv/bin/python -m scripts.preflight_rea_target \
  --allow-offline-rea-preflight \
  --snapshot-id target-<32-lowercase-hex> \
  --receipt-sha256 <64-lowercase-hex>
```

The flag must be explicit. Merely providing an identity or receipt does not
permit a review. No arbitrary host path, source folder, tool name, network
endpoint, credentials, container ID, script or permissions are accepted.
The selected snapshot is revalidated only inside the fixed, private,
operator-owned snapshot root. Wrong/missing/tampered receipts refuse with one
bounded, generic reason and no paths or file contents.

The local CLI runs with its invoking OS user's permissions. An opt-in flag is
**not** proof of operator identity and is not a Core approval. Do not expose
this CLI, its directories or its output as an Agent tool, endpoint or public
service. Zelo's live API has no preflight route, and the prior no-runtime-import
regression remains intact.

## Exactly what is checked

Each invocation verifies the full sealed target against the independently
retained receipt digest; revalidates all 2,082 pinned upstream source files,
notices and separately pinned optional engine identities; and checks the exact
139-name no-grant REA inventory. It binds these identities to the single
`analyze_javascript_application` tool, whose measured runtime qualification
applies **only** to the fixed benign two-file fixture — not to this target.

Output is a frozen, deterministic SHA-256 fingerprint over a compact summary:
target/receipt identity, aggregate content SHA256, file count/byte size,
upstream revision, source manifest hash, tool catalog hash, fixed tool name
and explicit **false** authority fields. Repeating the review is read-only and
deterministic. It persists no new approval, claim, grant, lease, artifact copy,
Mind turn or worker dispatch, and never starts Docker, npm, Node or REA.

The response states `execution_enabled=false`, `core_approval=false`,
`runtime_qualified=false`, `worker_registered=false`, `tool_grants=[]` and
`tool_qualification=fixed_fixture_only_not_target_qualified`.
The fingerprint is **not a signature**, **not a revocable capability**, and
**not authorization**; an OS-local attacker could compute it independently.

## Later security gates

Before a real user-selected target may be processed, implement and separately
review durable Core-owned operator selection; source/target/Agent/Space/Worker
identity binding, separate execution approval, revocation and lease checks;
consumption-time snapshot revalidation, no-network isolated analyzer execution,
verified owned-container cleanup and bounded untrusted Evidence handling.
A valid preflight alone must never trigger or approve REA analysis.
The UI PR #61 and all four refused Media native qualification attempts stay
unchanged.
