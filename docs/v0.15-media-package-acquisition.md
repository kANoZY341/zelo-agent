## Fixed HTTPS request and TLS context

Use HTTPSConnection, never HTTPConnection, urllib openers, proxies or tunneling.
One new connection and one GET per archive. Fixed request headers:
Host: archive.ubuntu.com
Accept-Encoding: identity
Connection: close
No body, authorization, cookies, client certificates, netrc, credentials, debug
logging, caller headers, environment-selected endpoint or application retry.

Construct SSLContext(PROTOCOL_TLS_CLIENT) directly. Explicit CERT_REQUIRED,
check_hostname=True, minimum TLSv1.2, ALPN ['http/1.1']; never call
create_default_context, whose inspected Python code reads SSLKEYLOGFILE.
Do not mutate or print the environment. Assert keylog_filename is None and never
set it. Direct SSLContext.__new__ delegates to the trusted native baseline without
the Python keylog environment branch; this is not a recursively proven OpenSSL
platform or a claim about every native initialization/configuration behavior.

Read only fixed /etc/ssl/certs/ca-certificates.crt through a held nofollow FD after
admission. Require resolved literal path, root UID/GID, 0644, regular, nlink 1,
positive <=256KiB and stable descriptor metadata. Decode the immutable bytes as
ASCII and pass cadata to load_verify_locations; do not use default CA discovery,
cafile/path reopening or SSL_CERT_FILE/SSL_CERT_DIR selection. Record observed CA
size/hash as baseline identity, not independent CA provenance or signing-key
freshness. Hold this descriptor with the output FDs until support release.
TLS hostname is the fixed archive host. No TLS verification bypass.

Use a narrow fixed connection factory seam instead of unrestricted address retry:
getaddrinfo for the literal host, port443, AF_INET, SOCK_STREAM, IPPROTO_TCP only;
require 1..16 returned records after the trusted resolver returns; select the first
record, validate its tuple, and attempt exactly one socket connect. No alternate
address or application retry. Record only a generic stage code on failure.
Resolver allocations/time are baseline operations bounded by process AS/CPU,
not a pre-allocation DNS count or hard DNS wall-clock guarantee. No DNS results
or network endpoints are caller-selectable. TLS still verifies the literal host.

## Bound framing without a custom HTTP parser

Reuse HTTPResponse parsing. A narrow response subclass delegates _read_status to
stdlib and immediately rejects any status other than 200 or version other than
HTTP/1.1. Thus repeated 100 Continue is rejected at its first status, rather than
looping through unbounded interim headers. No reimplementation of status grammar.

Wrap only the response's makefile object in a bounded I/O adapter before begin:
readline delegates to the original buffered stream with a maximum request of
min(caller_limit, 8193, remaining_header_bytes+1). Reject >8192-byte lines,
>65 total status/header readline calls, or >65536 cumulative status/header bytes
BEFORE returning an excessive line to the stdlib parser. Count the terminator.
The adapter checks the deadline around every delegated operation. It performs no
HTTP field parsing and uses no global monkeypatch. After begin, switch to body
mode; read1 delegates at most65536bytes and refuses a non-bytes/oversized result.
Provide only the needed flush/close/closed operations with explicit object ownership.
A wrapper close detaches its underlying stream reference before calling close,
so an exception does not cause an application retry of that reference.

Require no email parser defects. Validate returned header names as bounded ASCII
HTTP tokens, values <=8192 with no CR/LF/folding or control bytes. Reject duplicate
names case-insensitively, including Content-Length. Require exactly one canonical
Content-Length equal to the fixed signed size; reject any Transfer-Encoding and
any Content-Encoding except absent or exact identity. Require response.chunked is
False and response.length equals the signed size before consuming the body.
No header can choose a filename, URL, redirect, decoder, credential or operation.

Read exactly the framed Content-Length body in <=64KiB chunks, charging bytes
before every output write. Refuse early EOF, oversized returned chunks or digest
mismatch. At completion require the expected length and response framing exhausted.
HTTPResponse clamps read1 to Content-Length; neither an extra read nor EOF proves
absence of trailing wire bytes. Extra wire/buffer bytes are UNUSED, not inspected,
and the connection is never reused. Tests must model this real behavior.

## Ownership and failure transitions

Application bookkeeping retains the connection before connect/request/getresponse,
and retains a successfully constructed response as soon as its factory returns.
Response construction is through a fixed factory attached to this connection; it
can register the response before wrapping its makefile stream. Construction or
library exceptions can conceal internal closes; treat their settlement as unknown.

| Stage | Ownership and required behavior |
|---|---|
| DNS/raw connect | Factory retains the raw socket before configuration/connect. On error it has one object cleanup path, detaches its reference first, and never retries a raw FD number. Failure marks uncertainty if a close is hidden or errors. |
| TLS wrap | Inspected SSLSocket._create transfers the descriptor with detach and attempts its own close on failure. Keep the connection, do not recover or close a remembered numeric descriptor, and conservatively refuse cleanup certainty on a wrap exception. |
| Response construction/header failure | getresponse can close response and sometimes connection internally. Preserve reachable owner objects; an opaque library failure marks support cleanup unconfirmed. Do not re-run getresponse/request or restart cleanup after interruption. |
| Returned response | It owns its makefile reference. Persistent connections may also retain that response; will_close connections have already detached/reset their socket through internal close. Both cases are expected stdlib behavior. |
| Body completion | read1 can internally close fp at the declared length or early EOF. _close_conn clears fp before close; socket/makefile reference counting can defer the underlying socket close. No claim of exactly one public close-method call per object. |
| Normal application cleanup | One application cleanup path closes the retained response, then connection. Already-closed object calls rely on inspected pointer-clearing/idempotent behavior; no remembered FD integers are retried. On any close exception or interrupt, stop that path, retain objects, mark cleanup unconfirmed, and never restart it. |
| Body abort/unknown library settlement | Quarantine retained connection/response/raw-socket objects with state/lease until operator exit; no success receipt. Do not infer a universal fence or complete hidden close. |

A returned response must be fully consumed and application cleanup settled before
proceeding to the next archive. Known data validation refusal may clean up normally;
opaque library/close failure remains conservatively fenced. No callbacks or worker
threads are created. Standard native resolver/TLS baseline behavior is not newly
qualified process isolation. No raw socket FD is added to _State's integer list.

## Time, memory, disk and output contract

CLI limits before project imports: AS512MiB, CPU30s, FD64, FSIZE4MiB, CORE0.
Whole300s is COOPERATIVE, with checks around setup/header/each body chunk/proof/
cleanup and immediately before receipt emission. Socket10s is an operation/idle
limit, not an absolute job limit under slow delivery. DNS, TLS setup, buffered
readline/header work, filesystem I/O and cleanup have blind spots; no hard network
or filesystem wall-clock guarantee. If a hard job deadline is required, revise
architecture to a separately owned process before implementation, not a thread
that could outlive the lease. Do not claim the current proposal enforces it.

Header acceptance caps precede join/decode/email parsing, so accepted input is
<=64KiB plus one <=8193-byte refusing read and the stdlib buffer. Copies and bounded
headers are accounted separately from <=64KiB body chunks. Support reservation
64MiB includes TLS/CA/parser buffers, <=8MiB read-back copy peaks and <=2MiB report
serialization; interpreter baseline excluded, not measured cgroup containment.
Trusted native baseline allocation still falls under process AS512MiB/CPU30s.

Capacity-one admission before CA/source/attempt/network allocation, unchanged
runtime/media-elf-metadata-admission. New semantic scope:
runtime/media-package-acquisition/acquisition-proof-*; four retained attempts
across all revisions, including failures. No repair/reset, overwrite or retry.
Before creating an attempt, boundedly validate the existing scope's private
regular files/directories and aggregate retained caps; refuse malformed state.

Each attempt has <=16 entries and <=16MiB regular bytes: eight fixed exclusive
0600 archive files totaling8745084bytes (each<=4MiB), plus policy.json,
manifest.json and cases.json, each<=2MiB. Ledger11files/15036540bytes. Charge the
fixed archive reservation before file creation, each chunk before writes, and
JSON before persistence. Retain partial files in place; no duplicate temp copies.
A JSON-only _Store subledger can be reused unchanged, but is explicitly not the
archive ledger; combined retention is independently charged against16MiB.

Hold all output FDs. Incoming incremental SHA and bounded stable held-FD read-back
size/hash must match every fixed declaration before complete manifest/proof.
No archive framing parser, member listing, decompression, extraction, import,
installation or code execution. Generic bounded error stages only; never retain
raw headers, server reason strings, response error bodies or arbitrary trace text
as accepted evidence. Output lock/policy and validated fixed records bound JSON
before serialization. Pending cases precede single support release; stdout binds
its in-memory SHA after confirmed cleanup, with no post-release proof-file I/O.

Claim only all-eight archive_hash_verified against the accepted signed-index
chain. Member origin, platform, ABI, freshness, current signing-key validity and
runtime authority remain false. CA/TLS baseline is conditional, not recursive
platform provenance. No Core binding, enabled flags, OS changes or native decoder.

## Tests and gates

Use real stdlib HTTPResponse parsing over synthetic BytesIO/socket/makefile fakes
where useful, not a fake parser with different framing semantics. No real DNS,
TLS context, sockets, server or network in offline tests. Fake TLS factory must
prove direct context setup and absence of create_default_context/keylog/CA-path
fallback. Cover interim rejection, pre-parser header budgets, defects/duplicates/
folds, framed trailing-wire handling, short/size/hash refusal, one-address policy,
all-eight lock/aggregate, partial writes, read-back drift, quota and ownership.
Inject connect/wrap/getresponse/internal-close/read/cleanup failures and interrupts;
verify no application cleanup retry, no receipt and conservative unknown fencing.

Refined design clearance -> offline implementation -> FULL frozen source review
explicitly clearing at most ONE fixed eight-file batch -> clean preflight/that
attempt -> FULL actual review + matching CI + supplements -> normal merge.
Any refusal returns to design. No alternate endpoint, automatic retry or pin/
protocol widening. No package/member tool inspection or execution from this plan.

The CLI must catch ordinary failures and emit only a fixed bounded refusal code
with exit1, not a chained traceback containing peer-controlled status/header text.
Interrupts produce no receipt and no restarted cleanup. No raw diagnostic text is
promoted into accepted evidence or interpreted as instructions.
