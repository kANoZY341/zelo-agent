# REA manual profile: stable identity checks

## Observed failure and reproduced defect

Post-merge main run 37997783658, commit 6eab7b9, failed one test:
`test_exact_manual_profile_is_pinned_and_denies_all_core_access`.
The other 5,491 tests passed, with two skipped. The failure was
`rea_target_profile_changed` after reading the pinned manual profile.

The previous reader compared complete `os.stat_result` values from before
opening, after opening, and after reading. Those values include access time.
Linux can update access time when a file is read; access time alone does not
establish changed file bytes or a changed permission profile.

The CI log did not capture before/after metadata, so it cannot establish
which field differed in that particular run. Separate deterministic tests
reproduce a concrete matching defect: the original `_policy` function
rejects valid pinned bytes when only access time differs, both before and
after the read. These same tests pass with the correction.

## Narrow correction

Compare device, inode, mode, link count, owner, group, length, nanosecond
modification time and nanosecond metadata-change time. Ignore access time
only. Nanosecond fields retain precision that whole-stat tuple equality
can lose. The initial regular-file/size check, `O_NOFOLLOW`, bounded read,
expected SHA-256, exact JSON contract and descriptor cleanup remain intact.

Regression coverage uses real `os.stat_result` values retaining nanoseconds.
It accepts atime-only observations at both checks, rejects independent
changes in every protected field before/after read, checks descriptor closure,
rejects same-length tampering despite atime drift, rejects an actual file
replacement between stat and open, and exercises a cold read of an isolated
copied profile without depending on a particular filesystem atime policy.

No pinned policy bytes, expected digests, upstream sources, sandbox settings,
operator consent, Core grants or Media qualification budgets are changed.
These are isolated local tests, not a new native REA or Media qualification.
Full exact-head CI and post-merge main validation remain required.

## Reference semantics

- Python 3.12 `os.stat_result` documents access/modification/change times,
  nanosecond fields and sequence compatibility:
  https://docs.python.org/3.12/library/os.html#os.stat_result
- Linux `inode(7)` documents access-time updates by reads and their dependence
  on filesystem mount policy:
  https://man7.org/linux/man-pages/man7/inode.7.html
