# OpenDots-inspired Space grants — inert owner-intent foundation

This small Zelo-owned slice follows the imported OpenDots profile/computer
references without importing OpenDots' scheduler, autonomous runtime,
permission engine or separate worker registry.

The authenticated owner can inspect or record a **Space grant intent** for a
specific existing active AgentInstance only when its exact current, registered
AgentSpec explicitly declares the Space ID. The record binds project identity,
AgentInstance ID, AgentSpec version, registry fingerprint, scoped resource kind
and logical ID, requested metadata-only operations, SHA-256 integrity, a
maximum 60-minute TTL, and append-only revocation. SQLite duplicate-insert guards also block
`INSERT OR REPLACE` from silently replacing revoked or immutable records
when `recursive_triggers` is disabled. Each AgentInstance has at
most 16 unexpired, non-revoked intents and 256 lifetime history records.

For this pre-enforcement stage only `files`, `browser`, `terminal` and
`memory` logical resource types are modeled. Only `read` (and for files,
`list`) metadata intentions qualify; arbitrary paths, shell commands, writes,
execution, navigation, account access, tool invocation and takeover are
rejected. A declared computer resource must also be in the trusted AgentSpec.
These IDs **do not resolve to a host filesystem or browser endpoint**.
The owner-only endpoints are:

- `POST /agents/{id}/space-intents` — append immutable, short-lived intent
- `GET /agents/{id}/space-intents/{intent_id}` — revalidate spec, lifecycle,
  project, TTL and revocation each time
- `POST /agents/{id}/space-intents/{intent_id}/revoke` — irrevocable event

Every response reports `effective_resource_access=false`,
`worker_authority=false`, `tool_authority=false`,
`model_context_admission=false`. It does **not** create a Space, change
permissions, start an Agent, or authorize Worker's actual resource access.
Existing Computer and Worker gates retain sole authority.

Every pause, resume or retirement event after an intent is recorded
permanently invalidates that intent's review eligibility; resuming the same
version of AgentSpec never resurrects old consent. A new operator intent is
required after resumption. This is still metadata only, not enforcement.

## Still required before Space *permissions* are functional

1. Trusted Space and resource registry, operator grant activation workflow,
   and exact per-AgentInstance scope verification at dispatch, claim and use.
2. Actual path/URI canonicalization at resource-open time, symlink and hardlink
   containment, concurrent revocation and lease expiry checks.
3. Explicit enforcement for Computer browser/files/shell, Tools, task retries
   and delegation, and negative cross-Space test coverage.
4. Specialist profile reflecting instructions, memory, skills and effective
   permissions with denial reasons; governed skill learning without automatic
   promotion.
