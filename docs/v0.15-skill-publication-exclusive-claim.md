# v0.15 — Exclusive local claim for learned-skill publication

**Candidate status:** implementation/test slice, NOT a published or enabled skill.
**Scope:** one real, durable, operator-selected reservation of an exact accepted
`SkillPublicationIntent`, serialized across competing procedure/version
candidates. This is the first local claim stage toward release closeout issue
[#166](https://github.com/kANoZY341/zelo-agent/issues/166).

## Why this is necessary

Before this change, two independently accepted proposals for the same agent,
source Skill, procedure and version could each prepare an apparently valid
read-only publication intent. Local *post-merge* promotion-link exclusivity could
reject the loser but could not prevent an already merged competing GitHub PR.
The generic GitHub merge runtime correctly refuses protected learned-procedure
files until a true premerge exclusive authority path exists.

## Bounded implementation

`SkillPublicationClaimService.reserve(proposal_id, expected_intent_fingerprint,
OperatorPrincipal)` opens the existing SQLite `BEGIN IMMEDIATE` writer lock
**before** recomputing the accepted proposal, operator review, complete artifact,
current AgentInstance/spec/Skill registry and exact promoted predecessor through
the existing authoritative Core intent verifier. The caller's expected intent
fingerprint must exactly equal the reconstructed one; the service does not trust
or accept a constructed external `SkillPublicationIntent` as a grant.

Within the same transaction it inserts one immutable claim for the tuple:

`(agent_instance_id, source_skill_id, procedure_id, proposed_version)`.

An exact repeat by the same accepted proposal/intent returns the same immutable
historical claim; a competing proposal for the slot is refused. A stale
predecessor, paused agent, unconfigured repository, invalid review or wrong
principal refuses before any new claim is written. A later version may claim
only once the actual preceding revision has been independently promoted through
the existing governed promotion-link rules.

SQLite unique keys and append-only triggers also forbid UPDATE, DELETE and
`INSERT OR REPLACE` replacements even when recursive SQLite triggers are off.
The returned immutable claim checks its own deterministic receipt SHA-256
against the claimed proposal, selected intent and operator identity. A claim
is deliberately **not** a bypass key: an independent integration test reserves
a valid claim, then verifies the generic promotion merger still refuses the
protected artifact before GitHub PUT, with zero CI/merge side effects.
The claim freezes proposal/intent identity, review, repository, artifact hash,
previous revision, version, and a deterministic SHA-256 receipt. Claim history
is visible only to trusted local operator code. The service has **no API route**,
no model Tool, no expiration/unclaim shortcut, and no GitHub transport.

## Explicit non-authority

The response and DB row both force `publication_authority=false` and
`runtime_authority=false`. The original generic learned-procedure merge
refusal **remains active**. A stored claim is **not** permission to merge an
external PR, load a procedure, change a Skill Registry, widen Tool/Space rights
or consume a revision version.

No claim can be cleared by reboot, deletion, overwrite or caller-supplied
release flag. A later separately reviewed step must add explicit *terminal*
resolution evidence and fail-closed uncertain GitHub merge reconciliation.

## Required remaining release gates

1. Bind the exact claim with an operator-approved repository, PR number,
   PR head SHA, artifact content/path, current predecessor and independent CI
   evidence in a **skill-specific** publication mechanism.
2. Revalidate under the local serialized claim lock **immediately before**
   an external merge; handle changed remote head and untrusted concurrent PR
   merges as a release HOLD rather than relying on GitHub's generic merge.
3. Record an immutable remote-merge receipt only after verifying GitHub's
   committed SHA; ambiguous outcomes remain reserved for explicit reconciliation.
4. Invoke existing `record_promotion_link` only after the exact external
   evidence and live authority gates pass. Runtime loading/activation remains a
   separate operator decision.
5. Full exact-head test/CI, independent read-only review, post-merge `main`
   regression proof, final v0.15 release audit.

No v0.15 release claim is made by completing this local sub-gate. Preserve
the Media four consumed native proof refusals and the parked UI PR #61.
