# v0.15 — Harness project-bound team review plan

This slice binds one reviewed, permissionless Harness draft to an existing Zelo Project and an operator-selected resource proposal. The four source-verified team templates remain engineering quality, business research, YouTube content and trading research. No upstream Harness scripts or instructions are executed.

## Operator-only API

POST /integration-candidates/community/teams/{template}/project-readiness

The strict JSON body accepts a project_id (existing UUID), expected_blueprint_sha256 (from the existing GET team blueprint preview) and proposed_budget. The budget carries planning ceilings, not operational quotas: planned_instance_slots (1–4, four needed for the complete team), proposed_max_concurrent_workers (0–4), proposed_model_tokens_per_task (0–65536), and proposed_monthly_cost_cents (0–100000). External-account, shell and automatic-publication flags must remain false. None is a Worker slot, token authorization, payable budget or new runtime permission.

The service verifies current Project status and updated-at timestamp, trusted Agent Registry version, exact pinned Harness source and blueprint SHA, existing globally registered Agent IDs, and any nonretired AgentInstance with an overlapping role identity (including instances on other Projects).

Read-only reasons: eligible_for_design_review_only, project_inactive, agent_name_already_registered, agent_instance_identity_reserved, and draft_instance_budget_insufficient. Missing projects return 404, stale blueprint 409, bad role budgets or permission-widening request fields 422, and missing pinned source 503.

The strict SHA-256 checked response binds current Project/Registry/Blueprint identity, all four parent-linked agent roles, proposed ceilings and refusal reasons. The SHA-256 is a checksum, NOT an owner signature or authorization ticket. This snapshot must never be accepted by a later Task, Worker or Agent as proof of permission.

## Strict non-authority

Even an eligible-for-design-review result never creates AgentSpecs, AgentInstances, departments, OrganizationAssignments, Tasks, Approvals, Skill Registry revisions or audit records. It cannot start a Computer, make Shell/Browser/File/Space/Tool calls, delegate work, contact brokerage or YouTube accounts, or permit data publication. Resource figures are proposals only, not enforced runtime budgets. All existing Zelo Core action identity, lifecycle, approval, and use-point gates remain unchanged.

The result becomes stale if the Project, Registry, blueprint, role reservations or proposal budget change. Actual team activation needs a **separate durable Managing Director approval**, exact AgentSpec registry revision, atomic instance reservation, project/permission revalidation, per-role resource enforcement and revocation tests. Imported Harness is never a parallel agent runtime.
