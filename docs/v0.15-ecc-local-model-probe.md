# v0.15 — Explicit local Ollama ECC case probe

The preceding ECC fixed-case evaluator grades operator-submitted decisions on
12 Zelo-authored synthetic engineering cases across the four pinned ECC draft
Skills. It makes no real model calls. This separate, opt-in tool adds a bounded
**local-model observation** for three cases of one reviewed Skill at a time.

## Operator command (no service installs)

Run from the Zelo source checkout only when local Ollama is already installed
and idle enough for model execution:

    .venv/bin/python -m scripts.evaluate_ecc_draft_local \
      --skill-id ecc_security_review \
      --model qwen3:4b-instruct \
      --allow-local-ecc-probe

Accepted skills are ecc_security_review, ecc_agent_evaluation,
ecc_ai_regression and ecc_architecture_decisions. The model must be listed by
the currently running local Ollama service. The CLI always uses the fixed
http://127.0.0.1:11434 endpoint, disables inherited proxy settings in the
local Ollama HTTP client (model discovery, metadata and generation), and
removes inherited proxy variables in its own process. Before and after
all three prompts, it checks that the selected name has a pinned 64-hex
model digest and substantial (at least 128 MiB) GGUF model metadata with a
nonempty family. Known cloud-labelled model aliases, missing local-weight
metadata and model changes fail closed; the verified metadata digest appears
in the receipt. It offers no remote server, custom HTTP endpoint, file-writing,
GitHub or Tool configuration.

**This is not absolute network isolation of the Ollama daemon.** The fixed
loopback client and metadata checks do not prove that a configured local
Ollama service cannot initiate its own external/cloud request or falsify
metadata. Host operators must separately verify daemon ownership, configured
cloud policy and egress restrictions before treating it as confidential/offline.
This probe never changes Ollama daemon configuration or restarts services.
A future explicit OS-enforced no-egress qualification is required before
claiming offline model privacy for sensitive prompts.

The explicit opt-in flag is mandatory; without it the program refuses before
even constructing a ModelProvider. It reuses Zelo's existing OllamaProvider
and typed ModelRequest, with a trusted Zelo-authored **rubric only** (the
reviewed ECC manual playbook). No upstream SKILL.md instructions enter prompts.

For each of the three fixtures, the CLI asks the local model to return only
a strict JSON verdict: pass, fail or unverified. It checks the model name,
provider, response size (at most 512 bytes), JSON keys, duration and token
counts; calls time out independently (default 20 seconds, 2–45 accepted).
Any invalid model response or changed pinned source/model identity refuses the
entire score without pretending the failed case was an observed decision.

## Receipt and limits

On success, one bounded JSON receipt is printed to stdout. It contains
the exact Ollama model identity and attested local model metadata digest,
source/playbook/suite fingerprints, three
model-submitted decisions, a SHA-256 of each raw bounded model response,
locally measured duration and optional returned token usage, plus the
existing deterministic fixed-case agreement and error counts. The original
untrusted model text, source files, private credentials, HTTP headers and
entire prompt are not printed.

**A passing three-case local Ollama sample is not an evaluated autonomous
Zelo Agent or an active ECC Skill.** It is only evidence of these particular
local model answers. There is no real Task/Attempt, Tool or Space permission
test, full independent baseline, meaningful reliability sample, evaluator
independence, automatic Skill Learning admission, governance approval,
publication or runtime activation.

The probe executes no code from imported ECC references and grants no
Agent/Worker/Computer/Tool/Skill permissions. It does not persist a Zelo Task,
memory, model transcript, approval or evaluation record; no automatic CI,
merge, GitHub review or background job is launched. All outcomes remain
operator-visible evidence for later separately authorized qualification.

## Testing / future gates

A fake ModelProvider exercises all positive and negative contracts in CI,
without contacting Ollama. Qualification should also include one explicitly
approved real local run against an installed model while host capacity is
available, recording actual elapsed/model identity separately. That operator
proof still cannot qualify a production Agent or Skill. Later phases require
proper AgentInstance/Task/Attempt identity binding, real fixed-task baseline
comparison, independent reviewer observations and governed Skill publication.
