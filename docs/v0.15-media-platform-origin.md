## Reuse decision and architecture

Use distribution provenance as inert evidence beneath Core's platform lock.
Canonical Chisel was inspected at commit 567ecfe8b15846c4367ab6c9e86f4f9844a85e38
(v1.2.0), with Ubuntu 24.04 release definitions at
8e43bc3ea4cd0b10c0f5b9f275409155b4d4cf8a. The exact reference manifest is
runtime/media-platform-chisel-reference/manifest.json. Chisel is AGPL-3.0;
no implementation code is copied or executed. Release-definition LICENSE was
not present at the requested path, so no permission to vendor those files is
inferred. Their static dependency suggestions are research, not a platform lock.
Its generic Python minimal slice includes site customization, OpenSSL and many
modules outside this bootstrap. Mutable fetching, general slice resolution,
globs/mutations and optional Pro credential discovery add authority we do not
need. Do not install/run Chisel or consume its YAML as executable configuration.

Reuse installed GnuPG gpgv for signature verification, not custom cryptography;
later use dpkg-deb for inert package payload streams, not a custom deb decoder.
Use existing Zelo OwnedProcess, deadline, support-FD, durable admission and
retained-evidence lifecycle patterns. Do not edit shared ownership helpers.
This is qualification tooling, not a Core route or user-controlled resolver.

## Implemented source-review candidate

The design review cleared offline implementation only. This checkpoint closes
its specifications for review; no GPG attempt has occurred.

The first implementation is deliberately limited to three fixed Release
snapshots. Index parsing/retrieval/decompression and package inspection are not
implemented or authorized by this source candidate. No Chisel code or slice
definitions are incorporated. The selected historical root is explicitly pinned
by policy to F6ECB3762474EDA9D21B7022871920D1991BC93C, corroborated by the
pinned Canonical chisel.yaml reference (954a98ea87100fd0e892f2933c7f6832b8b85608e2bc55db3ee60f01de7f1ebf).
That corroboration and GitHub HTTPS are the retained source evidence; do not
infer independent current-key validity or revocation checks from the earlier
cross-check wording.

The entire guest bootstrap is a fixed in-argv literal, bound by policy SHA256,
and imports only trusted host stdlib. It does not attach/import any project module
or optional parser. There is therefore no additional guest project-source closure
to authenticate. It sets resource limits before file access; then authenticates
the held-inode executable, keyring and input mounts before any native exec.
The host launcher and host pure validator remain trusted reviewed operator code.

Host operator real/effective/saved UID and GID must all equal 1000. Bubblewrap
explicitly selects guest UID/GID1000, drops all capabilities, and the bootstrap
checks all three IDs, UID/GID maps (guest1000 -> setup0, length1), and CapInh/Prm/Eff/Bnd/Amb
all zero. NPROC0 is supplementary, not process containment. Only direct exec
of the descriptor-bound fixed gpgv path is possible in normal operation. The
bootstrap checks no surviving support FD above2 before exec; the standard streams
are the owned runner's DEVNULL stdin and captured stdout/stderr pipes. Readiness
FIFOs occur only in cancellation controls; they are closed before sleeping and
never reach GPG. Any unexpected inherited descriptor refuses.

The compute plan mounts selected Python/stdlib/architecture-library and loader
paths, not all /usr. Origin-specific pre-remount operations create /opt and the
private /tmp/zelo-gnupg, attach executable/keyring/input via /proc/self/fd held
descriptors, then preserve all existing read-only remounts. No live workspace,
home, config, credentials, network or target platform is exposed. Root-owned
host files are exact modes0755(gpgv)/0644(keyring and three Releases), regular,
nlink1 and stable size/hash. Trusted ancestors/mounts/no-concurrent-mutator remain
explicit; retained FDs are not immutable against a privileged writer.

Clean environment is fixed C.UTF-8, PATH=/usr/bin, TMPDIR=/tmp, private HOME and
GNUPGHOME; bubblewrap's PWD=/workspace is checked. This refines the original C
locale proposal without accepting locale-dependent diagnostics. Logger output
goes only to /dev/null; bounded machine statuses alone occupy stderr.

Pinned upstream GnuPG2.4.4 commit a43271cc08e2068acc75a1742f90740afe0479e0:
doc/DETAILS, g10/gpgv.c, mainproc.c, sig-check.c, plaintext.c, armor.c and
parse-packet.c were inspected statically. Reference hashes are retained in
runtime/media-platform-gnupg-reference/manifest.json. Source is protocol guidance;
the installed Ubuntu-patched executable remains conditional operator baseline,
not asserted byte-equal to upstream. No GnuPG code copied.

Exact acceptance grammar: one PLAINTEXT 74 0 (empty filename) before NEWSIG;
one NEWSIG with no signer-UID subpacket; 1..8 KEY_CONSIDERED records for the pinned
primary fingerprint with flags0 in pre-VALIDSIG phases; one SIG_ID with source-
defined unpadded27-character identifier/date/timestamp before GOODSIG; one GOODSIG
with pinned long key ID (its escaped UID is diagnostic only); one final VALIDSIG
with exactly ten fields. Signer and primary both independently equal pinned
fingerprint, v4/reserved0/RSA1/digest8,9,10/class01; canonical timestamps agree
with dates and SIG_ID, nonzero expiry follows creation. Unknown/extra/negative/
duplicate/out-of-order statuses refuse. Signature timestamps do not establish
current key validity or freshness.

Before GPG, syntax-only framing requires exactly one full clear-sign container,
no prefix/suffix/nested armor, allowed hash header and bounded base64 signature
with CRC line. The wrapper never extracts unsigned Release text for evidence:
only the same settled, successful GPG invocation's stdout enters the strict
Release parser, after complete status validation. Concatenated/malformed frame
tests, phase transitions and failed-exit/unknown-cleanup tests enforce this.
GPG cryptography remains a later actual proof.
