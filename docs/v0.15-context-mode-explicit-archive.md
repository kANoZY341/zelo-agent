# Context Mode concepts — explicit untrusted archive, no automatic recall

This is an independent **Zelo-owned** bounded implementation informed by
Context Mode concepts; **zero Elastic-2.0 upstream code** is copied or run.
It adds a deliberately manual, operator-authenticated and database-backed
archive of textual results. It is *not* an agent- or Worker-facing interface
and is not wired to Zelo Mind's automatic context assembly.

- `POST /integration-candidates/community/context-archive`: requires explicit
  `scope_kind` (`operator` or `project`), project ID where applicable,
  `source_ref` (operator-supplied untrusted label), and the UTF-8 `text`.
  Bounded at 1 MiB and 15,000 lines with no NUL. Returns only checksum,
  counts and bounded excerpt. Same scoped source/ref/bytes is idempotent,
  changed content is refused rather than silently replaced.
- `GET .../context-archive/{archive_id}/window`: requires the identical
  scope, exact SHA-256 digest, and explicit 1-based start/count <= 80 lines.
  Response is limited to 4 KiB; ContextResolver's separate 6000-character
  envelope budget is unchanged. Rejects stale identity or changed bytes.
- `DELETE .../context-archive/{archive_id}`: explicit operator-only purge
  to permanently remove the stored source payload from logical DB rows.
  SQLite file pages/WAL and backups may retain prior bytes until normal
  secure storage maintenance; this endpoint is not a forensic erase.
- All endpoints require Zelo's operator bearer token. There is no bulk-list,
  cross-scope access, auto-ingest, model prompt insertion, Worker activation,
  Tool permission, new external service, or automatic replay of instructions.
- Storage is within Zelo's existing privately-permissioned SQLite DB;
  at most 128 records and 16 MiB raw bytes in total (across scopes).
  Treat pasted logs as sensitive; do not submit credentials or secrets.
  Data is stored until explicit operator purge. Inspect backups separately.

The source reference is **not** proof that an external Tool executed, and the
metadata says `operator_submitted_untrusted_text`. Retrieved text is always
untrusted data, including malicious instructions. Caller-supplied project scope
must refer to a real Core project; agent/Space scopes remain **unsupported**.
