# Zelo Core v0.14 — Organizational hierarchy

## Status

Fifth bounded implementation slice of v0.14 Agent Factory.

Merged prerequisites:

- registry foundation: PR #47;
- project-bound agent lifecycle: PR #48;
- bounded task delegation: PR #49;
- generic Coding/Research execution identity: PR #50.

## Goal

Persist the canonical company hierarchy without mixing organizational authority
with temporary task delegation or worker/tool authority.

Canonical hierarchy:

```text
Human Managing Director
  -> Zelo Group CEO
    -> VP
      -> Director
        -> Manager
          -> Specialist Agent
            -> Worker
              -> Tool
```

The Managing Director and Zelo CEO are reserved principals. They are not normal
AgentSpecs or AgentInstances.

## AgentSpec organizational level

Factory-managed AgentSpecs now carry an immutable
`organizational_level`:

- `vp`;
- `director`;
- `manager`;
- `specialist`.

The field participates in the registry fingerprint. For backward-compatible
schema evolution, the historical absence of the field is canonically equivalent
to `specialist`; existing Coding and Research registry identity therefore remains
unchanged. Non-Specialist executive levels are explicit fingerprinted values.

An organization assignment must exactly match the AgentSpec's trusted
organizational level. A caller cannot promote a Specialist to VP by changing an
assignment request.

## Organizational containers

`OrganizationUnit` represents a durable container:

- division;
- department;
- team.

Required shape:

```text
division
  -> department
    -> team
```

Divisions have no organization-unit parent. Departments belong to divisions.
Teams belong to departments.

Units are lifecycle-controlled and cannot be retired while they still have active
child units or active assignments.

## Reporting assignments

`OrganizationAssignment` binds one active AgentInstance to one active unit and
one organizational level.

Default reporting rules are strict:

```text
VP         -> Zelo CEO
Director   -> VP
Manager    -> Director
Specialist -> Manager
```

Additional unit rules:

- VP leads a division;
- Director leads a department whose parent division is led by that VP;
- Manager leads a team whose parent department is led by that Director;
- Specialist belongs to the same team as the Manager it reports to.

An AgentInstance can have only one active organization assignment. A division,
department or team can have only one active leader for the applicable executive
level.

Assignments are immutable historical records. Ending an assignment is terminal.
A parent assignment cannot end while it still has active direct reports.

## Reserved principals

The organization snapshot always exposes:

```text
human_managing_director
  role: managing_director
  kind: human

zelo_ceo
  role: ceo
  kind: system
  reports_to: human_managing_director
```

VP assignments report to the reserved Zelo CEO principal rather than to another
AgentInstance.

Agent Factory cannot create or impersonate either reserved principal.

## Lifecycle coupling

An AgentInstance with an active organization assignment cannot be paused or
retired. The assignment must end first.

This is enforced:

- in AgentInstanceService for a controlled Core error;
- in SQLite for defense in depth.

## Organization vs delegation

The organizational reporting graph and task-delegation graph remain separate.

Organization answers:

- who reports to whom;
- what unit the agent belongs to;
- what executive level the trusted AgentSpec permits.

Delegation answers:

- what bounded objective was delegated;
- which task kinds/capabilities are permitted;
- which Campaign/Project/budget owns the work;
- how deep temporary child delegation may go.

Creating or revoking a delegation never changes the org chart. Reassigning an
agent never grants a task delegation.

## API

Authenticated operator routes expose:

- `GET /organization/snapshot`;
- `POST /organization/units`;
- `GET /organization/units`;
- `POST /organization/units/{unit_id}/retire`;
- `POST /organization/assignments`;
- `GET /organization/assignments`;
- `POST /organization/assignments/{assignment_id}/end`.

The API is a projection/control surface over Core-owned organization state.

## Migration

Migration `0023_organizational_hierarchy` adds:

- `organization_units`;
- `organization_assignments`;
- unit-shape guards;
- assignment-level/reporting guards;
- AgentSpec organizational-level enforcement;
- active-leader and active-agent uniqueness;
- assignment immutability;
- ordered assignment ending;
- no-delete historical protection;
- agent lifecycle protection while assigned.

## Non-goals

This slice does not:

- create agents automatically;
- let VPs/Directors/Managers bypass Core tasks;
- grant tool or worker capabilities based on title;
- merge reporting relationships with temporary delegation;
- add recursive/model-authored subagents;
- add new Core task kinds;
- add new worker types;
- add automatic memory writes;
- change approval, budget, scheduler, promotion, merge or release authority.
