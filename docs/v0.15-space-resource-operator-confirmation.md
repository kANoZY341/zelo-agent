# v0.15 — Core-owned Space root registry and owner confirmation

**Status:** staged Core contract only. This is not a file-access or Worker
permission release. Built on the inert Space-intent foundation and OpenDots
Specialist-profile foundation; OpenDots itself is never started.

## What this stage actually delivers

For a live AgentInstance whose exact registered AgentSpec declares both a
Space name and file-computer capability, an authenticated operator can:

1. Pre-provision a dedicated directory at
   `<configured runtime_dir>/spaces/<project UUID>/<space ID>/<resource ID>`.
   The names are canonical logical IDs; **no request accepts arbitrary host
   paths**. The service never creates or reads the directory's contents.
2. Record a permanent, uniquely keyed logical `files` resource mapping to
   that directory, with an inode/device attestation, approved operations
   (sorted `read` and optionally `list`), a SHA-256 metadata digest and a
   project boundary. No symlink is allowed in the four below-runtime path
   components. Missing/changed roots are not attested.
3. Record a separate operator confirmation of an existing current intent,
   only for the same project, Space, logical resource and subset of registered
   operations. Confirmation binds the exact AgentInstance, AgentSpec digest,
   registry version, intent digest, resource digest and intent expiry.
4. Revoke confirmation or permanently retire a resource, with one-way
   append-only records. Emergency revocation/retirement remains available
   while the Agent/Project is paused. Pausing/resuming invalidates old
   confirmations without resurrection.
5. Inspect bound status using authenticated endpoints. Confirmation reports
   `eligible_for_mediation` only as a **future implementation prerequisite**.

The new SQLite schema preserves the immutable resource/confirmation and
revocation/retirement history. It rejects both UPDATE/DELETE and duplicate
`INSERT OR REPLACE` with triggers; the service revalidates record hashes.

## Operator-only API

- `POST /agents/{instance}/space-resources` — register an existing directory;
  body: `{"space_id":"workroom","resource_id":"documents","resource_kind":"files","operations":["list","read"]}`
- `GET /agents/{instance}/space-resources/{resource_uuid}` — verify registry
  metadata, root attestation, terminal retirement.
- `POST /agents/{instance}/space-resources/{resource_uuid}/retire` — permanent
  deny; no deletion or reuse of the identity.
- `POST /agents/{instance}/space-intents/{intent_uuid}/activate` — separate
  confirmation; body `{"resource_record_id":"<resource UUID>"}`.
- `GET /agents/{instance}/space-activations/{activation_uuid}` — checks
  current intent/lifecycle, registration, root, expiry and revocations.
- `POST /agents/{instance}/space-activations/{activation_uuid}/revoke` —
  terminal and idempotent denial.

All endpoints require the existing Core operator authentication. Untrusted
documents, models, and workers cannot call these endpoints autonomously.
There is **no** endpoint that opens files through these records.

## Explicit security boundary and remaining work

Every receipt sets `effective_resource_access=false`; activation also sets
`worker_authority=false` and `tool_authority=false`. An eligible confirmation
**must not** be used as an authorization decision for a Worker or Tool.
Existing Computer and API policies remain independent; the registry does not
relax them or grant new capabilities.

Real Space enforcement is a **separate** milestone: register specific resource
use-points; bind the exact AgentInstance and Task/lease at dispatch, claim,
retry, delegation and immediately before use; recheck owner revocations,
project/agent lifecycle and fingerprints; and implement a file-opening adapter
using descriptor-relative `openat`/`O_NOFOLLOW`, bounded path parsing,
same-root containment and hardlink checks. Test concurrent resource swaps,
revocation races, stale identities and denial across all alternative entry
points. Then independently qualify Browser/Terminal/Memory or Tool access.
It is forbidden to wire a raw directory path or the boolean
`eligible_for_mediation` into a generic file/open/shell API.

No directory bytes were ingested, no production Space was registered,
no external accounts were touched, and no REA/Media authority was enabled.
UI PR #61 stays parked.

## Regression checks

`tests/test_agent_space_resources.py` exercises owner auth, exact project and
resource binding, operation subset, missing/symlinked roots, swapped inode,
retirement, lifecycle pause/resume, expiration, double activation, terminal
revocation, SQLite tampering/`REPLACE` and failure to turn confirmations into
effective authority. Also run the existing Space-intent and Specialist-profile
tests. CI and independent review remain required before merging.
