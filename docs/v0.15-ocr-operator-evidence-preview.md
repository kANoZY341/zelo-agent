# v0.15 — Operator-only Open Code Review evidence preview

This slice exposes the existing **source-verified, bounded offline Open Code Review adapter** to the authenticated Zelo operator without giving an external reviewer, Coding Agent, Task, Tool or source file any additional authority. It follows the pinned Apache-2.0 Open Code Review contract and trusted changed-line evidence from the existing trusted-Git OCR guide.

## Endpoint and usage

**POST /integration-candidates/community/open-code-review/evidence/{base_sha}/{head_sha}**

Requires the normal Zelo operator token and an application/json body of **raw untrusted reviewer JSON** (schema: zelo-ocr-line-review-input-v1). The endpoint reads at most 131,072 bytes via streaming size enforcement rather than accepting a parsed JSON object that could silently discard duplicate keys. Expensive Git evidence derivation runs in a thread pool behind a nonblocking, capacity-one process-local gate: simultaneous requests receive HTTP 429 without starting Git. Every Git command retains its own output and time bounds. Neither the body nor URL can choose a filesystem root.

The operator supplies two exact Git commit SHAs that must be local commits in Zelo's trusted, fixed application repository, with HEAD exactly matching head_sha. The base must be a real ancestor of the reviewed HEAD, not an unrelated commit containing identical file-tree bytes. The root comes from Zelo Core configuration, never the submitted request. The existing adapter derives changed-line authorization from committed Git objects, not from submitted reviewer text or mutable working-tree files. It rejects stale HEAD, unsafe Git configuration, untrusted paths, binary/symlink/deleted changes, unanchored comments and oversized evidence.

The response contains a normalized ReviewerReport, immutable OcrEvidenceEnvelope, bounded changed-file and changed-line counts, and explicit false authority flags. The **raw patch is not returned**. The preview creates no Task, Approval, Memory item, AuditEvent, GitHub comment or external reviewer invocation.

## Security and authority boundaries

- Exact HEAD/commit identity, diff hash, source provenance, and comment line ranges are checked inside the existing trusted verifier.
- All response fields for Worker registration, merge or approval, Git write, Tool use, trusted-review quality, and Mind admission are explicitly false. Finding text remains **untrusted evidence**.
- Denials return stable bounded reason codes, not file contents or private subprocess diagnostics.
- No promoted Skill, automated code patch, external reviewer process, GitHub PR action, independent review replacement or model-facing Tool is introduced. All existing approval, CI, reviewer separation and release gates remain required.

## Qualification and follow-up

The authenticated HTTP route must pass existing OCR review and trusted-Git scope regressions plus positive line anchoring, stale/forged identities, dirty-worktree independence, invalid/duplicate JSON, oversized bodies, unavailable pinned sources and no-mutation assertions.

This endpoint is **manual and operator-selected**, not an autonomous Coding Specialist review integration. The next independently qualified milestone must bind optional OCR findings to an exact Coding Specialist Developer Task/Attempt and frozen reviewer identity, measure false-positive rates, and activate only an explicitly operator-selected supplementary review mode. Never replace the independent reviewer merely because OCR evidence exists. Track these gates in issue #132.

Parked UI PR #61, REA/Media restrictions and v0.16–v0.18 ordering remain unchanged.
