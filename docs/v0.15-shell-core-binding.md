## Narrow runtime contract

A default-disabled Shell worker may reuse the now-qualified fixed sealed
Dash/prlimit/Bubblewrap built-in compute lane. No workspace, writes, network,
credentials, package install or new process creation. The payload contains only
bounded script text; no executable/flags/env/cwd/mount/source/directory/policy
selection. Do not offer a separate stdin data field while Dash parses the same
stdin as script: the first lane has one explicit script stream. Reject NUL,
empty/oversized UTF-8 bytes and nonfinite/bool/out-of-range deadlines at submission.
Ceiling remains two seconds and the exact qualified hard resource/output bounds.

Use distinct shell role/capability/skill and an isolated-shell-compute authority
profile. Do not relabel Python or Browser authority. No default AgentSpec,
Mind/conversation route, organization, release or production enablement. Native
output stays untrusted text; it cannot grant authority or become approval evidence.

## Persisted exact identity

Add a frozen strict ShellExecutionSpec with trusted worker selection, fixed
policy digest, operator/runtime/admission identity and exact deadline. Bind
source artifacts, sealed policy, arguments, environment, operator UID/GID and
adapter version from trusted assembly. Caller payload cannot supply the spec.
Submission persists it and action hashing includes it. Retry performs fresh
selection/binding; claim and Runner revalidate every selection/spec/action field
before creating/running attempts. Missing/stale/tampered spec fails closed;
never silently rebind old persisted tasks. Follow existing migration/trigger
preservation and explicit authority-policy schema versioning conventions.

Full artifact verification must occur before the Core writer transaction, with
an ephemeral runtime-bound validation token and bounded metadata revalidation
when binding inside the transaction. Never cache accepted source bytes between
attempts: actual guest creation seals and rechecks approved bytes again. Source
hash changes/configuration/operator changes invalidate selection/spec matches.
Hash/metadata validation is not independent source provenance.

## Trusted runtime ownership

One operator-provisioned canonical private persistent admission directory is
bound at assembly, not chosen per task. Reuse qualified ShellIdentity/ShellOwner
and generic admission/lifecycle helpers. Defaults perform no native startup or
source scans; unavailable/root/changed prerequisites refuse explicit enablement.
Do not auto-create or reconcile unknown admission state. Keep native per-call
observation and source/pin settlement evidence; only true cleanup permits owner
pruning. Results remain tentative until child/group, pidfd/pipe/task and pin
cleanup and durable lease completion. Late pending cleanup remains retained;
unknown cleanup/crash fences replacements. Runtime closure stops new admission
and closes all owned lifecycles without PID-age/TTL/error-string inference.

Map busy/fenced/runtime/source/deadline/output/cleanup failures to fixed Core
codes. A clean timeout uses explicit cleanup evidence, not exception provenance.
Never return partial successful output on cancellation or unknown cleanup.
Preserve existing approvals, scheduler, budget, audit, lifecycle and Agent
WorkerRequirement gates. Core decides and owns authority; Shell only computes.

authority/registry selection; default disabled/no routes; source validation and
runtime-bound token freshness; persistence/action hashing/retry; missing/stale/
tampered selection and spec at claim and Runner; migrations/triggers; Agent
Factory requirements; structured untrusted evidence; shutdown/pending ownership;
no command/env/path overrides or fallback; and existing worker compatibility.

Opt-in actual native Core proof uses init-only Settings, private SQLite and one
shared private admission directory. Drive TaskService and Runner with two real
harmless Shell tasks, persisted exact selection/spec/action identity, verified
untrusted output and readmission. Add actual output/deadline/cancellation/fence
lifecycle cases, not a fake backend standing in for the execution boundary.
Ambient settings/hooks/credentials must not alter fixtures or the fixed guest.
No live Core database, user files, services, public listeners or model requests.
