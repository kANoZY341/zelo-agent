# Zelo Core v0.15 — Browser Worker qualification

## Status

Design and qualification plan only. No Browser Worker is implemented or activated
by this document. Begin from the verified API Worker merge, not a stacked runtime
change. Keep the published Core version unchanged until normal release preparation.

## First bounded outcome

Read an operator-approved public page and return bounded text/evidence through Core.
Do not introduce general computer control, arbitrary JavaScript execution, form
submission, uploads, downloads, authentication, persistent profiles or host secrets.
Treat page content as untrusted data, never instructions that can change authority.

## Reuse candidate

Evaluate a narrow Playwright Python adapter, rather than forking a browser automation
framework or replacing Core. Its upstream license is Apache-2.0 [1]. Record the exact
qualified package/browser versions and provenance before integrating dependencies.
The host prerequisite inspection found no Playwright, Selenium or Chromium installation
in the current Core environment; no installation was performed during this planning.

Playwright documents request interception and warns about service-worker interception
gaps [2]. Routing hooks are therefore a convenience, not the complete egress boundary.
Its Docker guidance also distinguishes untrusted browsing from ordinary test use and
calls for browser sandbox qualification [3]. Do not copy permissive test-container
settings into production or silently disable Chromium sandboxing.

## Authority to qualify before activation

- Core owns the allowed origins, resource budgets, deadlines, task identity and audit.
  User/model input cannot select arbitrary hosts, executables, browser flags or proxies.
- Use a fresh non-persistent browser context with an empty private profile. No mounted
  Zelo workspace, credential stores, extension directory or inherited browser session.
- Prove OS-level prevention of unmediated browser egress. Evaluate a Core fetch broker
  plus isolated rendering; routing callbacks alone are insufficient. Do not give an
  external browser unrestricted host networking as a fallback.
- Every brokered connection must enforce reviewed public HTTPS destinations, DNS/IP
  validation and verified TLS identity. Do not broaden the existing JSON-only API
  Worker to accept arbitrary page content. Factor only reviewed shared primitives.
- Reject or individually revalidate redirects. Bound request count, wire/decompressed
  bytes, resource types, execution time, page text and memory before enabling a task.
- Block service workers, arbitrary sockets, persistent storage, downloads, clipboard,
  permissions and local-file navigation. Start with page JavaScript disabled unless
  stronger isolation and its residual behavior have been demonstrated by live probes.
- A GET restriction is not a remote side-effect guarantee. Operator-approved origins
  must be suitable for this lane; no caller tokens or private data in URLs/queries.
- Do not reuse the OS resolver without addressing its outstanding-thread availability
  limitation in the browser request-budget design. Bound admission and cleanup.
- Preserve native browser sandboxing and qualify the outer process/filesystem boundary.
  If the required isolation is unavailable, report unavailable; never weaken it.

These are proposed acceptance requirements, not claims that the host enforces them
already. The choice of container/process boundary and broker transport remains subject
to qualification; no new system services or firewall changes are authorized by this file.

## Delivery gates

1. Qualify an optional, pinned browser environment without modifying Core's live
   environment. Record browser executable/assets and the complete enforced policy.
2. Run real browser probes against controlled fixtures: private/loopback targets,
   mixed DNS, TLS mismatch, redirects, service workers, sockets, file navigation,
   downloads, page resource floods, cancellation and child-process cleanup.
3. Only after those probes pass, add a typed bounded task, trusted WorkerDescriptor,
   capability/skill and exact persisted execution binding through Supervisor/Core.
   Do not create a default AgentSpec or invent organizational authority.
4. Preserve action hashing, retries, claim/Runner revalidation, exclusive scheduling,
   audit and migration guards. Do not register missing/unqualified runtimes as active.
5. Require focused tests, full pytest, independent Astra Medium review and exact-head
   GitHub CI. Optional dependencies must fail closed without breaking existing workers.

No higher roadmap milestone is reordered: channels remain v0.16, real specialist
organizations remain v0.17, and advanced learning/recovery remains v0.18.
