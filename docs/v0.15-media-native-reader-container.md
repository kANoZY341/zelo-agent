## Scope

PR #91 merged at `09b68a5355098e15f3549faa98126203c08309eb` with tree
`4b39b2f253108e7bbf1461b4cccaffac321d270e`, exactly matching the reviewed

## Fixed future runtime shape

The future image is scratch-style and may contain only the separately pinned
reader artifacts and required notices:

- `/reader/dpkg-deb`
- `/reader/ld.so`
- fixed libraries under `/reader/lib`
- retained notices

The only candidate command is:

```text
/reader/ld.so --inhibit-cache --library-path /reader/lib   /reader/dpkg-deb --threads-max=1 --fsys-tarfile -
```

The command is policy-owned. There is no shell, human tar command, package
manager, caller-supplied executable, host pathname or option interpolation.
Input arrives only on stdin. The image must contain no gzip/xz/zstd/bzip2 helper
executables; the declaration gate already confirms the intended libraries are
the fixed providers.

Environment is exact and fail-closed:

```text
LC_ALL=C
LANG=C
PATH=/nonexistent
HOME=/nonexistent
TMPDIR=/nonexistent
```

No ambient DPKG_DEB_* or compressor settings are accepted.

## Container configuration contract

The pure validator requires:

- exact content-addressed image identity and bundle digest;
- image architecture amd64 / OS linux;
- inert image config: no baked entrypoint, command, environment, user, volumes,
  ports, healthcheck or on-build actions;
- `runc` runtime;
- network mode `none`;
- read-only root filesystem;
- non-root `65534:65534`;
- `cap-drop=ALL`;
- exactly `no-new-privileges`;
- memory and memory-swap both 512 MiB;
- PID limit 8;
- CPU period 100000 / quota 50000;
- nofile hard/soft limit 32;
- private IPC and cgroup namespaces;
- no host PID or UTS namespace;
- 1 MiB shm;
- no restart, no daemon log driver, no autoremove;
- no binds, devices, device requests, port bindings, links, extra hosts,
  DNS settings, supplemental groups, sysctls, device cgroup rules, cgroup
  parent, storage options, tmpfs or other mounts;
- stdin open, no TTY, working directory `/`;
- exact lease and bundle labels.

These are configuration assertions only. A later native matrix must inspect the
actual container and its cgroup at runtime; CLI arguments alone are not evidence
that limits were enforced.

## Why a container boundary is required

The reviewed dpkg source forks a copy child and a decompression child. Per-process
resource limits therefore do not establish aggregate memory/PID/CPU behavior.
The xz path also does not provide a sufficient hard aggregate decoder memory
bound. A cgroup-backed container is the intended aggregate boundary.

The reviewed source can normalize decompressor SIGPIPE to success. Consequently,
stdout saturation, timeout or cancellation must permanently invalidate the
result even if the final parent exit status is zero. The future owner must settle
the entire owned container/process tree before any receipt.

## Input and output progression

The first native-reader qualification must use a **fixed synthetic modern Debian
archive**, not any of the eight acquired archives. It will establish only:

1. the fixed loader/library image can start the reader;
2. modern package framing reaches the data tar stream;
3. output/resource/cancellation limits are actually enforced;
4. every owned container/process is settled and removed.

The acquired archives remain inert until a later separately cleared real-package
attempt.

The reader stream and USTAR inventory scanner stay separate trust boundaries.
The scanner currently accepts a deliberately narrow USTAR subset and rejects
GNU/PAX extensions. A real-format refusal returns to design; it does not authorize
loosening the scanner.

## Required synthetic controls before native execution

A future launcher must test, without using acquired package bytes:

- image/bundle identity drift before create;
- wrong runtime/entrypoint/argv/environment;
- unexpected mount, network or privilege authority;
- memory/PID/CPU/nofile mismatch;
- writable root or helper executable presence;
- modern positive synthetic package;
- legacy package refusal;
- duplicate/premature control/data members;
- unsupported compressor;
- truncated compressed stream;
- decompressed stdout cap;
- stderr cap;
- timeout;
- cancellation and repeated cancellation;
- output saturation followed by exit zero;
- container create acknowledgement loss;
- child/process-tree cleanup ambiguity;
- removal/discovery failure;
- support-release failure after otherwise passing cases.

Every failure remains retained and no successful receipt is possible without
confirmed cleanup.

## Gate order

1. Pure contract and fake tests.
2. Fixed synthetic package and scratch-image construction manifest.
3. Image contents/inventory verification without running it.
4. Frozen launcher/source review.
5. One bounded synthetic native matrix.
6. Independent retained-evidence audit, exact-head CI and merge.
7. Separate real authenticated-package design.
8. Only then compose native tar streaming with the qualified USTAR inventory
   path and continue Media runtime/import/image-decoder closure.

No previous proof counter is reset by this design. Version scope remains 3/4,
USTAR isolation remains 1/2, archive acquisition remains 1/4, and all historical
failures/evidence are preserved. No Core binding, enabled flag, UI work or later
milestone completion follows from this document.


## Consolidated offline implementation checkpoint

The initial pure contract has been consolidated with separate, non-executing
boundaries rather than duplicating policy:

- `media_reader_container.py` is the single container configuration contract;
- `media_reader_fixture.py` owns exactly four hand-built synthetic Debian inputs
  and post-cleanup result validation;
- `media_reader_image.py` derives the deterministic eight-file scratch-image
  manifest and inert Dockerfile from the accepted bootstrap lock;
- `media_reader_seccomp.py` pins and validates the repository's exact vendored
  Moby default seccomp profile without Chromium's extra rules;
- `media_reader_process.py` is a qualification-only owned-container handle. Its
  current evidence is fake-daemon lifecycle testing only; it performs no action
  on import and has no product application import.

Admission lease identities are the actual 64 lowercase hex characters produced
by `AdmissionController`; the earlier 32-character draft assumption was corrected
before any daemon operation. Image config remains inert: runtime loader, argv,
environment, user and seccomp are supplied only by exact create arguments.

The fixed positive archive contains `debian-binary` = `2.0\n`, an empty
`control.tar`, and the already-qualified synthetic USTAR bytes as uncompressed
`data.tar`. Three negative fixtures alter only the version, member order or final
byte truncation. An independent test-only ar decoder confirms those layouts
without invoking dpkg or a general archive parser.

Focused validation currently passes 158 tests across image, fixture, seccomp,
container and owner modules. Fake-owner coverage includes no inherited Docker
context/HOME, exact labels, profile drift before start, resource/config drift,
stdout overflow, bad result rejection, create/start/remove cancellation,
lost-create ambiguity and cleanup failure fencing. This is implementation
evidence only; no Docker daemon or native process has run.

Next source gate: freeze these exact files, run the broader Media/context suite
and causal controls, then normal draft PR/full CI. A later branch may implement
the setup/operator and seek explicit clearance for one synthetic native matrix.
No acquired package bytes are eligible in this offline slice.


## One-shot synthetic operator checkpoint

PR #92 merged the offline boundary at `f05abe11cd6b659a8339132028ca710e16393c48`
after 4,505 full-CI passes and two skips. The next branch implements the separate
operator described above; it still grants no native authority on merge by itself.

The setup now labels the built image with the unpredictable admission lease before
container creation, so a lost build acknowledgement can be reconciled through an
exact label query. Discovery accepts at most one image and one container for that
lease; every removal rechecks the lease label and unrelated Docker resources are
never selected.

A private build context copies only the eight retained bootstrap binaries. Build
uses network none, pull false and a scratch Dockerfile. A stopped setup container
is exported with the existing bounded Browser export helper and verified against
the fixed image manifest before any start. Build-context files are rehashed after
attestation.

The actual runtime probe occurs after start/attach but before stdin. It verifies
the running container contract and reads only the exact cgroup-v2 membership plus
memory.max, memory.swap.max, pids.max, pids.current and cpu.max. Expected values
are 512 MiB memory, zero extra swap, pids 8 and CPU quota/period 50000/100000.

The candidate native matrix contains the four fixed synthetic Debian packages plus
stdout-limit, timeout, cancellation and repeated-cancellation controls. The
stdout control only passes for the exact `process_output_limit` refusal; unrelated
exceptions cannot satisfy it. Every case must settle the exact owned container.

Offline verification at this checkpoint passes 173 focused operator/setup/cgroup/
container/process tests and 2,752 combined Media/context tests. Static lint,
format and whitespace checks pass. See
`reviews/media-native-reader-qualification-source-review.md` and its gate JSON.

The source review conditionally clears at most one synthetic `--run` only after
the exact committed implementation/tree passes its own full CI. Until then, no
Docker image build, native loader/dpkg execution or new native-reader attempt is
authorized. Acquired package files, image decoding and Core/runtime authority
remain separate later gates.
