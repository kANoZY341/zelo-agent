## Host observations so far

Default container profile denied the user-namespace primitive. A first candidate
then failed at native chroot confinement; the candidate with the constrained
namespace calls and chroot rendered a fixed trusted data URL successfully.
A further narrowed candidate with the exact five rules also rendered successfully.
The image and container were removed after each probe. No external page, user
file, credential, image pull, or privileged container was used.

These observations do not alone prove native renderer filter/cgroup enforcement
or qualify untrusted browsing. Repeatable renderer/negative-control/resource/
cleanup probes and independent review must follow. Strictly distinguish observed
properties from a complete production Browser Worker.

## Offline profile API and proof scope

`qualification/browser_seccomp.py` provides `build_profile() -> SeccompProfile`.
The frozen contract contains immutable `profile_bytes` and their SHA-256 `digest`;
construction validates both. There are no caller-selected policy, path, flags or
architecture parameters. Local architecture must be exactly `x86_64` or `amd64`.
This check does not attest a remote executor/container architecture.

The fixed vendored source is read with a 64 KiB ceiling (one extra byte detects
oversize), authenticated against the code-pinned upstream SHA-256 before parsing,
and freshly decoded for every build/validation. All baseline settings and syscall
rules remain semantically unchanged; deterministic compact JSON appends only:

- clone arg0 EQ `0x10000011`, `0x20000011`, `0x70000011` (three rules);
- unshare arg0 EQ `0x10000000` (one rule);
- chroot (one rule).

Every addition has `includes.arches = ["amd64"]`. Default ERRNO and all upstream
conditions remain intact. The adapter adds no capabilities. Original upstream
JSON, LICENSE and NOTICE bytes are retained unchanged.

Before eventual use, call `validate_profile(profile_bytes, digest)` on the exact
bytes to be consumed. It raises `SeccompProfileError` for invalid bytes/digests,
unsupported architecture, unreadable/oversized/drifted source, or any difference
from the freshly rebuilt canonical candidate. Recomputing a digest after policy
mutation cannot authorize that policy. Even equivalent alternative JSON formatting
is rejected. Output is also bounded to 64 KiB; no mutable policy cache is shared.
Code, pins and repository ancestors are trusted operator inputs. Test-only
monkeypatches of those constants are not supported policy configuration. This
contract authenticates policy bytes; it does not attach seccomp, launch a container,
verify native renderer enforcement or enforce no-network/resource/cleanup settings.

## Repeatable owned host diagnostic

`python -m scripts.qualify_browser_native_sandbox` requires explicit
`--acknowledge-local-container-test`, an operator-prepared `--bundle`, and its
independently trusted `--expected-bundle-digest`. The tool validates the pinned
browser hash, copies/rescans the bundle, compiles a repository-owned static C
fixture, and builds only a labelled scratch image with build networking/pulling
disabled. No package or browser installation is performed. The exact profile,
image, entrypoint, environment, mounts, privilege and resource settings are
checked before container start. Images/containers are removed only after their
unpredictable ownership label is verified; failures are reported as unproven.

Actual host diagnostic passed with bundle digest
`5cd2da1e5d84d268dbe7c46e6a95f82d640babed410ffd1f31c681de37f424ca` and generated
profile digest `96f07a6e4fe3a1dd9b93527078f25250e616dae615f875df9943ad4223811b37`.
The renderer reported seccomp mode 2/two filters (container has one), NNP 1,
CapEff 0 and nested PID depth 3 versus container depth 1. The fixture independently
read memory.max=536870912, memory.swap.max=0, pids.max=128 and
cpu.max=50000/100000. Initial-container NEWNS/NEWNET unshare, setns and chroot
were denied; clone3 retained its ENOSYS fallback. The native renderer still
performed its nested chroot confinement, with no container capability addition.

The diagnostic's private debugging listener stays inside network-none; it is not
the planned production pipe interface. Page content is a fixed trusted fixture.
No claims are made about arbitrary-page execution, a global admission integration,
all possible kernel exploits or complete artifact freezing/TOCTOU protection.
The pinned policy exposes additional namespace/chroot syscall surface deliberately;
its restrictions and kernel namespace/capability checks are part of the trust model.

Host focused gate: 369 passed (94 new policy tests, 23 diagnostic-gate tests,
252 prior artifact/owner/resource/broker/DNS cases), three existing warnings.
Full CI and independent review remain merge gates. Real native diagnostics are
opt-in and are not automatic CI container/browser execution.
