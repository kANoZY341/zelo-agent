# v0.15 — Immutable Git commit, tree-mode and blob-byte attestation for Skills

**Status:** isolated development candidate. No GitHub write/merge or runtime
Skill activation, and no new Agent/Worker/Tool permission.

The earlier operator-selected exclusive claim, approved review and fresh
GitHub PR/CI checks establish the intended repository/PR/head/base identity.
This slice additionally proves the *immutable* reviewed Git head contains
exactly the approved regular-file artifact, avoiding races caused by GitHub's
mutable PR-files listing.

## Immutable source and mode proof

1. Reconstruct trusted Core accepted proposal, claim, reviewed single-file
   artifact and exact frozen PR/head/base/CI evidence. Refresh the GitHub PR
   and required CI via bounded GET requests.
2. Query `GET /compare/{base_sha}...{head_sha}` using the frozen **immutable
   commit IDs**, not `GET /pulls/{pr_number}/files`. Require exactly one
   added file, at the reviewed path, with one Git blob object ID; reject
   other files, deletion, rename, wrong base and unexpected comparison state.
3. Query `GET /git/commits/{head_sha}` and verify the exact immutable
   reviewed commit identity. Starting from its returned tree SHA, traverse
   each path segment using bounded `GET /git/trees/{tree_oid}` requests.
   Require each parent to be an ordinary tree with mode `040000`; the
   final exact file must have Git type `blob`, mode **`100644`** and the
   **same blob object ID as the immutable compare result**. Reject symlinks,
   gitlinks/submodules, missing/duplicate names, truncated tree replies or
   unexpectedly large directory listings. Every returned tree must match the
   requested immutable tree SHA.
4. Read the exact Git blob by OID using GET, reject excessively large or
   malformed base64, confirm exact size no greater than 65,536 bytes, and
   compare source bytes against the original trusted Zelo artifact's SHA-256.
   Separately recompute Git's SHA-1 blob object ID to prove consistency
   with the immutable Git tree. Git SHA-1 is a Git protocol locator; **the
   local SHA-256 is the content-integrity requirement**.
5. Recheck the mutable PR *after* the immutable object reads and revalidate
   current Core Agent/claim/registry authority. A changed PR head/base,
   closed/draft/merged status or revoked local actor fails closed.

The response includes bounded IDs, digests, observation time, and literal
`immutable_base_head_compare_verified=true`,
`exact_head_tree_regular_file_mode_verified=true`,
`git_blob_oid_and_sha256_verified=true`,
`no_github_write_authority=true` and
`no_runtime_skill_authority=true`. The verifier neither persists nor
returns source text.

## Test coverage and non-authority

Offline scripted-provider tests cover successful immutable tree proof, an
extra/missing/deleted path, altered base or commit SHA, symlinks, submodules,
wrong Git mode/blob object IDs, truncated trees, corrupt/oversized blob data,
unexpected PR changes, newline-wrapped base64 and invalid operator principal.
No test sends a GitHub write, activates a Skill or calls a native Media reader.

Even fully verified immutable source bytes do not authorize GitHub PUT or
resolve races in an external publisher. This remains **read-only evidence**.
A functional protected learned-skill merge requires a separate reviewed
human-authorized publication-specific executor with durable pre-side-effect
fencing, exact remote preconditions, and read-only reconciliation of uncertain
responses before ever recording a promoted link. No blind retry is allowed.

attempts remain terminal refusals; no fifth native proof is authorized.
