# v0.15 — Read-only Git blob byte attestation for claimed Skill proposals

**Status:** isolated development candidate. No GitHub PUT/merge, no runtime
Skill activation, no new Agent/Worker/Tool grants.

This phase narrows the gap between a locally reviewed procedure artifact and
the bytes present in the GitHub PR. The earlier Core publication claim, frozen
MergeRequest preview and fresh provider PR/CI verifier establish exact
operator-selected proposal, repository, PR, base and head identity; the new
`SkillPublicationBlobEvidenceService` adds bounded source-byte verification.

## Read-only checks

After independently confirming current Core claim/Agent state and provider CI:

1. GET the reviewed PR's changed files with `per_page=100&page=1`; require
   exactly **one** added file with the exact reviewed procedure path and one
   40-hex Git blob object ID. Any extra, removed, renamed, missing or mismatched
   file refuses before retrieving source bytes.
2. GET the exact Git blob object. Require `encoding=base64`, exact expected
   byte size no greater than 65,536, bounded encoded content and strict
   base64 decoding. Compare the content bytes to the **trusted local Core
   artifact SHA-256**, not merely a Git blob object ID or caller metadata.
3. Recompute the Git SHA-1 blob object ID (its Git-protocol identity, **not**
   the security digest) and compare with the reported OID; SHA-256 remains
   the security content-integrity check.
4. GET the PR again after receiving the blob and refuse changed head/base,
   closed/merged/draft state, repo, number or branch identity.
5. Recheck current local Core claim/proposal/Agent authority after network
   reads. Return only bounded hashes, IDs, timestamp and strict non-authority
   flags; no source text, credentials, URL query or filesystem content is
   admitted to Mind, logged or persisted by this module.

All provider calls are **GET**. The bounded test provider simulates changed
PR files, corrupted bytes/encoding, oversized response, changed blob OID,
foreign path, terminal PR, and unauthorized principal.

## Limits — not a merge ticket

This Git-blob proof does **not independently verify the Git tree entry's file
mode** (for example `100644` vs `120000`). The response explicitly reports
`git_tree_mode_not_verified=true`. A future externally acting publisher
must attest the exact Git tree mode and commit ancestry and must not consider
this result a durable source of current provider state.

A successful read-only observation can become stale immediately. It neither
approves a later merge nor settles ambiguous PUT results. The original
protected learned-procedure generic-merge refusal remains active. The separate
operator decision ledger authorizes **review only**, not GitHub actions.

Before a functional v0.15 publication path is eligible, the provider writer
must bind the exact approved decision and Git tree, durable pre-side-effect
fence, human approval, current CI, exact remote state and read-only post-merge
reconciliation. No blind retry or runtime Skill activation may be inferred.
All remaining v0.15 release gates and four consumed Media native-reader proof
refusals remain as recorded in issue #166.
