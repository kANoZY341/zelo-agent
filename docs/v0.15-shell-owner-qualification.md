## Implemented candidate, gates pending

`qualification.shell_compute.ShellIdentity` binds immutable sources, sealed
artifact handling, exact argument/environment tuples, nonroot operator identity
and hard ceilings. Execution is generated from the same bound object; changed
module globals cannot switch a fingerprinted policy. Operator/type/tamper checks
repeat before native launch. One absolute deadline covers admission, synchronous
setup, preflight, process creation and work; cleanup may outlive that deadline.

`LeaseResourceOwner` extracts only policy-neutral retained lifecycle machinery.
The existing Browser `ResourceOwner` remains a strict `ExecutionPolicy` wrapper.
`qualification.shell_owner.ShellOwner` uses the existing durable admission
controller unchanged and creates a resource-free handle before setup. Native
per-execution observation starts before spawn and distinguishes pending creation,
no-child failure, owned child, final reap, pidfd/pipe closure and I/O settlement.
Shell source verification descriptors and sealed-pin closure are tracked too.
Independent reader/drain cleanup continues even when child termination is unknown.
Incomplete process observation is uncertainty, not positive cleanup evidence.

Results remain tentative until cleanup succeeds and the durable lease finishes.
Repeated cancellation and grace expiry retain the lifecycle and marker; late
verified cleanup can admit a fresh owner. Unknown child/source/pin/pipe cleanup
or owner death stays fenced. No error-code or global-registry snapshot is used
as termination evidence. Complete relevant `/proc` visibility, the live event
loop, trusted fixed installed artifacts/host dependencies and same-UID operator
remain prerequisites/assumptions. No automatic reconciliation is added.

```bash
.venv/bin/python -m scripts.qualify_shell_owner --allow-native-shell-probes
```

The optional proof runs fourteen fixed boundary cases through durable ownership,
then independent-owner contention, repeated cancellation/readmission, and owner
death with a preserved restart fence. It kills only a directly owned harmless
fixture parent after a bounded guest is alive; descendant pidfds observe exact
exits and never signal numeric descendants. The fixed guest has no process
creation, workspace, network or writes. A crash marker remains in its private
proof directory even after death-bound descendants exit. Reports distinguish
reaped boundary launchers from observed crash-descendant exits; hashes do not
establish independent provenance. Host fixture Python/dependencies are trusted.
The hidden fixture entry also requires opt-in and only accepts this harness's
canonical private proof-root namespace. No configurable task/command/path/target
surface is exposed to Core.

Preliminary host proof passed seventeen cases. Focused/static/exact-head CI and
independent Astra Medium review remain required before this runtime slice merges.
