# OCR real-diff quality receipt

This offline diagnostic scores raw Open Code Review JSON against two pinned,
committed Zelo diffs. `migration_0049_data_loss` uses PR #242's merge commit
`b0f2da6d9c18afd657113731059c11f5c3bbd60b` and its ancestor base
`d3ebcdadc2c9631eecbc9691158ee2f01e5aa711`. The known defect is the
destructive `downgrade()` at migration line 175, later repaired by PR #305.
`browser_297_clean` uses PR #297's clean change, base
`a417272318e7c1ba62fda337819a83b6f1ca8451`, head
`02908456765063232dc9cac528aab92bc6c155fb`.

Use a separate disposable checkout at each historical head. The raw review
file must be an OCR `zelo-ocr-line-review-input-v1` JSON response. For example:

```bash
.venv/bin/python -m scripts.evaluate_ocr_real_diff \
  --case migration_0049_data_loss \
  --repo /absolute/path/to/disposable-head-checkout \
  --raw-review /absolute/path/to/local-raw-review.json
```

The command verifies exact HEAD, ancestry, immutable diff and changed-line
anchors through the existing Git and OCR adapters. It emits hashes and counts,
not reviewer prose. A malformed review is `invalid_review`, never a clean
negative. A valid review with no findings misses the known migration defect;
a valid empty Browser review counts as a clean negative for this selected
case. A valid comment remains `needs_adjudication` until its actual claim is
read against the code and separately labelled.

For manual labelling, pass `--adjudications` with a JSON array. Each item has
`comment_sha256` from the initial receipt, `verdict` (`known_defect`,
`supported_other`, or `unsupported`) and a 20–2000 character `rationale`.
The `known_defect` label is accepted only for a comment anchored to the pinned
migration line. This is a hash-bound human claim, not cryptographic proof of
reviewer independence. Its rationale is hashed into the receipt and is not
printed. A clean control with a comment cannot count as a clean negative.

This tool does not run a model, contact GitHub, register a Worker, create a
Task, publish a Skill, approve code, or activate OCR. The two historical cases
do not establish general model quality. Issue #132 still requires independent
semantic adjudication over broader real diffs, false-positive and miss rates,
then a separate operator activation decision.
