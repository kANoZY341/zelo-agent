# v0.15 delegated Space file use candidate

Status: merged in #217 at `d7291fb`; not an R1 or release gate PASS. Exact-head CI 39181179012 passed; distinct main CI 39182417806 passed, while host acceptance remains open. The full v0.15 release remains HOLD.

A delegated child can submit a bounded Computer `files_read` or `files_list` Task only with its own explicit Space intent and activation. The parent cannot lend its activation. The child AgentSpec, its current Project and computer permission, the exact Task action, Worker selection, campaign and active delegation, reserved budget, parent Agent identity and `computer_read` capability are checked at submission, retry, claim and again immediately before filesystem use. Revocation or owner human takeover prevents a new read. The gateway refuses delegated use if it has no Core TaskService validator.

The gateway uses the existing pinned-descriptor path handling, file size and extension limits, serialized Core writer, bounded control lookup and audit event. The child read result is not automatically admitted into model context. Existing nondelegated behavior remains covered by its regression suite.

The tests exercise a real persisted parent/child delegation, campaign reservation, child-owned approval, claimed Task and Runner result. Negative cases cover delegation revocation before use and during the awaited control lookup, parent activation substitution, missing Core validator, and `list` versus `read` operation separation. They assert no backend file read and no completion audit on denied use.

This does not grant general Space permissions, Browser/Memory/Terminal access, write access, arbitrary delegation, or a Media proof. An already-started bounded read cannot be retroactively stopped by a later revocation. Host acceptance and the other Space authority gates remain required before this can contribute to R1.
