## Purpose and boundaries

The eight-case Core host proof uses fixture HTTP/DNS with real Chromium,
containers, persistence and cleanup. Qualify the default real DNS/TLS/fetch path
and trusted operator assembly separately, without activating production.
Reuse the existing preparation command and configured_browser_runtime; do not
build another broker, renderer, policy or authority layer.

Development qualification may enable an isolated temporary Core task service
with its own private database and fixed operator configuration. Never read live
credentials or modify live settings, conversations, services or databases.
No default AgentSpec, Mind route, browser interaction, downloads or release.

## Bounded qualification harness

- Add an explicit opt-in host harness, excluded from deterministic offline CI.
  Without its explicit flag, stop before DNS, Docker, preparation or Core startup.
- Fix one public documentation origin and one small HTML document path in the
  harness. No arbitrary URL, receipt, headers, cookies or credentials from tasks.
  Record the exact source and retrieval time; remote content can change.
- Prepare a fresh diagnostic-owned image/receipt with the existing verifier;
  assemble through configured_browser_runtime using the resulting private paths.
- Use actual OwnedResolver, verified TLS PageSession, DocumentRenderer and
  DockerHandle defaults. Do not inject a mock transport or resolver into the
  live-network case. Keep Chromium network-none and scripts disabled.
- Submit, claim and run browser_run through real TaskService/Runner and persist
  bounded evidence. Require exact origin/path/contract identity, source digest,
  instruction_trust=none, node/truncation metadata and confirmed cleanup.
- Exercise a fresh second task after cleanup to prove readmission. Use an
  independent contender for admission exclusion where practical.
- Keep deterministic timeout/cancellation/lost-ack tests in the existing harness;
  do not manufacture those faults through a public site's behavior.
- Failure remains failure: DNS/TLS/response-budget/MIME/site changes must be
  reported without relaxing policy, retries, certificate verification or bounds.
- Reinspect the reusable image and check container/child/admission cleanup.
  Remove only harness-owned labelled resources after proven cleanup. An unknown
  cleanup marker stays fenced and is recorded for operator investigation.

## Implemented host command

Run only on the trusted Linux qualification host with the previously qualified
source bundle, compiler and Docker already available. This command deliberately
contacts `https://example.com/`, the small public Example Domain informational
page, twice through the default adapter. It accepts no target override. A failed
first task stops qualification; the second fetch proves fresh admission rather
than retrying a failed request. Content and availability can change.

```bash
.venv/bin/python -m scripts.qualify_browser_operator \
  --allow-public-network-and-owned-containers \
  --bundle /absolute/path/to/qualified/bundle \
  --expected-bundle-digest QUALIFIED_SOURCE_MANIFEST_SHA256
```

Without the opt-in flag, execution stops before preparation, Core startup, Docker
or networking. The harness creates a new private directory under ignored
`runtime/browser-operator/`, prepares a fresh image with the existing verifier,
and uses init-only settings that ignore `.env`, environment overrides and secret
sources. Shared setup commands use a minimal explicit environment; Docker setup,
inspection, export and cleanup use the same fixed local socket as runtime and a
fresh private empty Docker configuration directory. Operator Docker contexts,
credentials, daemon selectors and loader hooks are not inherited. It uses a new private SQLite database and no HTTP listener or background
scheduler. It does not change application settings or start a service.

The printed `EVIDENCE=` path points to an exclusive 0600 bounded report. The
report includes retrieval times, task IDs, persisted bounded evidence, cleanup
confirmation and post-run image filesystem digest. Keep that report with the
exact Git commit and source manifest digest used. A passing report requires both
Core jobs, runtime shutdown, clear admission, no image-associated containers,
a stopped-image filesystem reinspection and diagnostic setup cleanup. Failure
details are limited to exception types and fixed Browser error codes; inspect
the private diagnostic database for further task state. This is a sample of one
public origin at one time, not general website compatibility or ongoing uptime.

After diagnostic success, the harness removes only its labelled setup resources
and image. It retains the private receipt, bundle, report and database as evidence;
that receipt is consequently no longer usable until a new operator preparation.
If runtime cleanup cannot be confirmed, it preserves the image and any admission
fence. Never truncate/remove the marker or infer cleanup from PID age. Investigate
owned resources without touching unrelated containers. Preparation failure uses
the existing preparation helper's cleanup and never guesses an owner from labels
on an unbound image.

## Operator readiness checklist

For a future separately authorized deployment, prepare a fresh verified image
and private receipt with `scripts.prepare_browser_worker`. Set the documented
Browser endpoint, receipt, bundle, runtime and shared admission paths together;
all enabled Core instances sharing the host browser capacity must use the same
canonical 0700 admission directory. Runtime/bundle paths must remain canonical,
receipt mode 0600, and the trusted source files, same-UID operator, filesystem
ancestors and Docker daemon must remain controlled. Do not use the diagnostic
receipt after its image has been removed.

The receipt structurally binds configuration and the prepared manifest; it is
neither a signature nor independent provenance nor a fresh scan of the current
image. Preparation verifies actual stopped-image bytes and modes; runtime checks
immutable image identity and configuration. A previous passing sample does not
replace validating prerequisites at activation. Unknown cleanup blocks readiness
and needs operator investigation; no automated reset is implemented.

Browser Worker remains disabled by default. Production enablement, a release,
and any Agent/Mind browser route require their separate acceptance scope. The
controlled eight-case fixture proof remains the evidence for cancellation,
timeout, lost acknowledgement and cross-process exclusion; the public harness
does not inject these faults or relax transport policy to make them pass.
