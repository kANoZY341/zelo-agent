# v0.15 — ECC draft Skill fixed-case evaluation

The user-selected second curated import is Everything Claude Code (ECC).
The four pinned ECC references and four Zelo-authored manual playbooks already
exist under the source-verified community candidate library. This slice adds
an *inert* deterministic grader for structured answers to tiny fixed scenarios.
It neither runs imported ECC scripts nor executes any model, Worker, Task or
Skill and cannot change the active Skill Registry.

## Authenticated operator endpoints

- GET /integration-candidates/community/ecc/{skill_id}/cases
- POST /integration-candidates/community/ecc/{skill_id}/evaluate

Accepted skill IDs: ecc_security_review, ecc_agent_evaluation,
ecc_ai_regression, ecc_architecture_decisions. Each suite returns three
Zelo-owned hypothetical engineering situations and a SHA-256 suite identity
bound to the exact reviewed playbook hash, pinned upstream source commit, fixed
case evidence and expected decisions. The GET response **withholds expected
decisions** but is not a secret exam: Zelo source is inspectable and can be
studied. It is a regression fixture, not an externally validated benchmark.

The operator supplies one canonical verdict per case, in the returned order:
pass, fail or unverified. Submission must include the expected suite SHA-256
and one harmless candidate label. Unknown, duplicate, reordered or missing
case IDs, invalid values, extra request fields, stale suite identity and
modified upstream sources fail closed. JSON duplicate keys and oversized
bodies are rejected before scoring. Input is capped at 8,192 bytes.

The response contains immutable SHA-256-bound evidence for the input answers,
the pinned suite and evaluated cases, including:

- Agreement count across the three fixed scenarios
- False alarms: a submitted answer rejects a fixture-labeled safe case
- Unsafe misses: a submitted answer passes a fixture-labeled unsafe case
- Unsupported overclaims: a candidate passes a case whose evidence is incomplete

A high agreement count **does not prove real agent reliability or quality**.
These are simple deterministic fixture decisions, not real prompts executed by
a model, observed task outcomes, independent security assessments, cost
measurements or statistically meaningful failure rates. The candidate label
is operator-provided and is not a trusted AgentInstance, SkillSpec activation
identity, Worker selection or proof of any model invocation.

The receipt carries literal false publication/runtime/Tool/automatic-promotion
flags. The service neither writes Task, Attempt, Approval or Audit rows nor
activates any Agent/Computer/Worker or imports ECC instructions as prompts.
It does not create a Skill Learning proposal or issue promotion authority.

## Gates before any real ECC activation

Record actual before/after agent outputs and independent evaluator results on
fixed tasks, compare a reviewed baseline and candidate under the same authorized
worker/AgentSpec/version/tool/Space identity, and measure real permission
failures, latency, tokens and cost. Governed Skill Learning review,
materialization, publication and runtime admission must separately bind an
operator-approved exact candidate and fail closed on stale/revoked predecessors.
No new skill should become active merely because a fixed fixture score is high.
