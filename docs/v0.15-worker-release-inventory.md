# v0.15 — Core Worker release-scope inventory (non-authoritative)

Status: **release HOLD**. Snapshot references audited Core source at
main commit 8866006ac58a37d9632c3e4de9fdbf8973055a0b on 12 October 2026.
Latest published release is v0.14.0.

This inventory is a conservative *configuration and source-registration*
observation, not an operational qualification or live Agent/Task/Tool permission.
The pure function in app/v015_worker_release_inventory.py accepts an already
validated Settings object, derives exact IDs/roles/capabilities from the
trusted WorkerDescriptor constructors, and returns a fixed eight-row record.
It does not instantiate runtimes, call models, read credentials or paths, make
network requests, issue GitHub actions, run imports, or invoke native Media.

## Observed default-registration boundaries

| Worker | Core source assembly | Default config / actual permission limit |
| --- | --- | --- |
| Research | Worker registry constructed at Core startup | Registered by default, but live source/tool/model admission and Task-bound authority remain independent |
| Python | Worker registry constructed at Core startup | Registered by default; no general host shell, network or arbitrary workspace authority inferred |
| API | Worker registry always constructed | Default endpoint allowlist empty. Registration does not admit any public API endpoint |
| Browser | Only registered if configured_browser_runtime returns a qualified runtime | Disabled by default. Enabled flag alone is insufficient: requires receipt, bundle, runtime, admission file and named endpoints |
| Computer (read) | Only registered if OpenBot backend configured | Default backend lacks the required supervisor URL and separate tokens; no persistent host computer read is inferred |
| Computer (named navigation) | Conditional registration after Computer backend + internal network/egress proxy/named HTTPS endpoints | Default disabled. Even configuration cannot grant click/type, shell, workspace writes, arbitrary navigation or credential access |
| Shell | Only registered if explicitly enabled and admission source validates | Disabled by default; enabled flag alone is insufficient. No unrestricted host shell |
| Media native reader | No Media Worker registered in app/application.py | Source and qualification fixtures do not supply a live Media Worker. Four refused native proofs exhausted; **no new proof authorized** |

The conservative record uses only the states registered_conditional_authority,
registered_no_approved_endpoints, disabled_by_default, configuration_incomplete,
configured_unverified, and not_registered_in_core. Every row explicitly has
release_qualified=false and new_authority_granted=false. The overall record
explicitly has release_ready=false and operational_proof_performed=false.

## Test evidence and limits

Six new side-effect-free inventory tests passed, including default-deny,
conditional configuration, fixed Worker identity, absent Media, no filesystem
probe, and no secret/endpoint/path disclosure.

The broader selected Core Worker regression list (registry, Python, API,
Research, Shell Core binding, Browser Core binding, Computer dispatch and the
inventory) produced 370 passes with seven developer-validation failures in a
fresh isolated worktree because its local virtual environment was absent.
A worktree-local independent environment was then copied strictly for test
qualification; an external nested directory symlink in that copy was removed,
as required by the existing fail-closed validation_manifest path-isolation
policy. The original seven tests were rerun **unchanged** and passed.
A final combined run from the now-isolated local virtual environment passed
**377 tests, 0 failures, 3 pre-existing warnings**. No validator logic was
modified and no external native qualification was run.

These checks cover Core contracts and simulated execution. They do not by
themselves prove real host networking, browser sandbox support, Shell VM lease,
an actual resident Computer backend or field-performance of Research answers.
Exact release-head full CI, deployment-specific worker proofs and independent
review remain separate. Do not turn configuration flags into WorkerAuthority,
SkillRegistry activation, new Tool grants or a release tag.
