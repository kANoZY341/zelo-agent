# v0.15 — Agent Computer Core control

## Goal

Place persistent per-AgentInstance computer ownership, grants, lifecycle and
human takeover under Zelo Core before any Agent receives browser/files/shell
execution authority.

This slice builds on `docs/v0.15-agent-computer-openbot-foundation.md`.

## Authority chain

```text
trusted AgentSpec
  -> AgentInstance exact snapshot
  -> persistent computer permission record
  -> owner-only AgentComputerService
  -> Zelo OpenBot adapter
  -> pinned OpenBot supervisor/computer
```

The backend never decides what an Agent may do. Core does.

## Persisted permission state

Each AgentInstance whose trusted spec declares a computer receives one immutable
ownership row:

- `enabled`
- `browser`
- `files`
- `shell`

All default to false.

Permissions may never exceed the immutable AgentSpec computer profile. Widening
a grant requires an active AgentInstance whose registry snapshot still exactly
matches the current trusted Agent Registry. Revocation remains allowed even when
an Agent has become stale or paused.

Disabling the computer is immediately authoritative in Core. When the backend is
configured, Core also asks the supervisor to stop that Agent's computer; a stop
failure is recorded but cannot roll back the revoked permission.

## Activity history

Computer control receives its own append-only per-AgentInstance event stream.
Current owner/system events include:

- permission changes;
- start success/failure;
- stop success/failure;
- revocation-triggered stop success/failure;
- take-control success/failure; and
- release-control success/failure.

Events contain bounded non-secret state/error codes. They never store credentials,
human-entered secrets, file contents, screenshots or terminal output.

## Owner control routes

Authenticated owner routes are:

```text
GET   /agents/{instance_id}/computer
PATCH /agents/{instance_id}/computer/permissions
POST  /agents/{instance_id}/computer/start
POST  /agents/{instance_id}/computer/stop
POST  /agents/{instance_id}/computer/take
POST  /agents/{instance_id}/computer/release
GET   /agents/{instance_id}/computer/events
```

These are the future Computer Panel's Core contract.

## Human takeover

Takeover requires all of:

- active/current AgentInstance;
- trusted AgentSpec browser support;
- trusted AgentSpec `human_takeover=true`;
- persisted Core computer enabled; and
- persisted Core browser permission enabled.

Release is deliberately still available when the Agent is paused/stale so the
owner can always return control safely.

OpenBot's handback state is preserved. After release,
`resume_snapshot_required=true` remains visible through Core so later Agent
browser mutation must first obtain a fresh browser snapshot.

## Non-goals

This slice still does **not**:

- add `computer_run` or any Agent-executable computer task;
- allow Mind or an Agent to call navigate/click/type/files/write/exec;
- give the computer backend authority to change Core permissions;
- add credential injection;
- add the Computer Panel to the parked UI;
- expose computer ports publicly; or
- allow fallback to the host machine.

## Next slice

Add a typed Computer Worker execution contract behind Capability Registry,
Skill Registry, Worker Registry/Supervisor, exact Agent execution identity and
the persisted permission intersection defined here.

The first executable surface should remain narrow and prove revoke/cancel,
takeover barriers, fresh-snapshot handback, audit and no-host-fallback before
broader browser/files/shell behavior is enabled.
