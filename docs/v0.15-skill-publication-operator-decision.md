# v0.15 — Immutable Managing Director review decision for one Skill candidate

**Status:** local Core development candidate, no runtime API, no merge execution.

This slice follows the durable exclusive proposal/version claim and the exact
PR/head/CI preview plus read-only, freshly queried GitHub evidence. It **only**
records the Managing Director's selection of one reviewed merge request for a
later, independently qualified publication action.

## Owner decision and persistence

`SkillPublicationOperatorDecisionService.record_approval` accepts an exact
claimed proposal ID, a frozen `MergeRequest`, the trusted `OperatorPrincipal`,
and the explicit confirmation string
`APPROVE_EXACT_SKILL_PUBLICATION_REVIEW`.

- A missing/incorrect principal or confirmation refuses before any GitHub
  request or database write.
- The separate remote verifier issues only GET requests, checks the claimed
  current Agent/Skill/proposal/artifact and exact PR/head/base, verifies current
  required GitHub CI and app identity, then repeats PR and local Core checks.
- A SQLite `BEGIN IMMEDIATE` transaction then revalidates the existing
  immutable claim and exact local merge-request identity before writing one
  new decision. No network await occurs inside the writer transaction.
- The decision binds claim/proposal identity, repository and PR number, exact
  head/base SHA, complete reviewed request digest and current provider CI
  evidence digest to the authenticated operator choice. A deterministic
  fingerprint covers those identities.
- Exact replay returns one existing immutable decision; an alternative
  request for the same claim or a second claim targeting the same PR is
  refused. Database uniqueness and triggers reject UPDATE, DELETE and
  `INSERT OR REPLACE` substitutions.
- A recorded decision may be retrieved as *history* even if the originating
  Agent is subsequently paused/revoked; it is never reusable as authority.

## Explicit non-authority

The strict response and database constraints force:

- `publication_authority=false`
- `external_merge_authority=false`
- `runtime_authority=false`

The confirmation is **approval for the next review stage**, not permission
to merge. No model Tool, HTTP route or Worker action is added here. The generic
learned-skill GitHub publication refusal remains enabled. There is no native
GitHub write, no auto-retry, no source import activation, no Skill Registry
mutation and no procedure execution.

## Remaining release gate

Before external publication is allowed in v0.15, implement a separate
approved publication-specific runner that verifies the exact immutable
operator decision, fresh GitHub state and CI, then atomically writes a
**before-side-effect fence**. Any timeout, connection failure or uncertain PUT
result must remain blocked; retries must reconcile the specific remote merge
receipt read-only, never send a second blind merge request. Bind exact Task
and actor execution identity and preserve the protected generic path refusal.

An approved decision alone is not a release receipt. v0.15 is still on HOLD
pending #166's broader Space, Worker and Media qualification gates; the four
Media native-reader proof attempts remain terminal refusals and UI #61 stays
parked.
