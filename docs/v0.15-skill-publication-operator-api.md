# v0.15 — Authenticated Core API for reviewed learned-skill candidates

**Status:** development-stage operator interface for v0.15 release closeout.
**Allowed:** exact reservation, read-only evidence, immutable review/fence decisions,
and one separately confirmed external merge attempt only when its default-off
operator setting and every service-side gate are satisfied.
**Not allowed:** autonomous publication, Skill activation, new Tool/Space grants
or generic learned-Skill merge bypass.

All paths require Zelo Core's existing `Authorization: Bearer <operator-token>`.
The bearer is verified by the existing `require_operator` dependency, not by
a caller-supplied username or a self-asserted principal. Unknown/invalid
identities fail before any artifact read, reservation or provider request.

## Routes and behavior

| Route | Effect | Trust boundary |
| --- | --- | --- |
| `POST /skill-publication/proposals/{proposal_id}/claim` | Persist one exact approved proposal/version reservation | Requires `expected_intent_fingerprint` and current accepted review/spec/registry; duplicate exact requests reuse immutable receipt |
| `GET /skill-publication/claims/{claim_id}` | Read immutable reservation | No tool, publication or runtime authority |
| `POST /skill-publication/claims/{claim_id}/preview` | Check exact reviewed `MergeRequest` (JSON body) | Local evidence only; no GitHub network |
| `POST /skill-publication/claims/{claim_id}/remote-evidence` | Recheck actual PR/head/base/provider CI using GitHub GET only | Requires configured publisher/CI, exact claim/registry and approval evidence |
| `POST /skill-publication/claims/{claim_id}/blob-evidence` | Attest immutable Git base/head, tree mode and approved artifact SHA-256 using GET only | Rejects changed PR, divergent ancestry, unexpected files, symlinks and malformed provider results |
| `POST /skill-publication/claims/{claim_id}/decision` | Persist one exact operator review selection | Requires `confirmation=APPROVE_EXACT_SKILL_PUBLICATION_REVIEW` and nested `merge_request` plus current live GitHub/CI checks |
| `GET /skill-publication/claims/{claim_id}/decision` | Read immutable historical selection | No current provider request, never transferable authority |
| `POST /skill-publication/claims/{claim_id}/dispatch-fence` | Reserve one exact no-send action fence after fresh GET evidence | Requires `APPROVE_EXACT_SKILL_PUBLICATION_FENCE_NO_SEND`; repeated exact reservation returns the same fence |
| `GET /skill-publication/claims/{claim_id}/dispatch-fence` | Read durable fence | No provider request or send authority |
| `POST /skill-publication/claims/{claim_id}/merge-once` | Attempt one exact external squash merge when explicitly enabled | Requires `MERGE_EXACT_APPROVED_SKILL_ONCE_WITHOUT_RETRY`, exact approved Task/claim/fence, strict GitHub policy and before-PUT durable attempt; no retry on uncertainty |
| `GET /skill-publication/claims/{claim_id}/merge-attempt`, `/merge-receipt`, `/merge-failure` | Read durable history after any outcome | Available even after dispatch is disabled; no provider request or Skill activation |

Claim request example (digests/IDs are placeholders, not runnable values):

```json
{
  "expected_intent_fingerprint": "<approved-64-hex-SHA256>"
}
```

Decision request (schematic):

```json
{
  "confirmation": "APPROVE_EXACT_SKILL_PUBLICATION_REVIEW",
  "merge_request": { "<existing-frozen-MergeRequest-fields>": "<reviewed-values>" }
}
```

Pydantic rejects unexpected fields, invalid digests, malformed nested MergeRequest
and wrong confirmation text before execution. Owner authentication is mandatory
even for read-only routes. Backend configuration does not default to a live
GitHub action: when `promotion_repository` is absent, remote inspection and
decision routes return HTTP 409 without contacting GitHub.

## Security limits and remaining work

- All methods reuse reviewed Core Skill/Agent authority, existing
  serialized SQLite writer transactions, migration 0043 exclusivity and
  migration 0044 append-only operator decision history.
- Preparation and historical reads use bounded provider **GET only**. The
  default-disabled `merge-once` path is the sole possible PUT; its service
  commits a nonretryable attempt before sending and verifies the exact result.
  There is no merge Tool, release Tag path or Skill Registry mutation.
  Provider diagnostics, CLI auth data, raw blob bytes and unrestricted paths
  are never returned.
- A claim, preview, review decision or fence never grants merge or runtime
  authority. The generic protected learned-procedure merge refusal remains.
  The dispatch route requires a separate owner confirmation and every current
  source, CI, provider policy and exclusive attempt gate.
- Provider-side uncertainty remains terminal with no blind retry. Historical
  reconciliation and receipt linking are separate read-only paths; a positive
  merge receipt is not Skill activation. Live provider qualification and the
  final v0.15 release gates remain open.
- Media is deferred from v0.15 and remains unavailable. UI PR #61 remains
  parked.

This interface is not part of published v0.14.0. Full exact-head CI, independent
review, integration and v0.15 scope audit in issue #166 remain mandatory.
