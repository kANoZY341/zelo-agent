# v0.12 Push-to-talk voice

## Goal

Add a local, replaceable speech layer around the existing Zelo conversation path.
Voice is an input/output modality, not a new agent or authority system.

## Canonical flow

```text
browser push-to-talk
  -> loopback-only Voice Service
  -> STTProvider (default: faster-whisper)
  -> transcript text
  -> existing Workspace conversation turn route
  -> existing Zelo Mind -> Core path
  -> assistant text
  -> loopback-only Voice Service
  -> TTSProvider (default: sherpa-onnx Supertonic 3)
  -> WAV playback in browser
```

## Initial providers

- STT: faster-whisper, multilingual Whisper, CPU int8 by default.
- TTS: sherpa-onnx Supertonic 3, multilingual, speaker/style selectable.
- Arabic and English are first-class target languages.
- Providers are replaceable. A future Nabra Arabic voice, Piper, Kokoro, cloud service,
  or custom voice must implement the same STT/TTS boundaries rather than changing Mind/Core.

## Authority boundaries

- The Voice Service has no Core operator token.
- Workspace authenticates to it with a separate server-only `ZELO_VOICE_SERVICE_TOKEN`;
  direct browser requests cannot invoke speech model work.
- It cannot create tasks, approvals, Campaigns, schedules, projects, or goals.
- It only converts audio <-> text/audio.
- The transcript enters Zelo through the same conversation endpoint as typed text.
- Push-to-talk is explicit. No wake word or always-listening microphone exists in this slice.
- The service binds only to loopback.

## Model/runtime files

Large speech models belong under ignored `runtime/voice/`, never Git.
The first Supertonic model directory is expected at:

`runtime/voice/models/sherpa-onnx-supertonic-3-tts-int8-2026-05-11`

The service lazily loads providers so Core CI does not need voice model packages or weights.

## Local setup

Voice dependencies and model files are optional and stay outside the normal Core
runtime dependency set.

```bash
./scripts/setup_voice.sh
./scripts/run_voice.sh
```

The setup script installs only into the repository virtual environment, creates a
separate random Voice Service token in the ignored local `.env` when missing, downloads
the Supertonic model into `runtime/voice/models/`, and preloads the configured
faster-whisper model into the same ignored runtime tree. No sudo or system service
installation is used.
