# Zelo Core v0.14 — Agent activation and evaluation gates

## Status

Seventh and final bounded implementation slice of v0.14 Agent Factory before
release preparation.

Merged prerequisites:

- registry foundation: PR #47;
- project-bound lifecycle: PR #48;
- bounded task delegation: PR #49;
- generic agent execution identity: PR #50;
- durable organizational hierarchy: PR #51;
- hierarchy-aware permanent child creation: PR #52.

## Goal

Prevent a trusted AgentSpec from becoming operational merely because it parses.

Activation must be deterministic, inspectable and fail closed against the actual
bounded Core surfaces available to the process.

The activation gate is not model judgment and does not grant authority by title.

## Policy

The activation evaluator checks each active AgentSpec against:

- available Core task kinds;
- available Zelo-owned tools;
- configured worker requirements;
- developer-task worker binding;
- review-required contract shape;
- VP/Director/Manager organization authority;
- Specialist permanent-hiring boundary.

The policy version is:

`zelo-agent-activation-policy-v1`

## Executive gate

An active VP, Director or Manager template must explicitly declare all of:

- `allow_subagents = true`;
- positive bounded `max_subagents`;
- `organization_hire` permission;
- `organization` procedure.

This does not grant worker or tool authority. It only permits the already-bounded
hierarchy child-creation path to consider that template eligible.

## Specialist boundary

A Specialist Agent may never declare `organization_hire`.

A Specialist may still receive separately bounded temporary delegation authority
when an AgentSpec explicitly allows it, but temporary delegation does not become
permanent reporting authority.

## Execution surfaces

Every declared task kind and tool must exist in the current trusted Core
surfaces.

A template declaring `developer_run` must also declare an explicit
worker-neutral `WorkerRequirement`.

If that requirement cannot be satisfied by the configured enabled WorkerRegistry,
activation is rejected.

## Review contract

When `review_required = true`, the template must also declare:

- `developer_run`;
- `code_review` capability;
- `review` procedure.

Independent reviewer acquisition remains an execution-time worker-selection
boundary. The activation gate verifies the trusted template contract rather than
performing a live worker execution.

## Evidence

Each evaluation records:

- agent ID and version;
- registry version;
- organizational level;
- exact runtime-surface digest;
- deterministic pass/fail/not-applicable checks;
- sorted failure codes;
- evaluation digest.

The report records all active-template evaluations plus one report digest.

The runtime-surface digest fingerprints:

- available task kinds;
- available tools;
- configured WorkerDescriptors.

Changing those surfaces changes the evidence digest even when the same template
still passes.

## Draft candidates

The evaluator exposes a candidate-template path that can evaluate a trusted draft
AgentSpec before its lifecycle is changed to active.

Draft templates do not enter the active startup report and cannot be bound by
AgentFactory until explicitly activated.

## Startup gate

Application assembly:

1. builds the trusted tool and developer worker surfaces;
2. builds the trusted AgentRegistry;
3. retains the existing registry structural activation checks;
4. evaluates all active AgentSpecs;
5. fails startup if any active template is rejected;
6. exposes the accepted report in application state.

The operator can inspect the current evidence through:

`GET /agent-factory/activation`

The route is operator-authenticated.

## Non-goals

This slice does not:

- let models author or activate AgentSpecs;
- create new executive or Specialist templates;
- run worker preflight commands during activation;
- grant authority because a title is VP/Director/Manager;
- change organizational assignments;
- create children;
- change task, worker, tool, approval, scheduler, promotion, merge or release
  authority;
- write memory automatically.
