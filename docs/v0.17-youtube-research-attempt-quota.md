# v0.17 — Rolling Research Worker-attempt cap (separate from Task admission)

This stage is stacked on the exact opt-in YouTube Specialist and the
Project-scoped eight-new-Task/24h admission quota. It adds a *different*,
persistent safety boundary for actual Worker dispatches and retries.

## Enforced claim-time limit

Within one Project + trusted `youtube_topic_researcher` AgentSpec identity,
Core allows at most **12 started Research Worker attempts** per rolling 24 UTC
hours. The records are counted from the existing `task_attempts` table joined
to immutable Project/Agent execution identity in `tasks`. This includes
failed, cancelled, interrupted, completed and previously retired/recreated
AgentInstance histories. Restart does not reset the limit.

The enforcement happens inside `TaskService.claim()`'s existing serialized
SQLite writer after normal persisted AgentInstance/Project/Registry/Campaign/
delegation identity and Worker-selection revalidation, and directly **before**
inserting the next `TaskAttempt`. It applies only to Task kind
`research_run` bound to the optional YouTube Specialist. Generic/unbound
Research and other AgentSpecs are unaffected.

When exhausted, the claim fails closed: the pending Task is marked CANCELLED
with `youtube_research_attempt_quota_exhausted`, an `execution_denied`
audit event is written, and **no** new `TaskAttempt`, `execution_started`
event or Worker dispatch occurs. An operator can retry the cancelled Task
later, but the next claim must pass the *same* attempt budget; Task retry does
not escape the guard. The count uses serialized TaskAttempt creation so
competing claimers cannot oversubscribe it.

## Operator-only projection

Authenticated `GET /agents/{instance_id}/research-attempt-quota`
returns the Project, observation time, trailing 24h window, count and
remaining attempts, plus exact invariant flags marking this as a read-only
measurement rather than an authority grant. It refuses missing or unrelated
AgentInstance identities. A separate `research-quota` endpoint continues to
report the eight new-Task admissions, not attempts.

## Boundaries

This is **not** model token metering, an actual currency spending ceiling,
live output-quality certification or a Campaign delegation budget. Each
admitted Task may run existing bounded model steps and read-only Tools;
12 attempts are still meaningful compute work. Further per-model usage and
cost accounting need trustworthy receipts integrated with the existing
Campaign control plane. No YouTube publishing, account credentials, Shell,
Browser, Computer or Agent hiring is introduced.

No new database table or separate policy authority was needed. No
Task/Agent/Worker is auto-created or enabled; the upstream YouTube Specialist
remains off by default without the exact operator-reviewed startup digest.
UI #61 is parked and REA runtime/Media refusal restrictions are unchanged.
