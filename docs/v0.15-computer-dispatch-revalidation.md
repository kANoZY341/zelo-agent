# Computer Worker — revalidation immediately before backend dispatch

This fix strengthens the existing Computer Worker permission boundary while the
OpenDots Space/resource enforcement work remains unfinished. It activates no
new Worker, tool, Space, file root, endpoint, model or external service.

## Reproduced gap

ComputerRuntime.run checked the execution snapshot before awaiting the computer
control-state lookup. If permissions were revoked, the backend identity changed,
or an approved navigation endpoint changed during that await, the code could
still dispatch a file/browser action. A later check rejected its result, but did
not prevent the already-started operation. The synchronous started-event callback
was another place where trusted Core state could change before dispatch.

A regression using a real migrated isolated Core database and a fake computer
transport reproduced the file-read call after permission revocation. No live
browser, host resource or external network was accessed during reproduction.

## Correction

The worker now checks its existing exact execution binding again immediately
before calling read_action or navigate_action, after both the control-state await
and the started-event callback. A stale permission, backend identity, endpoint
registry or navigation policy is refused with the existing
computer_execution_spec_stale error before the backend operation is called.
The earlier task/admission checks and post-result check remain intact.

Tests cover all four read actions and named-endpoint navigation, at both
suspension/callback boundaries, for revoked permissions and changed backend
identities. Separate navigation tests cover endpoint-registry drift. They assert
that the resource operation was never dispatched, not merely that the eventual
result was an error. Existing successful read/navigation tests remain required. Additional positive
cases verify each unchanged action dispatches exactly once; a real Core
Runner regression verifies revoked work records a failure without a result
or resource operation. The transport is fake in these tests.

## Scope and remaining limits

This closes the demonstrated Core dispatch gap. It does not make a database
check and a remote computer operation atomic, retroactively cancel an in-flight
request, or qualify full Space permissions. Backend-local resource mediation,
revocation during remote execution, and grant/lease binding at every relevant
use point still require the separately reviewed Space enforcement work in #131.
A started audit event records an attempt, not proof that resource access occurred.

No database migration, API schema, host configuration, live computer permission,
REA policy, Media qualification attempt or parked UI #61 is modified by this fix.
