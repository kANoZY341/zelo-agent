# Space HTTP retry after activation revocation

Extend the disposable two-Computer qualifier at the current main source. Keep its
private database, loopback server, fixed Docker images, and cleanup unchanged.

1. Create a third, distinct child Space activation for a file read of a missing
   fixture path. Submit it through normal Core HTTP and wait for a failed Task.
2. Revoke that activation through Core HTTP. Retry the failed Task through the
   normal HTTP route; require `computer_space_activation_invalid`, no new Task or
   attempt, and the original failed result.
3. Preserve the valid child activation for the existing read/list and later
   delegation revocation checks. Test the helper and real in-process Core route,
   run the native host qualifier, then independently review and use exact-head
   CI before integration. Do not change production grants or release scope.
