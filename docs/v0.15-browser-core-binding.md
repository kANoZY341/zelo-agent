## Entry gate and scope

The entry gate is complete: renderer integration PR #66 merged after exact-head
Astra Medium review and full CI (**1,538 passed, 2 skipped**). The merged tree
exactly matches reviewed/tested commit `ba188c3`. This plan does not itself activate a worker,
change the published v0.14.0 release or touch parked UI PR #61.

The renderer already composes approved document fetching, isolated native-sandboxed
Chromium, bounded untrusted DOM text and cleanup-confirmed evidence release. The
next slice connects that path to Core tasks using the existing worker registry,
Supervisor, Agent execution identity, claim/retry and Runner boundaries. Reuse the
qualified implementation through a narrow adapter; do not create another renderer,
browser control API, policy authority or scheduler.

## Trusted operator setup

Default configuration disables Browser Worker and has an empty browser-origin
registry. API endpoints do not automatically authorize document browsing. Only
trusted application assembly may configure canonical approved HTTPS origins,
verified bundle, exact local sha256 image, captured manifest, generated seccomp
profile and one persistent private admission directory shared across processes.

Provide a separate explicit operator preparation path for a reusable local image
and its content-verified receipt. Runtime never builds, pulls, chooses image tags
or removes that reusable image. Any serialized operator receipt is configuration,
not a signature or independent provenance claim. Validate its schema/bounds and
all contract identities; retain the stopped-image filesystem verification gate.
No model/task field may select receipts, images, paths, mounts, flags, Docker
contexts, profiles, runtime directories or policy. No system-service installation,
production database modification or live `.env` update is part of development.

## Task and persisted execution identity

- Introduce a narrow `browser_run` input: approved endpoint ID, strict relative
  document path, and bounded timeout only. No absolute URL, query, method, header,
  cookie, credentials, navigation, script, screenshot, clicks or downloads.
- Add typed BrowserExecutionSpec and result models. Bind exact endpoint registry/
  origin, worker selection, complete RendererContract digest, renderer/broker/
  resource identities and prepared image/artifact/profile identity into persisted
  task authority and action hashing. Task callers cannot author these bindings.
- Preserve original source origin/path/digest, full contract and broker policy
  digests, node count, truncation and `instruction_trust="none"` in bounded evidence.
  DOM text is not a CSS visibility or complete-page claim.
- Extend the next task migration and immutable database guards without weakening
  existing kinds, Agent execution bindings, campaign/delegation scope or approvals.
- On retry, select and bind fresh trusted configuration. At claim and again in
  Runner, revalidate persisted identity against current worker/configuration;
  drift fails closed before DNS, Docker or pipe work. Reuse API/Python patterns.
- Add a narrowly described worker authority/capability. Register it only when all
  explicit operator prerequisites validate. Do not add a default AgentSpec,
  department, Mind routing surface or broad browser authority in this slice.

## Lifecycle and availability

One canonical AdmissionController/ResourceOwner remains the sole cross-process
browser capacity boundary. Core concurrency counters cannot replace its lock or
crash marker. The complete renderer contract is admitted before DNS, fetch or
container creation. Every execution constructs a fresh one-shot renderer while
sharing the same trusted persistent admission directory.

Propagate cancellation and task deadlines through the composed job. Return or
persist successful evidence only after HTTP/DNS, container, local CLI children and
reader tasks have confirmed cleanup. Unknown cleanup remains fenced; task retry,
application restart, database state or TTL cannot silently clear the marker. Do
not infer ownership from stale PIDs or remove unrelated resources. Explicit
operator fence reconciliation requires its own design; do not invent it here.

Keep native Chromium sandboxing, private pipe/blank context, scripts disabled,
no-network/read-only/nonroot/cap-drop ALL/NNP and qualified cgroup/profile limits.
No privileged or no-sandbox fallback. Keep deterministic CI offline; Docker tests
remain explicit host opt-ins. Do not expose browser internals through task results.
