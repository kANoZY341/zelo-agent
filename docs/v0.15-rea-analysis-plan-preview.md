# REA — read-only Core analysis plan preview

This phase follows the source-owned offline target qualification (#126) and
operator-selected append-only target ledger (#127). A *selected* inert target
is not an executable target: its hashes were asserted by an operator and Core
has not independently read or authenticated its bytes. The upstream REA 6.0
catalog has 139 names but zero Core grants; only the fixed harmless two-file
fixture has a measured source-built static MCP runtime proof.

## Operator-visible endpoint

With an authenticated Zelo operator bearer token:

`GET /integration-candidates/rea/operator-targets/{snapshot_id}/analysis-plan`

The endpoint reads one active, non-revoked, operator-asserted target selection
from Core's existing SQLite store, checks the current draft REA specialist
AgentSpec against the unchanged active Agent Registry, and verifies the pinned
139-tool catalog and existing WorkerAuthority policy identity. It produces
one bounded deterministic review projection with hashes of the *claimed*
target/receipt, bounded claimed file counts/bytes, pinned source-manifest
identity, draft agent specification and current policy identity.

The response explicitly identifies `target_validation=operator_asserted_unverified`,
`agent_lifecycle=draft`, `tool_qualification=fixed_fixture_only_not_target_qualified`,
`approval_authority=false`, `task_created=false`, `agent_activated=false`,
`worker_registered=false`, `tool_grants=[]`, `may_execute=false`, and all five
required refusal reasons. It grants no task, tool, Worker, browser, computer,
network, credential, native execution or target access. The output is not
persisted and cannot be used as an approval, runtime identity, capability,
lease or credential. The fingerprint is a checksum, **not a signature**.

A missing selection returns 404. A revoked selection returns 409. Tampered
saved selection metadata or catalog/registry drift refuses with generic 503;
no local file paths or internal error details are exposed. Only GET is
implemented; the existing authenticated selection/revoke API remains separate.
If selection is revoked after a plan is displayed, that cached plan must be
considered stale and still cannot grant any permission. A later execution
system must revalidate revocation at claim *and* at runtime and must never
infer authority from possession of this preview.

## Execution remains blocked

No analyzer or REA MCP process is launched. Core does not import offline
`rea_target_admission` or `rea_target_preflight` libraries, access snapshots,
create a task or reserve any lease; the previous no-runtime-import regression
continues to pass. The live Agent Factory, Tool/Capability/Skill Registry and
WorkerAuthority profiles remain unchanged. UI PR #61 and four exhausted Media
native-reader attempts remain untouched.

The next separate gate must establish an independently qualified, no-network
source-owned static Worker with exact source/tool/runtime identity, deliberate
Core approval and bounded exclusive execution lease, trusted target/content
verification at claim time and before target access, durable revocation
checks, limited evidence projection and provable owned-container cleanup.
Until those steps are passed in order, no REA analysis of arbitrary admitted
targets is allowed.
