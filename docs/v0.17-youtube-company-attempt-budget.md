# v0.17 — Whole-company Research Worker attempt budget

This follow-on protects the **real opt-in** YouTube VP → Director → Manager →
Specialist hierarchy created from trusted Zelo Active AgentSpecs in PR #161.
It adds an actual persisted, automatically enforced, shared compute-attempt
budget. It does **not** infer model tokens, guarantee financial expenditure,
grant new tools, or permit autonomous hiring or publication.

## Exactly what is counted

The team has at most **24 started Research Worker attempts per active Project
over the previous 24 UTC hours**, counted across all four trusted Role IDs:

- `youtube` — VP
- `youtube_content` — Director
- `youtube_research` — Manager
- `youtube_script_writer` — Specialist

The existing SQLite `TaskAttempt` records are joined to Core's immutable
Task-bound Project ID and AgentSpec identity. Failed, interrupted, cancelled,
completed, retried and retired/recreated AgentInstance histories **all count**.
An operator cannot reset the count by replacing one AgentInstance, retrying
the same Task, or restarting Core. Another Project has its own budget.

Claims for all four roles use the *same* rolling limit; there is no separate
per-executive bucket. The scope is the Project and the four exact trusted
Agent IDs, not a YouTube channel, social account or Campaign accounting
resource. More than one Campaign in the Project uses the same limit.

## Enforcement, including competing claimers

The guard runs in `TaskService.claim()` under the **existing serialized SQLite
writer**, after the Task's entire registered AgentSpec, live Project,
active Campaign, exact Organization hierarchy, ancestor Delegations and
owner-bound reservations have been revalidated. It runs immediately before
a new `TaskAttempt` is created.

When the count has reached 24, a pending Task is marked **CANCELLED** with
`youtube_company_attempt_budget_exhausted`; the normal `execution_denied`
Audit event records this refusal. No new Attempt, `execution_started`
event or Research Worker dispatch can occur. An operator may request a retry
later but the next claim must independently satisfy the same rolling guard.
Competing claims cannot both consume the 24th slot.

This is separate from Zelo's other Core protections such as Task capacity,
Worker selection, model timeouts, step/tool budgets, Campaign reservation
validation and revocation. Existing noncompany Research, Coding and the
standalone `youtube_topic_researcher` pilot are **unaffected** by this rule.
The pilot retains its separate fixed 8-new-Task/12-Worker-attempt limits.

## Operator-only Project budget visibility

`GET /projects/{project_id}/youtube-company-attempt-budget` is protected by
Core's existing owner bearer-token auth. It returns the Project status,
observed UTC time and cutoff, counted/remaining attempts, precise eligible
roles, whether this process has the exact reviewed company registry
enabled, and strict boolean limitations showing that this read-only
view creates no resource grant or monetary guarantee.

No application startup, HTTP GET, source import or model text creates an
Agent, Campaign, Task, Worker instance, Tool grant, new Role or Space
permission. The company remains default-disabled without a separate
operator-selected full-registry SHA-256. This feature does not change
whether an AgentSpec can be activated.

## What still remains

The 24-attempt cap **does not measure** prompt/completion tokens, wall-clock
energy, provider prices, actual incurred currency, or downstream external
service charges. The existing `agent_steps` Campaign reservation is
*authorization proof*, not automatically committed measured usage. The
Managing Director must explicitly review any full Company bootstrap,
Campaign reservations and future external publication. A verified
provider-usage/currency ledger and cost-based hard ceilings are still
required before autonomous spending or publishing.

Validation covers all four real Role Task claims through the existing
TaskService, durable 24/24 cutoff refusal, retry and cancellation, concurrent
claim serialization, independent Project and generic Research isolation,
operator-only read-only HTTP projection, strict no-authority flags, and
permitted rolling window expiry. Require independently reviewed code and
exact-head/preceding post-merge GitHub full CI before integrating.
UI #61 stays parked, REA inactive, Media native-reader retry limit unchanged.
