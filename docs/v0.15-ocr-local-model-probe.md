# v0.15 — Explicit local Ollama probe for Open Code Review calibration

This separate opt-in CLI builds on the four-case synthetic Open Code Review
calibration. It reuses Zelo's existing `PinnedLocalOllamaProvider`, typed
`ModelRequest`, and digest-bound fixed-case scorer. It **does not** create a
reviewer Worker, change the default Agent Factory, register a Skill or Tool,
or mark a PR approved.

## Opt-in command

From this trusted Zelo checkout, with an already-installed local Ollama
model and without interfering with a running production CI check:

```bash
.venv/bin/python -m scripts.evaluate_ocr_draft_local \
  --model qwen3:4b-instruct \
  --timeout 30 \
  --allow-local-ocr-probe
```

Without the explicit `--allow-local-ocr-probe` flag, the CLI refuses before
constructing any provider. Valid per-case deadlines are 2–45 seconds.

The CLI removes inherited HTTP proxy variables in its own process; the
existing provider connects to the fixed loopback Ollama URL and uses trusted
local-model GGUF metadata qualification and SHA-256 digest, including a second
identity check after model use. An OCR-specific 512-token generation cap
replaces ECC's insufficient 64-token verdict cap, while every response is
limited to 4,096 UTF-8 bytes; the exact outbound limit is regression tested.
Neither local-model metadata nor loopback
configuration proves the Ollama daemon cannot make its *own* external
requests. Real sensitive prompts need a separately enforced daemon/host
no-egress test. No daemon configuration is modified by the CLI.

## What is actually tested

The fixed Zelo-authored prompts show a demonstrated path-boundary bug,
a pagination off-by-one bug, an independently verified public allowlist and
one storage handler lacking enough middleware evidence. The prompt does not
embed imported upstream code or arbitrary untrusted files. Each local model
response is requested with a strict JSON output schema and collected only
for offline scoring by `evaluate_ocr_fixed_cases()`.

A successful probe receipt contains exact model name/digest, pinned upstream
commit and test-suite fingerprint, four SHA-256 raw-response hashes, each
observed duration and available token usage, the fixed-case matched/missed/
unexpected/invalid metrics and explicit false authority flags. The raw
model output and full prompts are never printed, persisted to Zelo Memory
or admitted to Mind.

A malformed yet bounded raw model response is counted by the fixed-case
scorer as an **invalid review**; it is not silently treated as a clean
negative. Model identity drift, missing local GGUF metadata, remote/cloud
model names, excessive output, invalid metrics, generation failure or changed
pinned sources **refuse** the entire probe result.

## Interpretation and limitations

These are four known *synthetic* cases and expected path/line/severity/category
labels, not a real changed-Git-repository evaluation. Matching labels cannot
prove a model's natural-language claim is semantically correct. A high
synthetic score does not authorize autonomous code review, merge, PR comments,
Tool/Space access or Skill publication, and does not replace independently
qualified Coding review.

Actual adoption requires independently graded real diffs, exact
Task/Attempt/Reviewer identity, false-positive and false-negative analysis,
a bounded external-call/permission plan and a separate operator-approval
decision. Preserve UI PR #61 as a draft, REA runtime inactive, Media native
reader refusal budget and all earlier CI/merge gates.

## Qualification

`tests/test_community_review_local_model.py` uses a fake, async typed
ModelProvider: no model host is contacted by CI. Tests verify all four
prompts, scored outputs, invalid JSON classification, wrong model/provider
refusal, source/metadata drift, response bounds and digest tamper resistance.
A real local observation is a separate explicit opt-in experiment after CI
capacity permits it. No scheduler or background automation is installed.
