# v0.16 — Offline WhatsApp reply intent and operator decision

This is a private Core-only follow-up to the verified text admission in PR #346. It has no ASGI route, Meta credential, webhook listener, provider send, delivery receipt, Worker task or automatic approval. The published release remains v0.15.0.

Ahmad may prepare the exact saved assistant reply from one verified WhatsApp text turn. The service rechecks the verified message fingerprint, turn text digest and reply-only action, immutable thread binding, selected App Secret identity and account revocation inside the same serialized SQLite transaction as the prepared-intent insert. The prepared record stores only opaque account/recipient/thread/message identities, turn ID and reply digest; it does not copy reply text or raw provider IDs. The existing Mind turn remains the source of reply text.

One `approve` or `reject` decision may be appended for that exact intent. Exact retries return the frozen record; conflicting retries fail. Account revocation blocks preparation and decision but preserves historical rows. The intent and decision tables are `WITHOUT ROWID`, append-only and protected against `INSERT OR REPLACE`, including a changed intent fingerprint for the same verified turn. A database trigger also checks that the verified message, turn and bound account/recipient/thread match.

An approval is **not** delivery authority. No code in this slice calls Meta or claims sent, delivered or read state. A future sender must separately qualify credentials, provider policy, outbound approval, retry and status accounting, and must recheck account revocation and exact text at send time. A live webhook and account onboarding also remain separate gates.

Verification covers exact preparation and decision retries, approval/rejection conflicts, unverified and task-bearing turn refusal, empty or edited reply refusal, forged ledger identity refusal, revocation, SQL mutation/replace guards, populated `0052` upgrade, affected migration/channel regressions, review and exact-head/post-merge CI.
