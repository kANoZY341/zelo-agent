# v0.15 — Task-bound Space file mediation

This **stacked, Core-only** slice depends on the staged Space registry/owner
confirmation in PR #145. It adds a *real read use-point*, but it is **not
wired to an autonomous Worker or a public API route**. It does not activate
OpenDots, REA, Media, Browser, Terminal, Memory, or learned skills.

## New trusted use-point

`SpaceFileReadGateway.read(execution, activation_id, relative_path)` requires
a real, still-running `TaskService.claim()` Computer task. Core reloads the
actual Task, current running Attempt, exact persisted AgentExecutionBinding,
ComputerExecutionSpec, bound path and Worker capability and compares them to
the passed execution. The task must have a current active AgentInstance whose
registry/spec matches, an active Project, `computer_read` capability and
separately owner-enabled file access. The gateway refuses delegated executions
until delegation can be revalidated under this same contract.

A distinct operator-reviewed confirmation must be current, unrevoked,
unexpired, match the exact AgentInstance/spec/registry/project/Space/resource
and original intent, and have `read` in both intent and registered allowed
operations. Paused/resumed/retired identity, revoked/retired resource, changed
root inode or modified permission binding always deny.

Before touching files the gateway checks the live backend human-control state,
refusing human takeover, pending control requests, transitions and unsafe
resume state. It revalidates the full Core authorization **after** that await,
so a revocation or permission change during the lookup denies the read.

The gateway holds the existing SQLite `BEGIN IMMEDIATE` write transaction
**across** authority checks, descriptor-relative file opening, bounded
content read and safe audit event. This serializes Core writer revocations,
project and agent changes, and cancellations with the file read. A revocation
that commits *before* the transaction's authorization point denies access;
a concurrently requested revocation waits until this bounded operation ends.
No asynchronous I/O occurs inside the critical section.

## Filesystem restrictions

- Root is constructed entirely from `runtime_dir/spaces/<project ID>/<Space
  ID>/<resource ID>`; no user path chooses the host root.
- The directory root is opened using `O_DIRECTORY|O_NOFOLLOW` one component at
  a time; the final root's actual file descriptor must match the registered
  device/inode. All below-runtime directories must be owned by the Core UID,
  not group/other writable, and never symlinks. The entire opened FD chain
  is re-attested after reading to reject a directory moved during access.
- Relative path has at most four canonical ASCII segments and 255 total
  characters, with a text-only extension `txt/md/json/csv/log`. Dot-path
  traversal, absolute paths, URL encodings, backslashes, nested symlinks,
  device files and FIFOs never get opened as readable files.
- Final leaf opens `O_NOFOLLOW|O_NONBLOCK`, must be a single-linked regular
  file owned by Core, not group/other writable, at most 65,536 bytes.
  Verify FD metadata before/after,
  final directory entry's identity, exact read length and strict UTF-8.
- Result is only a bounded local text/byte-count/digest receipt. It is not
  automatically admitted into Zelo Mind's context. An audit event records
  Task/Attempt, activation and resource IDs, path digest, content digest and
  byte count—not source text or raw path.

## Important exclusions

The existing OpenBot Computer Worker still uses its own backend and controls.
This gateway **does not** silently redirect all `files_read` Worker actions to
Core's host or override their backend paths. Exposing it to execution requires
a distinct reviewed task routing contract, use-point admission and negative
tests proving alternative Tool/Computer paths cannot evade the grant. Browser
and Shell rights are not inferred from a Space. No new model-facing tool or
operator file-read route is registered.

## v0.15 R1 follow-up: file listing as a mediated Core Task

The prior isolated gateway/read proof is retained above as historical
design evidence. An additional real `files_list` Task route now uses the
same running Attempt/AgentSpec/permission/human-takeover barrier, including
the SQLite writer lock across validation, bounded descriptor-relative
enumeration and the non-content audit. Its approval requires the `list`
operation on the intent and resource (independent of `read`). It returns
canonical relative names and safe metadata only, never file content,
without falling back to the unrestricted Computer backend. Operations on
Browser, Terminal, Memory, writes and delegation remain unqualified.
