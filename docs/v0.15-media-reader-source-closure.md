## Closure questions before implementation or another native input

1. Authenticate the complete distribution source revision and patch series:
   signed source descriptor and source-archive hashes, relationship to the
   reported Git tree, and the exact files/configuration built into the observed
   `dpkg-deb`. A matching version string or source tree alone cannot establish
   binary membership.
2. Name a literal, finite source-file manifest for initialization and option
   handling, `--fsys-tarfile` dispatch, `DPKG_TAR_PASSTHROUGH`, decompressor
   selection, legacy/control paths, memory and thread queries, and build-time
   feature switches. Record every required include/helper and license. Any
   unlisted edge returns to review; no recursive fetch or current-upstream
   substitution.
3. Bind the Reader image's loader and seven other pinned objects to verified
   package members, notices, aliases and actual loaded-byte identities; test
   symbol/version/ABI behavior inside the isolated image. The existing ELF
   declaration graph does not settle this.
4. Establish the real eight-archive member-format matrix without claiming a
   parser success from `dpkg-deb` exit zero. The existing USTAR adapter rejects
   GNU/PAX, sparse and legacy forms. A refusal requires a separately reviewed
   parser/policy revision, never a permissive fallback or archive extraction.
5. Connect an authenticated, stable archive descriptor to the exact fixed
   Reader command, bounded tar stream, USTAR inventory, manifest binding and
   complete owned cleanup. Input, decompressed output, member count, memory,
   task count, CPU, time, stdout/stderr and retained bytes each need independent
   enforced limits. Saturation, SIGPIPE, cancellation, cleanup ambiguity or
   unsupported format permanently refuses that attempt even if parent exit is 0.

## Proposed bounded next work, subject to separate review

**A. Source-closure proposal, with zero requests.** Inventory the retained
15-file corpus and official source metadata read-only. Produce the literal
missing path/URL/version/hash expectation, purpose, expected maximum size,
license and dependency edge for each proposed input. Pin one official origin
and exact distribution revision. Have an independent reviewer decide whether
that finite manifest actually closes the questions above. An unknown path,
source correspondence or size is a design refusal, not permission to search.

**B. New acquisition decision.** Only after A is frozen and reviewed, propose
one new, separate source-research scope with an explicit maximum request count,
per-response and aggregate byte reservations, wall-clock deadline, retained
file cap, endpoint and TLS policy, one-attempt failure accounting and exact
stop/reconciliation rules. Do not borrow the spent 16 requests. Preserve
failed responses/partial evidence, never automatically retry or widen pins.
The concrete numbers and literal URLs must be reviewed against A before any
network action; this document grants **zero** requests and no quota.

**C. Offline source and format gate.** Verify each held source byte hash and
signed-source relation, inspect the exact dispatch/build paths and independently
review the resulting closed manifest. Use only hand-built synthetic archives for
negative ownership/format controls. The pinned stdlib USTAR path is the selected
restricted secondary inventory implementation; validate its exact source and
license before real use. Do not add a general ar/tar/compression parser or invoke
acquired archives in this phase.

**D. Separate real-package native decision.** After the synthetic fifth proof
and its independent audit, review a new fixed real-package scope: exact archive
identities, Reader/image binary provenance, isolation, per-archive budgets,
format matrix, input FD ownership, output/inventory/receipt semantics, stop
conditions and non-retry ledger. Require an explicit operator decision and
exact-source CI before any real archive is fed to native code. A refusal is
retained and returns to design. This decision is not supplied by #234.

**E. Decoder and Core gates.** Independently finish Pillow provenance/image
copy, actual seccomp and aggregate cgroup qualification, PNG decode/thumbnail
semantics with owned cleanup, and Core Media Worker registration, Task/Agent
permission and use-point revocation. The current pure syscall policy and
synthetic Reader do not grant image or runtime authority.

## Stop and acceptance rules

A source mismatch, absent signed correspondence, unlisted helper, unsupported
archive form, uncontrolled subprocess/decoder, uncertain close/reap, changed
retained bytes, exceeded budget, failed exact-head CI or missing independent
review stops only its own proposed phase. No fallback endpoint, package version,
parser mode, mutable host path, attempt reset or altered release scope follows.
Each subsequent phase requires an immutable SHA, explicit artifacts and a
separate evidence review. R4 stays HOLD until the actual package Reader,
decoder and Core authority gates have their own accepted receipts and the
final release audit is complete.
