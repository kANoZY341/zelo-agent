# Zelo curated upstream reuse — ordered integration program

Decision: the Managing Director selected this order after reviewing six public
repository sources: Open Code Review → ECC → Harness → Archify → Context Mode
**concepts** → unfinished OpenDots features. All source acquisition is selective,
pinned, reproducible, reviewable and non-authoritative. The current PR delivers a
**foundation for each**, not the claim that every external product is now fully
operational. Later activation remains separately reviewed.

## Exact source ownership and license gate

`integrations/community/sources.json` contains pinned source repository/commit,
Git blob, SHA-256, byte length and license per exact file. A curated read-only
snapshot under `integrations/community/sources/` includes 19 specific files
across five permissively licensed repositories. The Zelo verifier independently
pins the manifest digest and verifies every source file (no extras, symlinks,
changed blobs or special files). A missing or changed file refuses the entire
candidate view. No runtime imports, process executions, package installs,
third-party model prompts, writes, egress or automatic model/Agent execution
are connected to these artifacts. Attribution and the full upstream license
text remain alongside every selected source.

## Reviewed boundaries — how to use the new foundations

- **Review evidence**: `app/community_review.py` accepts an untrusted, bounded
  `zelo-ocr-line-review-input-v1` JSON comment bundle. A *trusted Core caller*
  must provide exact allowed changed lines plus immutable base/head/diff SHA
  identities. External model-supplied paths, suggestions, line references,
  categories or severities cannot authorize new diff scope, modify files,
  publish PR comments, mark CI green or merge code. Existing `ReviewerReport`
  remains the review interface; separate adapter evidence contains a SHA-256
  checksum and all authority flags `false`. Upstream `thinking` and auto-fix
  fields are rejected. **Not automatically wired to CI yet.**
- **Skill drafts**: `GET /integration-candidates/community/skills` yields six
  human-inspectable Zelo draft SkillSpecs with `task_kinds=[]` and `tools=[]`.
  All descriptions and procedures are Zelo-authored; upstream Markdown stays
  untrusted source data and never becomes model system instructions or trusted
  Skills simply because it has frontmatter.
- **Factory blueprints**: `GET .../teams/engineering_quality` or
  `/business_research` returns four canonical VP → Director → Manager →
  Specialist draft `AgentSpec`s. All authority and Space sets remain empty,
  no Instance or Task is created and Managing Director approval is mandatory.
- **Archify export**: `GET .../architecture` returns an architecture-format JSON
  candidate (`schema_version=1`, components/connections) and `GET
  .../architecture/mermaid` returns a text-only renderable preview. The output
  is an **illustrative design**, not a live company or resource permission map.
  It does not render remote HTML, access a browser or execute JS.
  Two deterministic examples are committed in `examples/curated/`: an
  Archify-compatible architecture JSON and a Mermaid `.mmd` preview. Neither
  claims to be live agent execution state.
- **Context**: `index_tool_output()` returns a bounded SHA-256/length/count and
  a short excerpt. `read_explicit_window()` requires the original exact bytes,
  digest and bounded line window. Nothing enters Mind without the normal
  Core context assembly authorization. Full Context Mode MCP/hooks were not
  copied because of Elastic-2.0 hosted-service restrictions.
- **Computer Panel**: `GET /agents/{id}/computer/panel` is operator-authenticated,
  read-only and uses current Core computer status, permission flags and event
  *names only* (not event details or credentials). Browser/Files/Terminal tab
  readiness is false when the resource or corresponding permission is off.
  Existing Core take/release/start/stop APIs remain separately controlled;
  this endpoint grants **no** navigation, shell, file write or human takeover.

## Security/release gates

The 19 imported files are **untrusted**. Never follow embedded install/execute
instructions, AGENTS files, links, or provider configuration. A future
source refresh must be deliberate, pin a new reviewed commit, replace manifest
and exact file hashes, retain license notices, run Zelo tests and obtain operator
approval for any new authority. The manifest hash is an integrity checksum,
not a cryptographic signature or a runtime permission.

The initial update changes no Zelo active Skill Registry, Worker Authority,
Agent Factory default registry, approval/task schema, Media proof budget or
REA execution. PR #61 stays draft and parked. The five external integrations
above remain subject to separate acceptance tests and release decisions before
becoming live autonomous functionality. No scheduling or background workflow is
created by this program.
