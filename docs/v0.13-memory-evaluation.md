# v0.13 — Memory evaluation and contamination boundaries

## Purpose

This third v0.13 slice establishes deterministic evidence that Zelo's memory
retrieval is useful without silently crossing scope, freshness or authority
boundaries.

The evaluation path is deliberately separate from model judgment. It exercises
the existing `MemoryService.retrieve()` contract directly and records exact
memory IDs, so failures are inspectable and reproducible.

## Evaluation harness

`app/memory_evaluation.py` defines:

- `MemoryEvaluationCase`: query, explicit scopes, expected IDs, forbidden IDs
  and result limit;
- `MemoryEvaluationResult`: the bound query/scopes/limit plus actual IDs,
  expected/forbidden sets, missing expected IDs, forbidden IDs present,
  unexpected IDs, precision, recall, candidate count and retrieval version;
- `MemoryEvaluationReport`: suite totals plus contamination/unexpected-hit
  counts.

A case passes only when:

1. every expected memory is returned;
2. no forbidden memory is returned; and
3. no unexpected memory is returned.

This is intentionally stricter than a single aggregate score. A perfect average
must not hide one cross-scope or stale-memory contamination event.

`memory_evaluation_evidence()` emits a JSON-safe
`zelo-memory-evaluation-v1` envelope. Evidence is bound to the query, scopes,
limit, expected IDs and forbidden IDs for every case. Forbidden contamination and
other unexpected hits are counted separately. The helper does not persist the
report; later evidence storage can consume the versioned envelope without
changing retrieval authority.

## Baseline quality cases

The baseline suite includes:

| Case | Expected boundary |
| --- | --- |
| Current personal preference | corrected/current memory is recalled; replaced and expired versions are absent |
| Unrelated personal query | no false-positive memory is returned |
| Arabic personal recall | Unicode/Arabic memory is retrievable with the same deterministic path |
| Project Alpha retrieval | only the explicitly requested project scope is searched |
| Research agent retrieval | only the explicitly requested agent namespace is searched |

The suite records the exact IDs behind every pass/fail result.

## Contamination boundaries

Separate context-level evaluations verify:

- automatic Talk-to-Zelo memory injection is personal-scope only;
- matching project/agent memories cannot leak into an unbound conversation;
- memory text that contains imperative instructions remains
  `instruction_trust: none`;
- conflicting remembered project/runtime claims do not replace canonical
  repository/Core state;
- Mind's routing prompt explicitly prefers canonical project/runtime facts when
  they conflict with remembered context;
- unrelated memory does not create a context envelope at all;
- memory remains excluded from authority-bearing Core task construction by the
  existing second-stage prompt boundary.

## What this slice does not do

This slice does not:

- call a model to grade memory quality;
- create an online evaluation service or new API;
- automatically persist evaluation output as memory;
- add embeddings/vector search;
- infer project/agent scope from text;
- add model-decided retention;
- create agents or workers;
- change approval, scheduling, merge or release authority.
