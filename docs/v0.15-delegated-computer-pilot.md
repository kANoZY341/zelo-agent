# v0.15 delegated Computer pilot startup

Status: merged in #219 at `875b766`; exact-head CI 39186742127 passed,
distinct main CI 39188013218 passed, while native host acceptance remains
open. The merged child-owned file-use slice (#217) remains bounded; this startup option is not a release
gate PASS. v0.15 remains HOLD.

The normal Core registry has no delegating Computer profile by default. The
existing computer_observer pilot explicitly forbids delegation and permits
one instance. The opt-in adds a separate exact catalog containing that
unchanged child Specialist and one computer_delegate Specialist parent. The
parent can delegate at most one bounded computer_run under the existing
Campaign budget and delegation contracts. It has no generic Manager or
organization-hiring authority. The existing Computer Worker remains conditional
on a configured backend.

The delegated_computer_approved_registry_sha256 setting defaults to null.
An operator can preview the fixed catalog digest without loading settings or
opening a database:

    .venv/bin/python -c 'from app.computer_observer import delegated_computer_registry; print(delegated_computer_registry().version)'

After reviewing the catalog, set
ZELO_DELEGATED_COMPUTER_APPROVED_REGISTRY_SHA256 to that exact digest in a
private operator environment, alongside the separately configured Computer
backend. Do not enable the existing Computer Observer registry pin at the
same time.

Startup accepts only the exact current registry digest, and refuses missing
backend, conflicting Computer catalog pins, stale catalog identity, incompatible
live instances, or disabling the selected catalog while any live Agent
remains bound to either Computer catalog digest. A registry pin creates no
AgentInstance, computer permission, Space resource, intent, activation, Task
or delegation. Each is separately authorized through the ordinary Core path. A parent activation never substitutes for the
child's own confirmation.

The normal-lifespan test uses the selected registry, authenticated owner
provisioning and confirmation, a persisted Campaign and budget reservation,
a parent-child delegation, a claimed Computer Task and actual file content
from the private Space directory. It checks the persisted result, absence of
backend file reads, and refusal after delegation revocation. The Computer
control backend is simulated in this test; a native host proof remains a
separate gate. Other Space operations, the Manager hierarchy, Skill
publication, Media and release approval remain open.
