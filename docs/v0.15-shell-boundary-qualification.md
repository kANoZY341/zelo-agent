## First proof contract

Use the installed mature Dash, Bubblewrap and util-linux prlimit commands behind
Zelo-owned fixed arguments. Inspect complete runtime dependencies and canonical
file identities before deciding the precise mount inventory. Preserve all source
and license notices if anything is copied or distributed; this first proof uses
installed trusted files only and vendors no binary. Installed-package observations
are not independently verified source provenance.

The first guest contains only the fixed shell, fixed resource-limit tool and their
required runtime libraries. It has no host workspace, engine, credential file,
operator HOME, shared writable directory or network. All guest filesystems are
read-only, including temporary directories. Only bounded stdin/stdout/stderr are
input/output. Run as the non-root caller with capabilities dropped and nested
user namespaces disabled. Refuse root or unavailable isolation prerequisites;
never fall back to a host shell.

Hard resource limits must include memory, CPU, open files, zero process creation,
zero file output and zero core dumps. The first shell surface supports built-ins
and exec within this closed guest; it deliberately does not promise pipelines or
external tools. Actual proof must establish effective guest UID, capability and
limit state before treating fork rejection as a boundary. A broader process or
filesystem surface requires separate qualification, not relaxed first-proof flags.

Use only fixed harmless diagnostic scripts to prove useful built-in text compute,
absence of a diagnostic host canary and ambient credentials, read-only filesystem,
rejection of a single bounded fork attempt and hard-limit escalation, exec limits,
stdout/stderr bounds, deadline/cancellation and cleanup. No fork bomb, internet,
user file, live Core instance or persistent service. Explicit opt-in precedes any
native probe. Default offline tests cover policy construction, source identity,
opt-in and harness failure reporting without launching guest processes.

No Core schema, capability, authority, task, API, retry, Agent/Mind route or default
activation is part of this proof. A later binding needs a separate immutable
execution identity and reviewed admission/ownership design. Reuse generic helpers
only where their policy and cleanup guarantees match; never relabel Python or
Browser authority. Require independent Astra Medium static review, focused tests,
actual host evidence and exact-commit full CI before merging proof/runtime code.


## Implemented optional proof

```bash
.venv/bin/python -m scripts.qualify_shell_compute --allow-native-shell-probes
```

No flag means no guest startup. This command uses fixed local package artifacts;
a missing or changed artifact fails qualification and never falls back to a host
shell. It accepts no script, command, file, environment or policy override. The
six expected artifacts are the Bubblewrap launcher, Dash, prlimit, glibc loader,
libc and libsmartcols; the latter is a prlimit dependency. Their observed SHA-256
identities are explicit in `qualification/shell_compute.py`.

The boundary reuses `pin_artifact` to verify and seal executable/library bytes in
owned memory descriptors. Bubblewrap is executed from its sealed descriptor;
its guest files are mounted from sealed bytes with mode 0500. This closes the
verification-to-path-mount replacement window without copying a binary into the
repository or distributing a prepared image. Trusted host engine dependencies,
root-owned source artifacts, filesystem ancestors and the same-UID operator
remain assumptions; observed hashes are not independent provenance. Local setup
is synchronous and charged to the absolute deadline, and no guest starts if that
budget is consumed. Sealed descriptors remain owned until the process helper
returns from cleanup; they are closed on every exit.

Fourteen fixed cases verify effective UID/GID, capabilities, no-new-privileges,
actual hard limits and isolated network interface state; built-in compute;
absence of ambient credentials and a harmless host canary; read-only guest;
a single bounded fork rejection; failed hard-limit escalation; absence of the
host shell; inherited state after exec; stdout/stderr limits; deadline; native
launcher cancellation; and a fresh subsequent probe. Cancellation waits for
actual subprocess spawn acknowledgement rather than guessing from elapsed time.
An observation wrapper records only real launchers and requires them reaped; it
introduces no await between resource creation and returning it to its real owner.
The output/deadline cases cannot pass without an actual native launch and reap.

The exclusive private report under `runtime/shell-qualification/` records the
Git commit, clean/dirty state, proof-plan fingerprint, effective guest state,
case outcomes and native launcher reaping. The fingerprint describes this proof;
it is not a Core execution specification or permission grant. No task, registry,
API, runtime configuration, admission reset or production activation is added.
A later Shell binding requires separate policy identity, ownership/admission and
Agent/approval integration gates. Pipelines, workspace access, write access and
extra tools remain outside the first built-in compute surface.
